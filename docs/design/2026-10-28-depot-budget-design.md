# G1-K7 — бюджетный склад магазинов как настройка аллокатора (дизайн, ред. 1)

Статус: ред. 1 после ревью @oh и ревьюера rush (оба FIX-REQUIRED на ред. 0;
ответы — `docs/design/k7-review/`). Основание: P0 (`docs/perf/G1_IDEAS.md`
§9 в PR #124 — потолок «перенос = 0» на bulk16k, отношение времени 0.5705
за вычетом null), консультация C5 (§10), решения владельца:

- бюджет удержания — настройка, которую пользователь задаёт при создании
  аллокатора; по умолчанию 1 МиБ сверх пола K5;
- README подробно описывает каждую настройку — на что влияет, замеры;
- **приём:** любой измеренный выигрыш против mimalloc на главном судье и ни
  одного проигрыша на замерах других типов (другие ядра, RSS и удержание
  памяти, Ir/iai, задержка), без потерь в безопасности.

## 1. Что меняется

Склад K5 (`src/registry/heap_core/state/depot.rs`) остаётся полом: те же
`DEPOT_K` для классов 0..17 (16..1024 Б), те же массивы в слоте реестра,
241 408 Б блоков на поток.

Сверх пола — **переполнение**: полный магазин класса склада, не
поместившийся в пол, паркуется в ленивое хранилище, пока сумма байтов
блоков в переполнении не больше бюджета E. Иначе (бюджет исчерпан,
хранилище недоступно, коммит не удался) — прежний путь: flush половины
магазина в список сегмента. При отказе парковки указатели, счётчики и
текущий магазин не меняются.

Парковка и перезагрузка — копирование 16 указателей, как у пола и P0;
блоки остаются MAG, кредиты сегмента не снимаются.

Инвариант склада: `PerClass::parked = floor_count + overflow_count`;
`floor_count = min(parked, DEPOT_K[c])`; переполнение заполняется только
при полном поле; перезагрузка берёт сначала из переполнения, потом из пола
(LIFO по всему складу). Дублей указателей нет. Формулировка И3 байта
состояния (`state_byte.rs`) расширяется: MAG = «в активном магазине, в
поле склада или в переполнении».

Вход: гейт в `free_magazine_full` (`dealloc_own_base.rs`, сейчас
`parked < DEPOT_CAP[c]`) пропускает все классы склада, если пол не полон
**или** в переполнении есть место по бюджету; проверка бюджета — внутри
холодного пути.

## 2. Настройка

`LargeCacheConfig::depot_budget_bytes(bytes)` (тот же конфиг, что
`SeferAlloc::with_config`; рядом с `pool(...)`):

- не задано → 1 МиБ;
- `0` → переполнения нет, поведение K5;
- `n` → округление вниз до 256 Б (байты наименьшего магазина: 16 × 16 Б),
  верхний предел `E_MAX = (u16::MAX − DEPOT_K_MAX) × 256` = 16 774 912 Б
  (`parked: u16` вмещает пол и переполнение класса 16 Б; закреплено
  `const assert`).

Разрешённое значение хранится в `HeapCore` (под `fastbin`); `HeapCore::new`
ставит значение по умолчанию; сравнение добавляется в
`HeapCore::live_config_matches` (под `all(alloc-decommit, alloc-global,
fastbin)`), не в `AllocCore`. Поле входит в деструктуризацию R6-T52
(`heap_slot.rs`). Правило слота реестра — **первый claim побеждает**:
повторный claim слота с другим E оставляет прежнее значение и увеличивает
`config_conflicts_total`; README говорит это прямо.

Чтение назад для R26-4: разрешённое и **эффективное** значение (у
резервной и standalone-кучи склада нет — `depot = None`, эффективно 0);
аксессор уровня `SeferAlloc`, проходящий через `#[global_allocator]`,
запись в `scripts/verify-dbg-hook-safety.mjs`.

README: E — на кучу (поток), не на процесс; без `fastbin` настройка
игнорируется; без `alloc-decommit` переполнения нет (хранилищу нужен decommit для trim) — действует только пол K5, настройка игнорируется (ред. 2, по ревью кода rush);
`Profile` её не задаёт; полное удержание на поток = 241 408 Б пола + E +
метаданные переполнения + сегменты, которые держат запаркованные блоки
(E ограничивает байты блоков, не физическое удержание сегментов);
справедливости между классами нет (кто первым занял E, тот держит до
затухания).

## 3. Хранилище переполнения

**Управление — в `Depot` слота**, все поля валидны при нулях (слот обнуляет
ОС): база резервирования (`*mut u8`, null = нет), размер резервирования,
на класс — голова кольца, число записей и отметка коммита, `overflow_bytes`,
флаг отказа, поля затухания. Никаких RAII-токенов в слоте.

**Резервирование содержит только записи**: на класс непрерывный регион из
`cap_c = ⌊E / (16 · bs_c)⌋` записей `[*mut u8; 16]`; регионы выровнены по
рантаймовому `page_size()`. Связей, голов списков и общего пула нет: запись
класса — кольцо (голова + число), новая пишется в конец, перезагрузка берёт
из конца (LIFO), затухание сбрасывает из головы (самые старые). VA ≈ 1.47·E
(≈ 1.5 МиБ резерва на 1 МиБ, только адресное пространство).

**ОС**: резерв через `aligned_vmem::reserve_aligned_lazy` при первой
парковке в переполнение (без `GlobalAlloc`, без рекурсии), `initial_commit`
= одна страница; коммит по отметке класса (`commit_range`), порядок
«коммит → сдвиг отметки → запись»; отказ коммита — состояние не меняется,
обычный flush; отказ резерва — флаг, новые попытки до trim не делаются,
уже закоммиченные записи остаются рабочими. Вызовы ОС — через существующий
шов `platform/sidecar.rs` (новый ленивый вид с учётом в `sidecar_stats`)
или обёртки в `os.rs` с гейтом `all(alloc-global, fastbin)`; разыменование
записей — tier-2 `#[allow(unsafe_code)]` с `// SAFETY:` в
`depot_overflow.rs` (единственный новый файл в `state/`, где сейчас 6
записей). README «Where unsafe lives» и заголовок `src/lib.rs` обновляются,
если шов станет tier-1.

**trim / выход потока / recycle**: `flush_all_tcache` опустошает
переполнение и пол (затухание в teardown отключено), затем закоммиченные
страницы регионов возвращаются ОС (eager на Linux и Windows, `decommit_lazy` на Darwin и BSD — там eager
только советует, CORRECTNESS_OPEN_ITEMS 48; сегменты так не делают), отметки коммита и кольца сбрасываются
в 0; резервирование остаётся за слотом. Содержимое после decommit не
используется (обнуление ОС не предполагается).

**Живучесть remote-обязательств**: перезагрузка со склада возвращается
раньше `drain_large_sidecar_ingress_hot_bounded()` и обнаружения
small-sidecar в refill (`alloc/hot.rs`). С переполнением подряд бывает до
~1000 перезагрузок, поэтому раз в 8 перезагрузок со склада выполняется
ограниченная проверка ingress; счётчик пропусков — в оракул.

## 4. Затухание

- Эпоха — холодные события кучи (парковка в склад, перезагрузка со склада,
  пополнение магазина из сегмента); часы не читаются. Длина эпохи =
  max(256, 2 × занятых записей переполнения), чтобы полный цикл
  заполнения и опустошения помещался в эпоху.
- Класс, у которого за эпоху была хотя бы одна парковка в переполнение,
  освобождён от затухания в этой эпохе (фаза заполнения).
- Остальным классам: нижняя отметка числа записей за эпоху h; в конце эпохи
  сбрасывается ⌈h/2⌉ самых старых записей (из головы кольца) через
  `flush_class_internal` (L-4 защита сохраняется), не больше 4 магазинов
  на одно событие, остаток — долгом на следующие события. Следующая эпоха
  начинается с фактической оставшейся занятости.
- Затухание запускается только на холодных путях после записи MAG для
  текущего блока и никогда не трогает живой магазин — пишутся только тела
  давно запаркованных блоков (R1-01 сохраняется).
- В teardown затухание отключено.
- Поток без холодных событий (одни попадания в магазин) держит
  переполнение до trim или выхода — как страницы mimalloc без `mi_collect`;
  README говорит это.

## 5. Ghost и Kani

- P12: `depot_overflow.rs` в `prod`; И1 — «склад, включая переполнение,
  пуст после teardown; decommit хранилища только после опустошения».
- Новое правило «decommit-after-drain» в `flush_all_tcache` (мутант:
  decommit до цикла); «reset-before-reuse»; «no-decay-in-teardown».
- `depot/owner-only-access`: пути парковки, перезагрузки, затухания и
  decommit переполнения в `allowed`; bind-once для базы резервирования.
- Новые `bench-internals` счётчики (`Relaxed`) — области в каталоге
  (`ghost_inventory --check`).
- Kani: LIFO через границу пол/переполнение (K+1 парковок, перезагрузка
  сначала из переполнения), граница `u16`, сохранение `overflow_bytes`
  после парковки/перезагрузки/затухания, уникальность записей кольца,
  E = 0 ≡ K5.

## 6. Тесты (в `tests/`)

- E = 0 → поведение K5, счётчики переполнения 0;
- E: парковка до E, следующий магазин — flush; перезагрузка отдаёт только
  освобождённые тестом блоки без дублей, LIFO через границу пол/переполнение;
- E_MAX на классе 16 Б (граница `u16`);
- затухание: класс без парковок сбрасывает ⌈h/2⌉ за эпоху из головы; класс
  с парковками в эпохе не затухает; работа на событие ≤ 4 магазинов;
- double free запаркованного в переполнении блока отвергается;
- trim / выход потока опустошает переполнение, отметки сброшены, повторное
  использование слота и повторный всплеск после trim работают;
- отказ резерва и отказ коммита (fault injection) → обычный flush, без
  потери блоков;
- конфиг: разрешённое и эффективное значение читаются назад; повторный
  claim с другим E увеличивает `config_conflicts_total`.

## 7. Замеры (предрегистрация отдельным файлом до прогонов)

Точка входа — реальный `#[global_allocator]` (у standalone `HeapCore`
склада нет). Неизменяемая идентичность исходников до прогона, сырые данные
по сэмплам, таблицы — скриптом.

**Приём (владелец):** измеренный выигрыш против mimalloc на главном судье
J1′ v2 хотя бы на одном ядре (CI отношения t_mi/t_sefer K7 лучше K5) и ни
одного проигрыша на замерах других типов:

1. главный судья против mimalloc (20 × 2000): ни одно допущенное ядро не
   хуже K5 вне его A/A-полосы;
2. абляция против K5 с null-копией, все ядра + новые `bulk64k` (когорта
   4 МиБ > E) и `bulk16k_256` (разведочное, потолок не мерился); инженерная
   цель — bulk16k ≥ 75 % эффекта P0, но решение принимается по п. 1, 3, 4;
3. RSS-судья — подпроцесс на плечо (K5 / K7 при E ∈ {0, 512 КиБ, 1 МиБ,
   2 МиБ} / mimalloc), те же режимы, что у скорости (bulk16k, bulk64k,
   bulk16k_256), плюс: ниже/на/выше E, смешанные классы, повторный всплеск
   после затухания и после trim, простой с одними попаданиями и с
   холодными событиями, разреженный free (каждый k-й блок — удержание
   сегментов), remote free, T = 1/4/16/64; снимки при живых потоках: пик,
   после всплеска, после затухания, после trim, после выхода и повторного
   claim; Windows PrivateUsage/WorkingSet, Linux RSS; метаданные
   переполнения отдельно. Проигрыш = хуже K5 вне шума в любом снимке,
   кроме удержания внутри объявленного бюджета (E + метаданные), которое
   публикуется числом;
4. iai/Ir: смена значения по умолчанию — `perf(runtime)`, обновить
   `bench:table` и `iai`; A/B E = 0 против K5 по Ir отделяет стоимость кода
   от механизма; первый коммит хранилища на свежем процессе — отдельной
   строкой;
5. для каждого плеча (R26-4, R30-8, автоматически, с отказом прогона):
   запрошенный, разрешённый и эффективный E, дельта
   `config_conflicts_total` = 0, граница процесса; оракул счётчиков:
   парковки в переполнение > 0, перезагрузки ≈ парковкам, доля промахов
   bulk16k из склада ≥ 95 %, E = 0 → всё 0, отказы по бюджету > 0 на
   bulk64k, сбросы затухания = 0 на bulk и > 0 в сценарии затухания,
   отказы резерва/коммита, байты закоммиченных метаданных, пропуски
   ingress-проверки.

Опубликовать: E = 1 МиБ покрывает bulk16k с запасом ≈ 9 КиБ (нужно
≈ 1 039 360 Б) — это подгонка под судью; свип E показывает, что
происходит за порогом.

## 8. Что не входит

- Ось `Profile` для бюджета (после замеров).
- Вариант с указателями в телах блоков (A′) и FREE-множество (B) — ниже A

## Ред. 3 (2026-10-29, после двух абляций — замеры в `g1-k7-meas`)

- Пол первым: парковка заполняет пол, перезагрузка опустошает пол раньше
  переполнения (`PerClass::floor`, биты 0..3 — счётчик, бит 7 — «парковал
  в пол в эпохе»); `parked = пол + длина кольца`; глобальный LIFO заменён
  порядком «пол LIFO, затем кольцо от новых к старым».
- Затухание считает только события переполнения и пополнения из сегментов;
  парковки в пол — активность класса для освобождения от долга, но не
  события эпохи. Трафик только по полу эпохи не двигает.
- `PerClass::limit` — встроенная проверка на free; отказ переполнения
  (бюджет, кольцо, ОС) защёлкивает предел до уменьшения переполнения или
  trim.
- Тик O(1): длины колец и маска долга в `DepotOverflow`, работа эпохи и
  долга — в холодной `HeapCore::depot_decay`.


## Ред. 4 (2026-10-29, после главного судьи и Callgrind — консультация @oh и rush)

Замер ред. 3 на неизменном 11-ядерном судье: bulk16k ×1,60 против K5, но
bulk64 на 2 % медленнее (CI не пересекаются); Callgrind: +656 тыс. Ir на
bulk64 (+1,16 %), около 26 Ir на событие магазина — учёт пола, которого у K5
нет. Ред. 4 убирает его с пути пола:

- `PerClass::parked` снова считает только пол (u8, смещение 1, как в K5);
  `Depot::depot_park/depot_reload` и холодные `HeapCore::depot_park` /
  `depot_reload` на полу — код K5 дословно. Кольцо считает свои записи само
  (`DepotOverflow::len`), `dbg_depot_len` = пол + кольцо.
- `PerClass::ovf` (смещение 2, рядом с `parked`) — подсказка «кольцо
  непусто» для проверки на пополнении: `parked` и `ovf` читаются одной
  16-битной загрузкой. Её пишут только холодные пути переполнения
  (парковка, перезагрузка, затухание), а перезагрузка верит длине кольца, не
  подсказке; слив при завершении тоже идёт по длине.
- Переполнение — холодные хвостовые вызовы `park_overflow` /
  `reload_overflow` / `reload_overflow_tick`. Тик события переполнения —
  внутри них: при парковке после того, как кольцо приняло запись и магазин
  обнулён (`count = 0`), то есть затухание видит только более старые записи
  (долг ≤ длины до парковки), а освобождаемый блок ещё LIVE и держит свой
  сегмент. Это отступление от §4 «после записи MAG для текущего блока»:
  обоснование — то же свойство (затухание не трогает ни текущий магазин,
  ни текущий блок), без зависимости от порядка в вызывающем.
- Перезагрузка для пополнения — `depot_reload_tick` (тикает только на
  ветке кольца), для слива — `depot_reload` (не тикает); правила
  `depot/ticking-reload-on-refill-only` и
  `depot/overflow-tick-reload-from-refill-reload` закрепляют разделение.
- Пометка активности пола — отдельный байт `PerClass::floor_mark` (запись
  константы на ветке парковки в пол, 1 Ir); затухание собирает и сбрасывает
  её в конце эпохи. Удалять её — отдельная абляция (обоснование rush:
  эпохи двигают и пополнения из сегментов).
- Защёлка ставится и при заполнении кольца (без счётчика отказа), чтобы
  free больше не звал холодный путь до уменьшения кольца.
- Тик пополнения из сегмента стоит перед вызовом проверки входящих
  удалённых освобождений, пока живы только `self` и `c`: иначе встроенный
  тик добавлял два сохраняемых регистра в пролог `refill_magazine_slow` и
  платился на каждой перезагрузке пола.
- `Depot` — `#[repr(C)]`, `mags` первым (смещение 0, как в K5).

Callgrind ред. 4 (зонд `b4_pmu_probe`, K5 `2bc830cc` против рабочего
дерева): bulk64 по функциям sefer +19,8 тыс. Ir из 56,46 млн (+0,035 %;
`depot_reload_tick` = K5 `depot_reload`, free −2 Ir, `depot_park` +2 Ir,
`refill_magazine_slow` +1 Ir на вызов); pair16/pair64/churn16 ≤ +0,03 %.

## Ред. 5 (2026-10-29, после замеров ред. 4 — консультация @oh, @ox и rush; Addendum 6 утверждён владельцем)

Ред. 4 не прошла правило 2 предрегистрации по букве: pair16/pair64 +0,9 % в
абляции (тот же знак у всех вариантов v2–v4 при ≤ +0,03 % Ir) и larson в
первой паре главного судьи. @oh нашёл в коде ред. 4 одну реальную лишнюю
работу: каждое пополнение из сегмента вызывал `depot_tick`, то есть читал
`HeapCore::depot` и `Depot.ovf.bytes` (≈ 18 КиБ от начала `Depot`) — две
линии, которых пополнение K5 не трогало; Ir этого не видит. Ред. 5 убирает
только её:

- `PerClass::ovf` — два флага: `OVF_HINT` (бит 0, прежняя подсказка «кольцо
  непусто») и `OVF_TICK` (бит 1, «пополнение этого класса из сегмента
  считает событие затухания»). Байт рядом с `parked`, который пополнение
  уже прочитало, поэтому проверка флага не трогает новую линию. Проверка
  перезагрузки маскирует `OVF_TICK` (по-прежнему одна 16-битная загрузка).
- `DepotOverflow::armed: u64` — зеркало флагов (бит `c`), в ведущей линии
  управления рядом с `bytes`. Инварианты: `OVF_TICK(c)` ⇔ бит `c` в
  `armed`; `bytes > 0` ⇒ взведены все малые классы.
- Взведение: успешная парковка в переполнение (единственное место, где
  растёт `bytes`) ставит `OVF_TICK` всем ещё не взведённым классам,
  `armed = ALL_SMALL`.
- Снятие лениво: пополнение класса с `OVF_TICK` зовёт холодный
  `depot_segment_tick`; если `bytes == 0`, класс снимает свой флаг и бит, иначе
  считает событие как в ред. 4. Жадное снятие стоило бы O(число классов) на
  каждом переходе 0 ↔ > 0 (тот же провал, что скан всех классов в v1).
- Полный сброс (`armed = 0`, все флаги 0) — в сливе при завершении после
  освобождения страниц и в `bind_depot`; там `bytes == 0`.
- Поэтому ред. 5 считает ровно те же события, что ред. 4: при `bytes > 0`
  каждое пополнение из сегмента тикает, а при `bytes == 0` тик ред. 4 ничего
  не менял. Расписание затухания то же; устаревший флаг стоит одного
  лишнего холодного вызова, пропустить тик нельзя. Бюджет от тиков не
  зависит (проверяется при парковке).
- Счётчики `arms` / `disarms` в `OverflowStats` (индексы 9 и 10 в
  `dbg_depot_overflow`) — доказательство активации для правила 5;
  `dbg_depot_ticking` отдаёт флаги и зеркало для тестов.
- Новое правило ghost-lint `depot/segment-tick-on-refill-only`; правило
  `depot/no-decay-in-teardown` теперь разрешает `depot_tick` из
  `depot_segment_tick` вместо самих пополнений. Kani И-O1 проверяет оба
  инварианта на последовательностях park / reload / pop_oldest / disarm.

Не входит (решение консультации): C.2 — перезагрузка из переполнения
пропускает обнаружение удалённых малых освобождений, которое идёт на
пополнении из сегмента; открытый пункт 128 в `docs/perf/OPEN_ITEMS.md`,
наблюдается нагрузкой W4 в RSS-прогоне Addendum 6.
