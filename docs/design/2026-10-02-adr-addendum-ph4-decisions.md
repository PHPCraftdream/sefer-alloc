# Дополнение к ADR: решения по фазам Ph4a/Ph4b/Ph4c (консультация владельца, 2026-10-02)

Статус: РЕКОМЕНДАЦИИ консультанта `@ox`, которому владелец делегировал решения по ADR. Основной ADR: `docs/design/2026-10-01-adr-physical-boundary-and-progress.md` (его текст не менялся, гейты C1–C7/P1–P4, пределы и стоп-линии остаются в силе). Вход: дизайн-записка `docs/design/2026-10-02-ph4-domain-lease-design.md` (§6 «Чего не знаем + вопросы владельцу»). Связанные документы: план `docs/design/2026-10-01-113842-src-foundational-refactoring-plan-xs-sol.md` (шаг 4), дизайн геометрии Ph3c `docs/design/2026-10-02-ph3c-offbody-geometry-design.md`.

**Порядок:** код Ph4a начинается только после принятия Ph3c (план: `3c → 4a`). Ph3c пока существует как дизайн + микро-прототип (`ph3c-proto`).

## 1. Где записка Ph4 расходится с кодом (исправить в дизайне до Ph4a)

- **§3.2 «`LOCAL` хранит `Option<HeapLease>`» — нельзя.** TORN-защита (`src/global/tls_heap.rs:54-59`) опирается на то, что `LOCAL` — константный `Cell` без `Drop`; порядок «LOCAL, потом GUARD» нужен из-за повторного входа в аллокатор на std ≤ 1.92 (`tls_heap.rs:440-451`); горячий путь — одна загрузка и сравнение (`:261`), предел ADR ≤ 1.02. Lease принадлежит `GUARD` (`Cell<Option<HeapLease>>`), `LOCAL` остаётся `Cell<*mut HeapCore>` без Drop.
- **§3.6/§4.6 «slot-lease и fallback-lock взаимно исключающие» — неверно уже сейчас.** `dealloc_routing(&mut self)` вызывает `publish_foreign`, а тот — `fallback::try_with_heap` под живым lease (`src/registry/heap_core_xthread/routing.rs:10-20`, `:35-44`). Верный инвариант: под любым slot/maintenance lease к fallback — только через неблокирующий `try_with_heap`; блокирующий `with_heap` — только без lease.
- **§4.2 «один bounded step».** Ограничен только ingress (`BACKGROUND_INGRESS_BUDGET` = 64, `ownership.rs:14`). `trim_cold_retention` не ограничен по числу вызовов ОС: `evict_all` (`alloc_core_large_cache_eviction.rs:70-72`), `drain_small_pool` (`alloc_core_small_pool_impl.rs:636-650`).
- **§4.5 B2 «тест нужен» — уже есть:** `tests/r8_autonomous_maintenance.rs:137-167` (`startup_failure_and_race`).
- **A3 «no-op или abort»:** для типизированного lease — abort (как `MaintenanceLease::drop`, `claim.rs:419-430`); тихий no-op остаётся только у старого `recycle` (`claim.rs:375-381`, на нём держится `tests/registry_basic.rs:298`).
- **Счёт тестов:** `HeapRegistry::claim()` — 69 файлов, `recycle(` — 70, `claim_with_config` — 20; `HeapRegistry` упоминают 114 файлов в tests/benches/examples.
- **`generation`:** в production нигде не читается (`heap_slot.rs:12-15`, `:163-169`) — в lease только числовой наблюдатель, без проверок на горячем пути.

## 2. Решения по 10 вопросам

1. **Send для `HeapLease` — вариант A в минимальной форме; вариант B (`unsafe impl Send`) отклонён.** `HeapLease` — `pub(crate)`, `!Send + !Sync`, не `Copy`/`Clone`; Drop → FREE (Release), получатель — выигранный Acquire-CAS (claim или maintenance). `DomainTable`/`try_transfer` в Ph4a не вводятся; «переносимый lease» плана выполнен в этой форме. Если позже понадобится адресная передача — только «числовая» (`index`, `generation`), получатель сам выигрывает CAS из нового состояния HANDOFF, недоставленный HANDOFF откатывается в FREE (отдельное решение).
   - Что доказать: **S1** исключительность носителя `&mut HeapCore` ∈ {победитель INITIALIZING, `HeapLease`, `MaintenanceLease`}; **S2** happens-before (Release в Drop → Acquire-CAS); **S3** сырой указатель не утекает (единственная производная — TLS-кэш того же потока, отравляется TORN раньше Drop); **S4** lease создаётся после чтения `initialised == true`, `&'static HeapSlot` валиден (чанки registry не освобождаются).
   - Тесты: расширить Loom `tests/loom_r8_maintenance_lease.rs` (Drop владельца ‖ claim ‖ maintenance); мутанты Relaxed вместо Release, lease по проигранному CAS, `core()` после Drop — красные; compile-time `!Send/!Sync` (`const _`, без новых зависимостей и doctest); Miri SB+TB: claim → drop → claim на другом потоке.
2. **Без «GC» и отзыва lease.** Освобождение слота — только Drop → FREE; существующего reclaim при повторном claim (`trim_for_recycle`, `claim.rs:298`) достаточно. Lease, потерянный без Drop (поток убит без TLS-деструкторов) — документированная утечка слота и памяти, не UB. Забрать слот по таймауту = claim под чужим `&mut HeapCore` (запрещено).
   - Тест: нативный `ph4_late_publication_across_recycle_exactly_once` на реальном `#[global_allocator]` (A выходит; B освобождает часть блоков до повторного claim, часть — после claim потоком C; C делает trim): каждый блок retire ровно один раз, `FOREIGN_OR_UNROUTABLE_FREES` +0; мутанты «сброс sidecar при recycle», «двойной consume ingress» красные; Loom: publish ‖ recycle ‖ drain.
3. **`HELP_BUDGET` не утверждается (G3+ не принят).** Пред-регистрация на случай переоткрытия: K = 1 FREE-слот на событие роста; ingress ≤ 64; ≤ 1 освобождение ОС за помощь (нужен новый шаг без `trim_cold_retention`); помощь только перед `bump_count` и перед резервированием сегмента, никогда при refill из существующих сегментов, dealloc, realloc. **NO-GO:** любой жёсткий предел ADR пробит (refill/flush EstCycles > 1.05 или Ir > 1.10; larson/mstress geomean < 0.95 или T < 0.90; RSS > 1.05 или +1 MiB); p99 холодного роста > 1.10 к B; активация помощи < 95% в плече с помощью; ненулевой счётчик помощи в плече без FREE-слотов.
4. **G3+ не принимается; Ph4b остаётся на G3.** P4 — N/A («не обещано»), не NOT_RUN и не PASS. В README/rustdoc помощь перед ростом не упоминается. Переоткрыть можно только по измеренному RSS-гейту: отдельный процесс на плечо, реальный `#[global_allocator]`, потоки рождаются/умирают, поздние cross-thread free, без worker; удержание в FREE-heap > предела ADR (> 1.05 или +1 MiB) против того же плеча со `start_maintenance()`; тогда — поправка к ADR с бюджетом из п.3.
5. **Порядок выбора слота не меняется:** hint → bump → scan; новых политик/настроек нет (`stack.rs:116-138`). Честно описать в rustdoc/README, когда срабатывает G3: старый FREE-heap гарантированно переиспользуется через hint (последний recycled) или после исчерпания `MAX_HEAPS` = 4096 индексов (`bootstrap/registry.rs:45`). Тесты `r11_p3_registry_claim_selector.rs::{overwritten_free_hint_is_deferred_until_cap_not_lost, delayed_stale_hint_cannot_grant_a_second_owner}` остаются зелёными без правок; мутант «scan раньше bump» красит первый.
6. **В Ph4a ничего не сужать; сужение — отдельная фаза Ph4c** (интегратор, после Ph4b, отдельным коммитом). По коду методы публичны только под `internals` и скрыты: модуль `registry` — `pub` только при `internals` (`src/lib.rs:480-487`), `HeapRegistry`/`MaintenanceLease` — `#[doc(hidden)]` (`claim.rs:33`, `:391`; `registry/mod.rs:32`, `:75-76`); `claim` (`:83`) и `claim_with_config` (`:113`) — `pub fn` (сырой указатель); `recycle` (`:354`) и `with_core` (`:406`) — `pub unsafe fn`; `try_maintenance` (`:41`) — `pub fn`. Это не стабильная поверхность (ADR `:90`).
   - Ph4a: старые методы — тонкие обёртки над `HeapLease` с прежней семантикой (`claim` превращает lease в сырой указатель без Drop; `recycle` при не-LIVE слоте — тихий no-op); новый код в `src/` обёртки не вызывает (кроме `tls_heap` до Ph4b; проверка grep'ом в receipt); новых `pub unsafe` нет.
   - Ph4c: безопасная замена для тестов под `internals` (RAII-хэндл с числовыми наблюдателями) → миграция тестов (с проверкой «падал бы без фикса») → только потом `pub(crate)`; существующие `pub unsafe` (`recycle`, `with_core`) завести в `docs/CORRECTNESS_OPEN_ITEMS.md` как долг с триггером «Ph4c».
7. **Публичного `DomainId` нет, связи с `Profile`/`LargeCacheConfig` нет.** «Домен» внутри — носитель lease (привязка потока `GUARD` или визит maintenance-worker'а); fallback — отдельный режим со своим lock, не домен; конфиг на уровне слота, побеждает первый (`claim.rs:96-106`). Порядок при выходе потока: TORN → `trim_for_recycle` → Drop(lease); при откате в `finish_bind`: `LOCAL := null` до Drop lease. Тесты: `tls_heap_teardown_*`, `dealloc_only_no_bind*` без правок; iai горячих плеч ≤ 1.02; в тестах с `with_config` прирост `config_conflicts_total` = 0.
8. **Fork/unload без изменений.** Worker стартует только явно, один на процесс, не лениво и не по доменам; fork активированного процесса и выгрузка не поддерживаются; atfork не добавляем (`maintenance_service.rs:6-13`, `sefer_alloc/maintenance.rs:32-35`). P2-контроль: `!SeferAlloc::maintenance_running()` после alloc/free/trim и выхода потоков без `start_maintenance()`.
9. **Perf-база и идентичность.** B_4a — SHA `main` в момент создания worktree Ph4a (уже с принятым Ph3c); C — временный measurement-коммит или `git diff | sha256sum` над B; B_4b — принятый коммит Ph4a. **Накопительный якорь B0 = `7d80d7e1`** (последний коммит перед первым кодовым коммитом Ph3 `faf253e9`); отношение C/B0 — в том же CSV на каждой фазе. Пробит жёсткий предел накопительно к B0 — стоп и решение владельца. Нужны все строки ADR, включая larson/mstress T = 1, 2, 4, 8, контроль A/A, ≥ 5 прогонов, отдельный процесс на плечо.
10. **G4 — только условная гарантия** (как в rustdoc `src/global/sefer_alloc/maintenance.rs:18-30` и README `:118-121`): `Err` — гарантия не активна; «best-effort» не обещается; аллокатор старт не повторяет. Матрица receipt: `tests/r8_autonomous_maintenance.rs:137-167` (`internals bench-internals`) + новый `ph4_p2_no_worker_pending_stays` (без старта worker'а pending и сегменты не двигаются; мутант «скрытый reclaim из пути аллокации» красный).

## 3. Что вставить в ADR (когда владелец примет)

- **Статус:** «ADR привязан к неизменяемому `93f182a2`; первый runtime-коммит Ph3 — `faf253e9`. Решения по Ph4 от 2026-10-02 — в этом дополнении, подлежат принятию владельцем.»
- **Решение 7 (Ph4a):** право на состояние heap — у `HeapLease` (`pub(crate)`, `!Send + !Sync`, не `Copy`/`Clone`; Drop → FREE Release; при неудачном CAS в Drop — abort); передача только через состояние слота; `DomainTable` и адресная передача — вне Ph4; новых `unsafe impl Send/Sync` нет.
- **Решение 8 (G3+):** не принят; P4 — N/A; переоткрытие только по измеренному RSS-гейту без worker; бюджет из п.2.3.
- **Гарантии, строка G3:** «…при повторном claim слота: через hint последнего recycled-слота или после исчерпания 4096 индексов (порядок hint → bump → scan сохраняется).»
- **Решение 9 (домен и TLS):** публичного `DomainId` нет; `LOCAL` — константный `Cell<*mut HeapCore>` без Drop; lease в `GUARD`; порядок выхода TORN → `trim_for_recycle` → Drop(lease).
- **Совместимость:** `HeapRegistry::{claim, claim_with_config, recycle, try_maintenance}` и `MaintenanceLease::with_core` — legacy-поверхность за `internals`/`#[doc(hidden)]`; Ph4a — обёртки; сужение — Ph4c.
- **Lock-order:** под любым slot/maintenance lease fallback только через `try_with_heap`; `CONTROL` никогда не берётся внутри `GlobalAlloc`.
- **Гейты:** C5 + Loom-модель lease и `!Send/!Sync` compile-time; P2 + `ph4_p2_no_worker_pending_stays`; exactly-once поздней публикации через recycle.
- **Perf:** неизменяемые SHA B и C до первого кодового коммита фазы; накопительный якорь B0 = `7d80d7e1`.
- **Стоп-линии:** не забирать lease по таймауту или смерти домена; не хранить в `LOCAL` тип с Drop; не запускать worker из пути аллокации; код Ph4a — только после принятия Ph3c.
- **Допущения:** аварийное завершение потока без TLS-деструкторов — утечка слота и его памяти (не UB), без восстановления.

## 4. Остаточные риски

- **G3 слабая:** без worker поздние free в старых FREE-heap держат память, пока не сработает hint, не исчерпаны 4096 индексов или не запущен worker; для процесса без `start_maintenance()` — бессрочно (ADR `:46` это принимает).
- **Хвост латентности нового потока:** `trim_for_recycle` при повторном claim (`claim.rs:298`) выполняется на первом alloc нового потока и не ограничен по syscalls; Ph4 это не меняет, должно проявиться в larson/mstress.
- **Устаревшие указатели в тестах до Ph4c:** пока живы `pub unsafe recycle`/`with_core`, тест с устаревшим сырым указателем может перевести в FREE слот, уже занятый другим потоком; тип это не ловит.
- **Пределы инструментов:** Loom не доказывает provenance и реальный TLS teardown; Miri не воспроизводит порядок TLS-деструкторов на всех платформах; ветка TORN — только нативные тесты.
- **Миграция тестов (Ph4c):** 70–114 файлов; риск вакуумных тестов — нужны проверки «падал бы без фикса».
- **Ph4 не закрывает P1 и MODEL-LIMIT:** GO по Ph4 ≠ GO для установленного `Box`.
- **Зависимость от Ph3c:** если Ph3c изменит API drain sidecar в `heap_core_xthread`, Loom-модели Ph4a придётся переписать.
