**P2-1 (`6c8b15c`)** — `/proc/self` resolves to the thread-GROUP LEADER
(main thread), not the calling thread. A multithreaded process's main
thread can legitimately exit via `pthread_exit` while the process keeps
running; the kernel clears the exiting task's `mm` at every thread exit, so
the leader-named status file survives but loses its `Vm*` fields even
though the process is alive and measurable. Fixed by reading
`/proc/thread-self/status` (falling back to `/proc/self/status` on
pre-3.17 kernels). New `tests/thread_leader_exit.rs`: a real native
lifecycle scenario — the process's actual main thread exits via the raw
`SYS_exit` thread-exit syscall (not `pthread_exit` from a Rust frame, which
risks an abort on unwind) while a worker proves it still gets a real
reading. Verified independently on real Linux (WSL2), including personally
running the counterfactual (pre-fix code makes the test fail with exactly
`Malformed`).

**P3-1/P3-2/P3-3 (`a2640b7`)** — three findings closed together because
they share one root fix, per the review's own recommendation. P3-1: the
bytes parser accepted a numeric PREFIX (`12oops kB` → `Some(12)`) instead
of a validated integer; grammar tightened to
`ws+ digit+ ws+ "kB" ws*`, rejecting deviations outright. P3-2: the live
scale oracle (`kb*64..=kb*16384` ratio band) could not distinguish ×1024
from ×2048 or ×1000 — extracted the production conversion into a closed
seam, `src/status_convert.rs` (`memstat_from_status` /
`snapshot_from_read`), tested against an immutable fixture byte-for-byte;
the live test demoted to an honest smoke check whose own blind spots are
pinned AS PASSING rather than hidden. P3-3: the UTF-8-regression guard and
error contract were tested around the real path, not through it — new
`tests/non_utf8_name.rs` sets the calling thread's real `comm` to raw bytes
containing `0xFF` via `prctl(PR_SET_NAME)` and runs the actual backend
against it; `snapshot_from_read`'s injectable acquisition step lets
`Os`/`Malformed` be tested per-injected-result instead of inferred from two
live calls. Verified personally on WSL, including three separate
counterfactuals (strict-grammar sabotage, `*1000` multiplier sabotage,
`read_to_string` regression sabotage) — each caught exactly the intended
regression, none other.

**P4 batch (`6f26840`)** — all six P4 (non-blocking) findings. P4-1:
`checked_mul(1024)` on all three scaled fields, closing a
panic-or-silent-wrap gap above `u64::MAX/1024`. P4-2: the macOS cached
Mach-port SAFETY comment now names BOTH write points (startup AND
post-fork child re-init) — no data race found or claimed, just an
incomplete proof completed. P4-3: `tests/monotonicity.rs`'s "non-panicking"
Drop guard actually called `eprintln!`, which can itself panic on a broken
stderr during an unwind — replaced with a raw `write_all` whose `Result` is
discarded. P4-4: the rejected fused-reader's "one prefix per line"
precondition was assumed, not enforced — documented explicitly and pinned
with a duplicate-prefix fixture rather than changed (production never
calls it; changing it would alter the already-recorded NO-GO measurement's

call" (~3.17%) from "the saving fusing provides" (~2.0%), previously
conflated; nothing re-measured. P4-6: narrowed several remaining
overclaims (the all-zero-fallback claim, the CI-history claim, the
platform_contract.rs "independent"/"moves no memory" claims). Verified
