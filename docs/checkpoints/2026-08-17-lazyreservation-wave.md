**Главное за сессию — смена решения по item 66 под давлением владельца.** Я
рекомендовал вариант (d): принять caller-tracked контракт и ограничиться
`const fn`-запросом. Владелец отверг: «мы публикуем крейт, нельзя идти путём
C++ — нужно дать инструменты, чтобы потребители не писали костылей». Возражение
засчитано, и я это признал явно: моя аргументация была направлена против
ПРИБИВАНИЯ ПОЛЯ к `Reservation` (обновлять его некому — методы берут `&self`,
свободные функции работают по сырому указателю), а не против переноса учёта в
крейт вообще.

**Что построено вместо этого** (коммит `0c1e6c4`): тип `LazyReservation`,
владеющий резервацией И водоразделом. `ensure_committed(len)` идемпотентен и
монотонен, округляет ВВЕРХ; `shrink_committed` тоже вверх, чтобы не отдать
страницу с байтом, который просили сохранить; `into_reservation()` — явная дверь
наружу. Мутаторы берут `&mut self` — это не гигиена, а первое честное
высказывание крейта о параллелизме. Плюс `lazy_commit_is_honored()`, из которого
ВЫВОДИТСЯ начальный водораздел, поэтому счётчик и запрос не могут разойтись.
Отслеживается ровно одно число; произвольные дыры намеренно непредставимы —
это была бы побитовая карта, то есть аллокатор, то есть другой крейт.

**Ярус 4 доделан, но НЕ закоммичен** (в рабочем дереве): `try_decommit` —
недостающий fallible-двойник, плюс `debug_assert` в `decommit`. «Пустой
диапазон» отделён от «нарушения контракта», которые раньше были одной веткой
`start >= end`.

## Decisions

- **Вариант (b) вместо (d) по item 66.** Отвергнуто: принять caller-tracked
  контракт. Причина смены — довод владельца про «мешок ножей»; мой контраргумент
  был против поля, а не против переноса учёта.
- **Один очевидный способ вместо двух.** `reserve_aligned_lazy` МЕНЯЕТ
  возвращаемый тип на `LazyReservation` (breaking, но 0.2.0 не опубликован).
  Отвергнут второй параллельный конструктор.
- **Дыры намеренно непредставимы.** Отвергнута побитовая карта. Правило,
  пригодное для будущих предложений: крейт заводит состояние ТОЛЬКО если ОС
  дёшево его не отдаёт И вызывающий иначе обязан изобрести его сам.
- **Аллокатор НЕ переучивается.** Три его lazy-сайта берут `.into_reservation()`
  — его frontier живёт внутри заголовка сегмента, потому что горячий путь имеет
  только голый указатель. Это и есть случай, ради которого сырые функции
  остаются публичными.
- **Распил файла — отдельным механическим коммитом** с машинной распиской
  (мультимножество непустых строк до/после). Отвергнуто: смешать с
  функциональной волной — тогда ревьюер не отличит перенос от изменения.

## Среда — то, что легко забыть

- `npm run check` только из основного чекаута: в worktree `cargo fmt --all`
  падает с `os error 206` (лимит длины командной строки Windows).
- Общий target-dir `D:/dev/rust/.cargo-target`; перед верификацией
  `touch crates/aligned-vmem/src/lib.rs`, иначе cargo рапортует «Finished» из
  кэша без единой строки «Checking».
- `git grep -E` НЕ поддерживает lookahead `(?!...)` — команда падает, пустой
  вывод читается как «совпадений нет». Использовать `-P`. Дважды дало ложный
  зелёный при переименовании каталогов.
- Отчёты ревью в `docs/reviews/` — untracked, в git-worktree их нет.
- Unix-ветки кода с Windows-хоста невидимы: проверять
  `--target x86_64-unknown-linux-gnu` и `i686-unknown-linux-gnu`.
