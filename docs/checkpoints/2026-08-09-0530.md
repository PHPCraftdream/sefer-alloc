## Decisions

- **User: "act independently, don't ask me — you can ask @oh"** — standing
  instruction for the rest of this session.
- **#706's fix**: RAII guard (`RollbackGuard`) rather than a manual
  try/catch-shaped pattern — idiomatic Rust panic-safety, fires correctly
  on both the explicit OOM path (defused first) and the unwind path
  (never defused).
- **#709's fix**: `expose_provenance`/`with_exposed_provenance_mut` (the
  task's own "ALTERNATIVE" route) rather than storing pointers directly
  (the "PREFERRED" route) — the preferred route doesn't work here, since
  `Mutex<Vec<*mut Payload>>` would itself be `!Sync` (raw pointers are
  `!Send`), so it can't cross the spawned-closure thread boundary at all.
- **#710's API posture decision**: promote both `dbg_*` hooks to
  documented, non-hidden stable public API rather than feature-gating them
  — `#[doc(hidden)] pub` is self-contradictory when the function's own doc
  explicitly invites external consumer use (unlike tagged-index-stack's
  `raw_head`, which had zero production/consumer-facing use case and so
  correctly stayed `#[doc(hidden)]` in task #704). Feature-gating was
  rejected as disproportionate: both hooks are already exercised
  unconditionally by this crate's own test suite, so gating would require
  restructuring that whole suite plus a CI matrix addition.
