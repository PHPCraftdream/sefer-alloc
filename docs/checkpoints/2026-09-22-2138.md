The review's claim: `SegmentHeader::read_at` (`Node::read_struct` — a plain,
non-atomic full-struct load) reads the WHOLE header including
`deferred_next`, a `u64` field a REMOTE thread may concurrently CAS/store

(undefined behavior) under Rust's memory model, independent of whether the
specific call site ever uses the resulting `deferred_next` value — the race
is in the non-atomic READ touching memory a concurrent atomic write also
touches, not in what happens to the result afterward.

Audited EVERY real `read_at`/`.header()` call site in `src/` (8 total, not
just the 2 the review explicitly named): `alloc_core/lifecycle.rs:438`
(`AllocCore::drop`), `alloc_core/mem/mod.rs:237` (own-thread Large

(the same `AllocCore::drop` walk), `small/alloc_core_small_reclaim.rs:453`
(`dbg_drain_all_rings_impl`, review-named), `alloc_core/bootstrap.rs:309`
(one-time process bootstrap), `small/alloc_core_small_pool/mod.rs:907`
(`dbg_segment_state_reconciliation`, review-named). Several of these are
individually arguable as "provably quiescent" (own-thread-only access, or
single-threaded init), but rather than proving that fragile argument
per-site (and per future caller), chose the STRUCTURALLY sound fix the
review's own second suggested option names: fix `read_at` ITSELF so it is
sound for every caller, including a diagnostic walk over segments this
thread does not own.

**The fix:** added `Node::read_struct_with_atomic_word<T>(src, atomic_word_off)`
to the confined `platform/node.rs` unsafe seam — copies the bytes BEFORE and
AFTER the named 8-byte word via two disjoint `copy_nonoverlapping` calls
(never touching that word's bytes non-atomically at all), then fills the
word via a REAL atomic load. `SegmentHeader::read_at` now calls this with
`deferred_next`'s `offset_of!` offset instead of a plain `Node::read_struct`.
This closes the race structurally for all 8 (and any future) callers with
ONE change, at negligible cost (every call site is already documented
cold-path).

## Decisions

- R2-06: chose to fix `SegmentHeader::read_at` ITSELF (via a new generic
  `Node::read_struct_with_atomic_word` primitive in the confined `node.rs`
  seam) rather than proving/documenting quiescence per call site — a
  structurally stronger, simpler-to-maintain fix that protects all 8
  current callers AND any future ones, at negligible cost (every call site
  is cold-path by the crate's own existing documentation).
- R2-06: rejected the "overwrite the field after a plain aggregate read"
  approach (read the whole struct via `Node::read_struct`, then splice in
  an atomic-loaded `deferred_next` afterward) as UNSOUND — the data race is
  in the non-atomic READ touching memory a concurrent atomic write also
  touches, not in what the caller does with the result; overwriting a
  racily-read value does not retroactively make the read itself sound
  under Rust's memory model. The chosen fix instead structurally NEVER
  performs a non-atomic read over the atomic word's bytes at all (two
  disjoint `copy_nonoverlapping` calls around it, real atomic load for the
  word itself).
- R2-06: built a REAL cross-thread miri test (mirroring the established
  `regression_xthread_thread_free_alias_miri.rs` shape) rather than a loom
  model, specifically so it exercises the ACTUAL production code
  (`read_at`, `push_large_deferred_free`) rather than a hand-reimplemented
  abstraction — loom cannot model "non-atomic read racing atomic write"
  UB the way miri's real data-race detector can; that detector is
  precisely what this finding needs.
- Both #2004/#2005's cross-instance-identity fix and #2007's provenance fix
  established, and #2008 continued, an empirical-probe-first /
  counterfactual-verification-first methodology: before touching source,
  write a minimal reproduction of the claimed defect and confirm it
  actually behaves as claimed (sometimes contradicting an existing code
  comment); after fixing, re-run the SAME probe (now a permanent
  regression test) and additionally confirm — via a genuine revert-and-
  recheck — that it fails without the fix. This is now the working pattern
  for all remaining tasks with a similarly strong, checkable empirical
  claim.
