**The `bind_range` design decision**: consulted `@fh` (recommended page-envelope rounding + a status-returning API, i.e. options b+c combined) then `@ox` for an adversarial second opinion (agreed page-envelope is technically safe, but disagreed that making it a breaking-change status return was justified — all 4 existing 0.2.0 breaking changes are mock-surface-only, this would be the FIRST break to real API; recommended an ADDITIVE `bind_range_status()` alongside an unchanged `bind_range()` instead). The user then separately invoked `/fm` (Sol-codex) on that brief and got a FIFTH recommendation that superseded both: `bind_range` cannot be meaningfully fixed at all, because even a page-aligned/enveloped `mbind` call only affects FUTURE page faults — `vec![0u8; 4096]` is already zero-faulted-in by the `vec!` macro BEFORE `bind_range` is ever called, so no fix to the byte-range API can make the README's own example actually work. Sol-codex's recommendation: remove `bind_range` entirely, replace it with a reservation-time-only `reserve_preferred_on_node(size, align, NodeId) -> Result<Reservation, ReserveNumaError>` where "successfully bound" is true by construction. ## Decisions

1. **`bind_range` removed entirely, replaced by fallible `reserve_preferred_on_node`** — Sol-codex's 5th-option recommendation, superseding both `@fh`'s (page-envelope + status return, breaking) and `@ox`'s (page-envelope + additive status fn, non-breaking) earlier analyses. Root cause: no byte-range API can honestly "bind" already-touched memory (mbind's default flags only affect future page faults), so the only honest fix is reservation-time-only. User explicitly confirmed after reading a written-up decision brief.
2. **Execution agent for numa-shim tasks: `/crush` (reconfirmed)** — mid-session the user asked to switch from `@sh` back to `/crush` for future runs ("переключаемся на ангетов /crush (в будущих ранах)"). Task #1306 was executed via `/crush` + worktree, matching this.
3. **Root crate's `bind_segment` seam removed, not redesigned** — confirmed no production caller existed (only `tests/numa_seam.rs`); the actual production path (`reserve_aligned_on_node`) now composes its own best-effort NUMA fallback visibly at its call site, per `@ox`'s specific recommendation that best-effort belongs at the caller, not hidden in the shim.
4. **Process-safety rule added to global CLAUDE.md**: never kill processes by image name (`taskkill //IM`), only by specific PID of one's own child processes — added after the user flagged an overly broad `taskkill //IM cargo.exe //T` I ran while debugging a build-directory lock contention issue.
