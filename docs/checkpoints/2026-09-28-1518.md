Most of the session then went into why the local `npm run check` kept failing
with `rustc`/`link.exe` exiting 1 with no diagnostic (item 153). It was first
blamed on sccache, which was refuted: it recurs under `RUSTC_WRAPPER=` with a
bare `rustc.exe`. The mechanism was found with a non-admin WMI
process-creation watcher and a logging `RUSTC_WRAPPER` (both scratch under the
system temp dir, not committed). Every Claude Code 2.1.281 session on the host
spawns `taskkill /PID <n> /T /F` directly from `claude.exe`, mostly against its
own already-exited statusLine process (`bash -c "node <statusline script>"`),
up to 8 times per PID. Windows reuses those PIDs, so other processes get
killed. Examples: our rustc, the logging wrapper itself, clippy-driver,
`docker stats`, another session's shells, a Codex node. The user approved
posting the data as a Windows-variant comment on anthropics/claude-code#96394
(https://github.com/anthropics/claude-code/issues/96394#issuecomment-5867853336).
The crates.io DNS also flapped at the same time (router DNS "Server failed";
the host itself is reachable by IP). Both were worked around by resuming the
gate from the failed step via a temporary copy of `scripts/check-all.mjs` with
the step list spliced; the copy was deleted each time.
