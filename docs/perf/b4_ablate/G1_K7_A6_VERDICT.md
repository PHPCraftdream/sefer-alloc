## Reading (not part of the decision)

- The win is large and confirmed by both instruments: bulk16k t_mi/t_sefer
  0.496 → 0.831 (K7/K5 1.675), churn64 1.081, churn1024 1.047; run 1 E_v
  bulk16k −52.45 %, GL1 bulk64k −9.88 %, GL2 bulk16k_32 −26.82 %.
- The loss is small and seen only by run 1: pair16 E_v +0.62 %, pair64 +0.73
  %. D (v5 − U, same data layout) is +0.34 % / +0.30 % with CI above 0, so
  that part (0.34 of 0.62, 0.30 of 0.73) is executed K7 code, not layout;
  the rest is layout (E_u +0.28 % / +0.44 %).
  P4 (b) explains where that code runs: in the G11 mix the overflow holds
  bulk16k's records from bulk16k on and never empties, so every segment
  refill of every kernel, the pair kernels included, ticks the decay.
- Run 2 does not see this loss (pair16 K7/K5 1.0021, no detected difference;
  pair64 1.0181, K7 faster). The two instruments disagree at the sub-1 %
  level on the pair kernels; the pre-registered rule takes run 1's loss
  without an exception (D CI lower > 0), and the rule is applied as written.
- bulk64 is not judgeable in run 2 (K7 0/8 admitted); churn16 is not
  judgeable for either tree. Both are decided by run 1 alone (no E_v loss).

## Consequence

- G1-K7 design revisions 4–5 are closed for this round (§ Finite). v4 and v5
