# NL-1 — `production` without `misuse-checks` (`perf(opt-in)`, measured; the default is unchanged)

Generated by `node scripts/nl1_report.mjs` from `docs/perf/nl1/raw` (written by `docs/perf/nl1/nl1.sh`);
summary: `docs/perf/NL1_MISUSE_CHECKS_OFF_summary.csv`. Do not edit by hand.

## 1. Question

NL-1 added the feature `misuse-checks` (in `production` and `hardened`). Without it a release
build neither writes nor reads the per-block state byte: the free lanes, `small_free_guard`,
`AllocCore` small dealloc, the magazine flush guard 2 and the sidecar reclaim FREE/MAG refusal are
removed as one set. What does that cost or save, on the real bundle?

## 2. Method and identity

- Entry point: `b4_pmu_probe bulk sefer 1024 <16|64> <passes>` and `g1_mt_one <larson|mstress> sefer <T> <steps>`,
  both on the real `SeferAlloc` `#[global_allocator]` (examples, `--features production`, release,
  the repository's alignment RUSTFLAGS).
- Source identity: `git archive` of main at `6ff20803` (landing of PR #188), tar sha256
  `69904939ffbef585124941120675b47e013e4b858fdb5169e3546b5c5cef5084`. Both arms are that tree; the off arm
  differs only by the `production` line of `Cargo.toml` without `"misuse-checks"` (the probes require the literal
  feature `production`); the diff and the binary hashes are in `docs/perf/nl1/raw/identity.txt`.
- Instructions: callgrind (`bulk`: 400 passes; MT: 100000 steps). Time: 5 repetitions of the order on, off, off, on
  (ABBA), so 10 samples per arm and cell, median and [min..max]; `bulk` 4000 passes, MT 1000000 steps.
- Path activation: the instruction deltas below are the evidence that the off arm skips the byte traffic
  (the same source, only the cfg differs); `tests/nl1_misuse_checks_state_byte_switch.rs` pins in CI
  (release, no `misuse-checks`) that the byte is not written, and the three `nl3_*` oracles run in the same row.
- Host: WSL2 Ubuntu 24.04 on the shared lab machine. Rule: no time claim from a T=4 cell whose sample ranges overlap.

## 4. Reading

- Instructions fall in every cell: -10.03 % on bulk (both sizes), -4.94 % / -4.91 % on larson T=1 / T=4,
  -6.74 % / -5.74 % on mstress T=1 / T=4 (denominators: the `on` callgrind totals in the table).
- Time (T=1 and bulk, where the samples are tight): bulk 16 B -10.40 %, bulk 64 B -7.28 %,
  larson T=1 -5.80 %, mstress T=1 -6.36 %. T=4 cells are not claimed.
- The prototype ceilings of NL-0 (docs/perf/NL0_LIVENESS_CEILING.md, NL0C_LIVENESS_CHECKS_CEILING.md) were
  B −9.26 % and C −13.64 % Ir on bulk; the implemented set is between them, as expected (the bound check of the
  free lanes stays until NL-4). The T=4 loss of prototype B (writes removed, readers kept) does not appear:
  here the readers are removed with the writers, and the cross-thread reuse oracles pass in this mode on CI.
- Not shown: RSS and the cold paths (the byte is still absent there too, nothing is added).

## 5. Verdict

`perf(opt-in)` result, not a default change: `production` still includes `misuse-checks`. The measured gain is the
size of what NL-9 would ship by dropping it from `production` once the remaining verification layers are in.
