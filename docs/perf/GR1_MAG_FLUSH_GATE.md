# GR-1 — flush из магазина без повторных проверок: NO-GO (измерение, прод не меняется)

Вердикт: **NO-GO** по предрегистрации (`gr1_mag_flush/GR1_PREREG.md`, записана
до замера). Код в main не идёт. Отчёт — измерительный (`bench`).

## Что проверялось

Владелец спросил: можно ли ускорить прод, отключив проверки, которые уже
покрыты тестами. Решение владельца: отключать только то, что можно отключить
безопасно; защиты от ввода извне (двойной free, чужой указатель, ответы ОС)
остаются.

GR-0 (абляция, growth16, callgrind) нашёл кандидата: `flush_run` повторно
проверяет каждый блок магазина — диапазон `[payload_start, bump)` и байт
состояния. Для блоков из магазина обе проверки всегда истинны: при free блок
проходит оракулы M2 (`small_free_guard`) и получает состояние MAG; refill и
пакетное заполнение магазина тоже пишут MAG. Инвариант I-MAG: каждый слот
магазина класса `c` — начало блока класса `c` в живом сегменте этой кучи, в
диапазоне, с байтом `encode(c, MAG)`. Пакетный free (staging, блоки LIVE,
возможны дубли в одном вызове) должен остаться на проверенном flush.

Вариант `gr1_mag_flush` (патч `gr1_mag_flush/gr1_mag_flush.patch`): три точки
flush магазина (половинный сброс при переполнении, вытеснение по лимиту
класса, `flush_all_tcache` при завершении потока) вызывают
`flush_magazine_internal` — тот же проход без двух проверок. В проверочных
сборках вместо них стоит ghost-проверка `mag-flush/mag-resident`.

## Вывод

Проверки, которые GR-1 убирает, стоят 20 Ir на блок, но во времени их цена не
видна: на bulk вариант медленнее на 2.3–3.5 %, хотя инструкций на 7.5 % меньше.
Значит, на bulk время ограничено не числом инструкций flush, а памятью
(запись `next` в холодные тела блоков, bulk16k ≈ 1 МиБ живых блоков) или
раскладкой кода копии варианта. Какая из двух причин — не установлено: для
этого нужны счётчики PMU на тех же ядрах, их не мерили. Отключение этих
проверок не окупается на ядрах судьи, поэтому оно не идёт в main, и проверки
остаются в проде.

Остаётся полезным и идёт отдельно: прогон всего набора тестов в
ghost-сборке нашёл реальную поломку G2 (тест `r19_large_cache_decay_trim`
не компилировался, исправлено в PR #113, `657dd4a9`).
