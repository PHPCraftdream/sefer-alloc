## Контроль A/A (mimalloc-плечи)

ΔIr: 11 из 13 плеч ровно 0.000%; `mimalloc_recycle_alloc_free_256x{16,64}b` —
−7 Ir (−0.013%, 53027→53020); ΔEstCycles max +0.572% (исторический шум A/A по
PG-3: ≤ +0.545%). Плечи mimalloc не исполняют ни одной инструкции кода спайка;
детерминированный сдвиг ±7 Ir объясняется изменением кодогена самих bench-функций
в едином бинарнике (layout-сдвиг), механизм — наиболее вероятное объяснение,
прямое доказательство по per-function данным не снималось. Формально критерий
«ΔIr = 0.000% ровно» нарушен на 2 плечах — зафиксировано честно; на гейты ADR
(исполняемый код спайка) не влияет. Правило «перемер один раз»: перемер дал
идентичные Ir (детерминизм), т.е. это не шум.

## Корректность (обязательна до perf-вердикта)

1. `cargo test` (WSL, Linux): `production internals` — все наборы зелёные
   (163 suite-ok), кроме 2 задокументированных исключений; `production
   alloc-stats bench-internals internals` — 163 suite-ok, те же 2 исключения:
   - `tests/r1_04_alloc_core_drop_stack_pressure` — КРАСНЫЙ только на
     Windows-host debug-кодогене (переполнение 64 KiB-стека в `AllocCore::new`
     при живом кадре; breadcrumb-маркеры доказали, что new+drop функционально
     завершаются), в WSL/Linux тот же набор ЗЕЛЁНЫЙ на B3; CI (Linux) не
     затронут. base A на Windows-host зелёный — маржинальный стек, сдвиг
     кодогена от диффа B3; логика не задета.
   - `tests/r6_route_directory_model::terminal_publication_signatures_consume_the_pin`
     — предсуществующий инфраструктурный фейл (offline-резолюция `smallvec`
     для compile_fail-сабкрейта), воспроизводится на base A — не B3.
   - `tests/r11_p3_small_sidecar_issue_oom::persistent_spill_oom...` — адаптирован
     с обоснованием: при B3 под-лист одно-классен по построению, смешанный лист
     (и spill) не возникает ⇒ инъекция `fail_next_spills` неприменима (на base A
     тест зелёный — модельная разница, не дефект).
   - `tests/regression_freelist_next_validation` и родственные «инструзивные»
     проверки: неприменимы к free-set — интрузивной цепи (`Node::read_next`/
     `write_next`) больше не существует;ouble-free guard (`AllocBitmap`) и
     битовая модель покрыты остальными наборами (все зелёные).
   Прежние Miri-порядки: `narrow` и прочие зелёные miri-шаги не запускались в
   этой сессии целиком (запущен только `paused`); narrow не затронут диффом
   (retire-путь B3 не добавляет обращений к телу).
2. Miri `paused` — ЗЕЛЁНЫЙ (exit 0, `COMPLETE paused_terminal_owner_retirement`)
   на всех четырёх клетках: {production, alloc-global} × {SB strict-provenance, TB}.
3. Мутант (временное возвращение `Node::write_next` в `reclaim_sidecar_record`,
   откачен): Miri SB paused production — КРАСНЫЙ ровно в
   `platform/node.rs:94 Node::write_next` ← `reclaim_sidecar_record`
   («not granting access … weakly protected»).
4. Клетки C4 (`tests/r11_pg3c_b3s_model_limit.rs`, портирован из PG-2):
   - reissue — КРАСНАЯ в месте reissue (`Box::new` на alloc-пути при живом
     защищённом кадре) ✓ MODEL-LIMIT;
   - large release — КРАСНАЯ (dealloc при protected item) ✓;
   - seg-release — наблюдаемо ЗЕЛЁНАЯ (witness завершается): при B3 trim/release
     не пишет в байты продюсера, а OS-unmap невидим Miri; краснота PG-2 на этой
     клетке объяснялась записью при retire — устранена. Отклонение от «все C4
     красные» зафиксировано честно: red остаётся только там, где есть
     реальное обращение (reissue/release Large).
