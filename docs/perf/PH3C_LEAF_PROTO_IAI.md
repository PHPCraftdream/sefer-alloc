## Метод

Плечи (3+1): **I** — intrusive-эмуляция (`next` в теле блока, плоский битмап
is_free/mark_free), **N** — NextTable-спайк (`next` в off-body таблице),
**L** — кандидат B (per-leaf occupancy: 64 листа × 64 слова u64, заголовок
листа {class, free_count, first_hint}, per-class слово непустых листов),
**L2** — модификация B2 (заголовок {class, words_mask}, pop = два tzcnt без
скана; `free_count` только popcount'ом внутри merge). 9 сценариев × 4 плеча =
36 бенчей + `identity_check`.

Идентичность: `identity_check` идёт ПЕРВЫМ в группе и валит прогон при расхождении
множеств выданных оффсетов (I↔N, I↔L, I↔L2) и per-leaf free-set'ов. На
churn_one_class / drain_dense / drain_sparse_* / refill_cold_* / remote_merge
проверяется полное совпадение мультинаборов (порядок выдачи законно разный:
LIFO-стек у I/N против адресно-возрастающего у L/L2). На `churn_mixed`
частичный дренаж (32 из 64) законно выбирает РАЗНЫЕ слоты у разных моделей,
поэтому мультинабор там проверяется только для I↔N, а для всех четырёх плеч —
равенство восстановленного per-leaf free-set. Пройден: трейлер «37 without
regressions; 0 regressed».

## Вердикт (по §3.3)

* **B НЕ ПРОХОДИТ.** Плотный лист `drain_dense`: L/I = **1.258** (x1.25828,
  +25.83% Ir) при пороге §3.3 `> 1.10` — FAIL. Наблюдательно (вне гейтов §3.3,
  `refill_cold_16` L/I = **1.292** (+29.23% Ir), `churn_one_class` L/I =
  **1.475** (+47.46% Ir). Разреженные drain проходят с запасом: L/I = **1.004**
  (k=1), **1.014** (k=8), **1.051** (k=64) ≤ 1.25 — то есть **провал B не в
  W_eff-скане**: разреженный pop (hint/mask) почти бесплатен, цена проявляется
  именно на плотном листе.
* **Модификация B2 улучшает, но порог не закрывает.** `drain_dense` L2/I =
  **1.163**, `refill_cold_16/64` L2/I = **1.218**, `churn_one_class` L2/I =
  **1.322**, `churn_mixed` L2/I = **1.248** (у L — 1.235). Одна разрешённая
  итерация (§3.3: пересмотр механики при провале) использована — плотный
  порог 1.10 не достигнут ни в одной из них.
* **Фрагментация (§4 п.10).** Модель `churn_mixed` держит 48 листов по 64 КиБ
  под 8 классами (по 6 листов на класс: `class = leaf % 8`, 48 = 8 × 6) при 1 КиБ
  живых данных на лист: неиспользуемый хвост
  **3 145 728 Б** (48 × 64 КиБ) при **49 152 Б** живых — отношение ~**64×**.
  Угол ADR «RSS / живые байты ≤ 1.10» в этом дегенеративном режиме
  проваливается: класс, записанный в заголовок листа при первом карвинге,
  делает весь 64 КиБ лист недоступным другим классам. В реальном аллокаторе
  bump-карвинг заполняет листы плотнее (классы чередуются в одном курсоре), но
  направление риска подтверждено; мотивирует под-листья < 64 КиБ или
  lazy-материализацию листьев. Маркеры `println!` (`FRAGMENTATION_TAIL_BYTES`)
  проглотил iai-runner (в сыром логе их нет — проверено), поэтому значение
  выведено из констант модели: на снапшоте все 48 листов имеют по 64 re-retired
  блока, хвост = полная ёмкость листа.
* **Remote merge: гейт «≤ 1.00 Ir/блок» на уровне модели НЕ подтверждается.**
  Скалярный OR-цикл 64 слов — это порядка 10 Ir/блок. Прямое сравнение плечей
  некорректно: в плече L/L2 сидят ДВЕ конструкции модели (donor + target,
  десятки тыс. Ir) плюс OR-merge — конфаунд конструкции; в плече I/N — 64
  re-push, и всё плечо целиком даёт ≈ 563–570 Ir/блок. Числа «Ir на блок merge»
  сознательно не выводятся (см. секцию remote merge в выводе скрипта). Оценка
  гейта — после интеграции и/или векторизации OR.
* **Контроль N/I.** На «плотных» сценариях N/I = **1.023–1.153** (по всем
  девяти — 1.008–1.153). Направление совпадает с PG-3: плоский off-body дороже
  интрузии на всех сценариях — сигнал не шум.

## Механизм

Разница L−I держится и у L2, то есть это не скан: разреженные сценарии почти
бесплатны (hint/mask), а цена — константные per-op ALU-расходы битовой геометрии
(вычисление leaf/slot/word, загрузка заголовка листа, RMW слова occupancy /
слова класса, изменение порядка выдачи на адресно-возрастающий). В абсолютных
Ir на сценарий (из таблицы): `drain_dense` +42 244 (L) / +26 674 (L2),
`churn_one_class` +57 072 / +38 749, `refill_cold_16` +36 446 / +27 233,
`churn_mixed` +98 848 / +104 428 — B2 снимает часть этого (words_mask вместо
скана), но константная часть остаётся.

Интрузивный pop/retire в модели — ≈ 27.6 Ir/операцию (`churn_one_class`:
120 258 Ir на 4 352 операции), у L — ≈ 40.7 Ir/операцию. Дизайн-оценка §2.2
«retire кандидата ≤ 36 Ir ≈ базе» на этих последовательностях **не
подтверждается**: базовая эмуляция дешевле оценки, кандидат — дороже.

## Чего не измерено

- Эмуляция на арене: нет `bins.set_head`/`dec_live`/magazine — интеграционные
  точки замены (§3.3 шаг 2) не тронуты.
- Ir-модель без кэш-геометрии реального размеления: заголовок листа и
  occupancy в реальном аллокаторе лежат в одном регионе, Ir-модель этого не
  видит; EstCycles-дельты здесь скромны (плотные drain/refill 1.03–1.15, hot-чурн
  до 1.37).
- Wall-clock и реальное железо (EstCycles — модель callgrind).
- Эффект смены порядка выдачи LIFO → адресно-возрастающий на локальность
  повторной выдачи и на tcache-поведение.
- Векторизация merge и N_records реального drain.
