# NL-0 part 2 — ceiling of dropping the other misuse checks, and what a partial removal does (`bench`, measurement only)

Measurement-only: no shipping or opt-in code changed by this report. The prototypes are
throwaway commits on the branches `g1-nl0` (B, already cited by
`docs/perf/NL0_LIVENESS_CEILING.md`) and `g1-nl0c` (C), never merged.

## 1. Question

Owner decision 2026-11-03: every check that only fires on a violation of the
`GlobalAlloc` contract by unsafe code moves under the same opt-in flag, off by default.
Part 1 measured the liveness state byte (B). This part adds the candidate checks of
tasks NL-4 / NL-5 / NL-6 and measures them on the single-thread bulk lanes and on a
multi-thread workload set.

## 2. Prototypes (source identity)

Base: `main` @ `908f2aba`. Branch `g1-nl0c`, tip `d8b7eb7a442fd77b2faaadf5147b65bc2138ec9d`.

- B (`d0742881`): free lanes without the state compare; no `write_granule(MAG)` in the
  free lanes; no `set_state(LIVE)` on the alloc hit and refill lanes.
- C (`d8b7eb7a`): B plus

  - no FREE/MAG refusal of a sidecar record in `reclaim_sidecar_record`
    (`alloc_core_small_reclaim.rs`).

Binary sha256 and flags: `docs/perf/nl0c/identity.txt`, `docs/perf/nl0c/nl0c.sh`
(release, `--features production`, `-C llvm-args=-align-all-functions=6
-C llvm-args=-align-all-nofallthru-blocks=5`, Linux x86_64 under WSL2).

## 3. Entry points under test

- `b4_pmu_probe bulk sefer 1024 <16|64> <passes>`: bulk alloc then free through the
  `SeferAlloc` global-allocator shims (own-thread small lanes of `HeapCore`).
- `g1_mt_one <larson|mstress> sefer <T> <steps>` (`docs/perf/nl0c/g1_mt_one.rs`, the
  `malloc-bench-rs` workloads through `SeferAlloc`), T = 1 and 4: includes magazine
  flush, depot traffic and (T = 4) cross-thread frees reaching the reclaim path.

Callgrind: bulk 400 passes, MT 100 000 steps per thread. Time: bulk `perf stat`/probe
ns/op over 4000 passes; MT `g1_mt_one` 1 000 000 steps per thread. 5 runs per cell,
median.

## 5. Reading

1. **Instruction ceiling.** C removes 13.64 % Ir on the bulk lanes (B: 9.26 %) and
   6.0–9.3 % on larson / mstress (B: 4.2–6.3 %). The extra 4.4 points on bulk are the
   free-lane bound check plus the flush guards (bulk flushes at magazine overflow); their
   split is not measured here. The reclaim refusal does not run in a single-thread shape.
2. **Time ceiling, single thread.** bulk: −8.5 % (16 B) and −10.8 % (64 B) for C, equal
   to B within noise at 16 B; mstress1: −7.6 %. larson1: C is +2.5 % slower than base but
   the base's own five runs span 57.4–62.5 Mops and C's 56.3–63.3, so larson1 time is
   inside noise; its Ir drop is −6.96 %.
3. **T = 4 wall-clock is not a reliable ceiling here.** Base mstress4 spans 161–211
   Mops across five runs on this shared machine; C's 178–214 overlaps it. larson4: C
   within noise of base. No time claim is made from the T = 4 cells for C.
4. **B at T = 4 is a real regression, not noise (spread is tight): larson4 69.5–79.7
   against base 111.6–123.8 Mops; mstress4 126.3–132.0 against 161.4–210.6.** B stops
   maintaining the state byte on the hot lanes but leaves its readers. By code reading
   (not confirmed with a counter): a block refilled into a magazine is stamped MAG, the
   alloc hit no longer flips it to LIVE, so a live block keeps the MAG byte; when another
   thread frees it, `reclaim_sidecar_record` refuses the MAG record (returns false) and
   the block is neither linked into a bin nor returned to the owner. The allocator
   carves fresh memory instead. This fits the pattern: T = 1 (no cross-thread frees) is
   fine, T = 4 is not. C removes those readers and returns to base-level throughput. The takeaway is a design constraint, not a result
   to cite as speed: **the state byte's writers and all of its readers must be removed
   as one set under the flag; a partial removal silently leaks.** This is the first
   mutant for task NL-3 (a stale-state variant that keeps one reader).
5. **C is a ceiling, not a design.** The chain path (`small_free_guard`, reached on
   memo/`own_cache` misses and on Large/odd routes) still compares the state byte exactly
   and, with a byte the hot lanes no longer maintain, would refuse legitimate frees. The
   numbers above hold for lane-hit workloads (bulk, larson, mstress); a real unchecked
   mode must route every free through a path that does not read the byte.

## 6. Decision per candidate (from this ceiling)

| task | check | ceiling (Ir, bulk16 / mstress1) | verdict for the flag |
|---|---|---|---|
| NL-1 | liveness state byte (reads + hot writes) | −9.26 % / −6.33 % | take: ≥ 2 % Ir and ≥ 1.5 % time |
| NL-4 | free-lane bound check `g >= bump` | −4.4 pts / −3.0 pts over B | take (≥ 2 % Ir) provided the chain path is also unchecked-consistent |
| NL-5 | flush guards (span + state) | included in C; isolated cost not measured separately | measure alone in NL-5 |
| NL-6 | reclaim FREE/MAG refusal | needs a cross-thread-heavy cell; not isolated | measure alone in NL-6 (fan-in) |

(The "pts over B" column is C minus B in percent of the base Ir, from the table above:
13.64 − 9.26 = 4.38 for bulk16, 9.32 − 6.33 = 2.99 for mstress1.)

## 7. Next

  chain path.

- NL-3: add the stale-state mutant from §5.4 and require every layer to fail on it.
