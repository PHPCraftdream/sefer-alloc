## Savings model (stated assumptions)

- Proportionality: a subset run is priced as testSeconds × skippedTargets / total, where skippedTargets = total − selected; this scales all matched test-step time, including compilation/library overhead, by integration-target fraction even though `--lib` is always retained.
- This is an approximate model, not measured wall-time savings. It excludes other jobs and setup/cache/queue time. Test targets differ in duration; a subset may also skip doctests and example/bench compilation, which the model does not separately price.
- The ±30% same-job noise figure is contextual input from the user, not measured in this window; the report uses window sums, not per-job medians.

## Risks and coverage limits of enforce mode (read from code and docs, no run)

- A subset run skips doctests and does not compile examples/benches; the `clippy` rows (`--all-targets`) still cover their compilation (docs/CI_TIERS.md:175-181).
- Targets unmapped in every row (including `no-coverage` and other unmapped statuses) are always selected (scripts/select-tests.mjs:54-55; docs/CI_TIERS.md:167-173); this rule does not claim what those tests execute.
- A changed Rust or `tests/` file absent from mapped sets selects `all` (scripts/select-tests.mjs:18-25, 67-77); this rule does not establish that maps can never cover particular files.
- The selector chooses the tests whose maps cover changed files and returns args as `--lib` plus enabled selected targets (scripts/select-tests.mjs:36-77, 98-103; docs/CI_TIERS.md:167-181).
- The selector uses the latest successful `main` map (ci.yml:154-188); the map is valid only for its recorded SHA and rows (docs/CI_TIERS.md:134-156). A missing map (no successful map run found), failed map download, or selector error writes an all-mode fallback (.github/workflows/ci.yml:178-183); there is no freshness guarantee, so scheduled maps can be stale beyond the nightly cadence.
- File-reader attribution uses source-text patterns (`READS_FILES` in scripts/select-tests.mjs:18-25, 56-77). A test reading changed data through an unrecognized mechanism could be missed by attribution; unmapped tests remain selected.
- In `test-core`, artifact download and selection-args steps use `continue-on-error`, and the three cargo-test commands consume their outputs (ci.yml:579-614). A plain test command results when the selector arg output is empty; this does not establish atomic fallback for partial outputs or rule out unrelated upload/runner failures.
- Nightly full runs on `main`, an explicit `CI: full` trailer, and `workflow_dispatch` select all (selector `--full`; docs/CI_TIERS.md:116-127); weekly runs add weekly-only jobs.
