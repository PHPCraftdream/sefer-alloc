## 1. Question

NL-9 compared SeferAlloc with itself (checks on / off); J2 compared it with mimalloc on one thread. After both, is there a multi-thread
cell where mimalloc is ahead?

## 2. Method and identity

- Entry point: the real `SeferAlloc` and `mimalloc::MiMalloc` as the allocator of the malloc-bench-rs workloads `larson` and `mstress`
  (`docs/perf/nl9/g1_mt_one.rs`: working set 768, mstress blocks 512, 1000000 steps per thread), T = 1, 2, 4, 8 threads.
  One binary carries both allocators and selects one by argument, so both arms are the same build: `--features production`, release,
  the repository's alignment RUSTFLAGS.
- Source identity: `git archive` of main `c75c0e52`, tar sha256 `0a8b5778e11b55ee31db107e228d2414ad375fd0ff14d574472a2e786d8b7922` (`docs/perf/j4/raw/identity.txt` also holds the toolchain, CPU and binary hash).
- Order: 5 repetitions of sefer, mimalloc, mimalloc, sefer (ABBA), 10 samples per arm and cell; the position in the order is part of each raw file name.
  Cell = median Mops/s (higher is better) and [min..max] over the 10 samples. Verdict per cell: "ahead" only when the two sample ranges are disjoint, otherwise a tie.
- Host: WSL2 Ubuntu on the shared lab machine, 16 logical CPUs; single host, so the ranges, not the medians, carry the claim.
