# J13 limited harness usage handoff

Usage guidance for the additive JSON bridge in the existing `g1_big_judge` and `paired-ab-runner`; it does not authorize a build, test execution, CI dispatch, workload, or measurement. The preregistration carries only the dated owner source-size amendment; the workload design and measurement authorization remain unchanged. No new entrypoint, workflow, reducer, or build script is introduced here.

## Existing judge and paired-runner contract

The study-only environment is `G1_BIG_THP=off|always` and `G1_BIG_CACHE=off|on`; both values are required together. Optional `G1_BIG_BYTES` is an exact positive decimal byte count that must ceil to the CLI MiB argument. The existing judge CLI remains `g1_big_judge <cycle|edge|grow|many> sefer <size_mib> <reps> [k]`.

- Boundary cycle: `cycle sefer 8 1`, with `G1_BIG_BYTES=8388607`, cache off.
- Cache cycle: `cycle sefer 16 2 1`, cache on; the second life must be a real cache hit, not a synthetic warm metric.
- Other cells must use their already registered scenario/size/reps/k and byte-boundary arguments. No additional cells are authorized.

Use JSON config with `result_format: "json"`; `metric` defaults to `cold_ns` and, if supplied, must be `cold_ns`. Set no `build` field, use identical `command` and `args` for both arms, and set explicit actual `G1_BIG_*` values per arm. A is Off and B is Always; `--arms A,B` selects that comparison and `--arms A,A` selects the same-Off control. The executable path must come from the trusted CI build receipt below, not a guessed path or a runner-side build. Paired invocation shape is `node scripts/paired-ab-runner.mjs --config <config.json> --arms A,B --pairs 12`; do not execute it without separate authorization.

The producer's root `cold_ns` (surfaced as `row.cold_ns`) is allocation+touch+free; runner whole-child time is `row.launch.child_wall_ns`, not a producer/root `child_wall_ns`. Preserve both and the raw child/OS fields, including `row.parsed_row.os.faults`, `row.parsed_row.os.peak_rss`, `row.parsed_row.os.end_rss`, and `row.parsed_row.os.anon_huge_peak`; do not substitute one timing for the other, strip observer cost, subtract captured storage, or extrapolate an uninstrumented value. Native advice capture is enabled for these rows and itself has overhead; report its actual emitted storage facts separately. Fault counts and live `AnonHugePages` are corroborative only, not exact advice attribution, physical peak, or speed evidence. Each launch receipt carries the executable path, before/after `binary_sha256`, and `env_overrides`; the full producer object is also retained at `row.parsed_row`. The JSON A/B summary (A/B or A/A) is descriptive, not the preregistered reducer statistic; Task112 owns that reducer.

The `dbg_current_large_cache_budget()` read first resolves the configured facade, binding the caller's heap before the tuple/stats readback; its resulting configuration probe remains outside the timed payload path.

The JSON runner's `source_identity` remains only the observer checkout's commit/tree/dirty state; it is not the measurement binary's build receipt. `features_note` remains an unverified label. The existing preparation CI action performs one locked release build of `g1_big_judge` on the Linux CI build host, explicitly passing the `rustc --version --verbose` host triple with Cargo's `--target` (not relying on Cargo's implicit target selection), and uploads the exact compiler-artifact executable plus its raw compiler-artifact JSON, SHA-256, source commit/tree/status, verbose Rust/Cargo versions, actual target selection, and `RUSTFLAGS`/`CARGO_ENCODED_RUSTFLAGS` values with unset states explicit. The receipt's `build.command` is the exact argv array passed to Cargo, including `--features` as one argument containing the space-separated feature list. `artifact.features` comes from Cargo's compiler-artifact record, not caller labels. The repository `.cargo/config.toml` currently sets only `CAPTRACK_AUTODUMP = "0"`; it does not select a target or rustflags. The same receipt records readable build-host observations (including raw THP, base-page, meminfo, swaps, pressure, uname, and cpuinfo facts) and fixed registered runner/study bounds. Missing observations remain explicitly unavailable/null/error rather than being filled with zero. This build-host receipt is evidence only for that CI build host and cannot establish the facts on a later measurement host or act as host admission. The uploaded binary is copied from the actual artifact path and rehashed; use the recorded artifact path/hash rather than assuming a `target/` location. The step does not launch a study, run the workload, or issue a measurement-host preflight/authorization. Parent integration must preflight the actual measurement host before any child, including 4 KiB base pages, available 2 MiB madvise THP, at least 8 GiB available memory, and no active swap or pressure; record unavailable/failed facts and treat a failed bound as INCONCLUSIVE. Neither the receipt nor these instructions authorize measurement.

The JSON runner timeout requests `SIGKILL` for its direct child at the configured deadline and retains `timed_out`, signal, raw output, status, and prior successful receipt rows. This does not kill or bound a process tree; the actual judge launches no children. OS scheduling delays and uninterruptible waits mean this is not an absolute wall-clock guarantee. Parent study policy still owns total-study and host-safety enforcement.
