Generated by `scripts/g1-widening-count.mjs` (derived numbers, none typed by hand; deterministic: no clock,
no machine paths — two consecutive generations are byte-identical). Question per plan §G1:
how many currently restricted-visibility items (`pub(crate)`, `pub(super)`, `pub(in …)`)
would have to become `pub` if the P2 crate layout of
`scripts/module-graph/layers.json` (§`boundaries`) were applied. This report is an INPUT
to the G1 decision; it decides nothing.

Source tree identity: content sha256 `9a9f9246e9cacfc57efae91788b21d1499ab9a1b13ff1ddf5ea8fc3fa8120179`, src tree (not a git worktree), 219 .rs file(s).

## Method

- Boundaries: `scripts/module-graph/layers.json` §`boundaries` (the P2 layout, plan §2).
  Conduit semantics (declared conduits `alloc_core`, `registry`): references THROUGH a
  conduit resolve to the DEFINING module, so a use counts against the defining module's
  future crate — reused from `scripts/module-graph/graph.mjs`, not reimplemented.
- An item is counted as widened-to-`pub` iff it is declared with restricted visibility
  (`pub(crate)`/`pub(super)`/`pub(in …)`) and is referenced from a module OUTSIDE its
  future crate, where a reference is a resolved `use` item or `crate::`/`super::`-style
  path reference (code, not comments; re-export `pub use` sites count, doc refs do not).
- Resolution is by symbol NAME at the resolved target module (the same name-matching
  `graph.mjs` §boundaryVisibility uses); module-graph resolves modules, not symbols.
- What had to be added beyond module-graph (its exports stop at module level):
  (a) attribution of `pub(crate) use` re-export DECLARATIONS inside the conduit mod.rs
  files (`src/alloc_core/mod.rs`, `src/registry/mod.rs`) — their primary module maps to
  no boundary, so `boundaryVisibility` skips them; each is attributed to the boundary of
  the module its re-export hop resolves to, via the conduit's own re-export edge sites;
  (b) the raw-pointer/`unsafe` safety signal, read from the declaration's signature text
  (lexer reused so file:line stay valid; a bounded signature scan over the lexed code, so
  strings/comments cannot forge a signal). No other parsing logic was duplicated.
- Private (no `pub`) declarations are NOT counted: today they are unreachable from any
  module outside their future crate except through a restricted re-export, which is
  counted as its own declaration. The count is therefore a conservative UNDERCOUNT.
- Unresolved path references are NOT attributed (data-quality signal,
  3 module-graph-unresolved refs in this tree; see
  `node scripts/module-graph.mjs` output). Unsure means not counted.

## Coverage and conservation asserts (fail loudly, never silently)

- every `src/` module maps to exactly one boundary of the variant, or is a declared
  conduit, or is the root module — otherwise the script exits nonzero;
- sum(per-boundary counts) === total unique items; every item key `file|line|name`
  appears exactly once across the report.
