# CF-2 — the route pin cache slot count becomes a setting (`perf(runtime)`, default unchanged)

**Class:** `perf(runtime)` — the always-on foreign-free path of
`src/registry/heap_core_xthread/route_pin_cache.rs` now reads the thread's slot mask (a word next to the `RefCell` borrow
flag) instead of using a compile-time constant; the default slot count (32) and every default behaviour are unchanged. New setting:
`LargeCacheConfig::route_pin_cache_slots(n)`. Tables and the summary CSV are generated by `scripts/cf2_report.mjs` from
`docs/perf/cf2/`; the prose cites them. Platform: Linux (WSL2) only.

## 0. Summary

1. **The setting.** `.route_pin_cache_slots(n)` on `LargeCacheConfig` (so also on `SeferAlloc::with_config`): the number of
   direct-mapped slots of the per-thread cache of route descriptors used by the foreign-free path. Rounded down to a power
   of two, clamped to `4..=64`, never panics; default 32 (the DZ-3 value). The array is sized for 64 slots; a per-thread
   mask selects the slots in use.
2. **Process-wide, first config wins.** Producer threads usually only free and never bind a heap
   (`current_for_dealloc` does not bind), so the value cannot travel with a heap. The first heap materialised with an explicit
   config publishes it (`Relaxed` `AtomicU8`, from `HeapCore::new_with_config`), each thread adopts it at its first insert
   into its cache, a different value from a later config is ignored (not counted by `config_conflicts_total`: that counter
   lives in `heap_registry`, whose sources are in the scope of many evidence rows).
3. **What a slot count buys (section A).** A direct-mapped cache keeps a cyclic or random order over `m` owner segments
   on the hit path only while the segments do not collide modulo the slot count. Measured hit rate of the cyclic order at
   m = 16 segments: {{HIT16C}}; at m = 32: {{HIT32C}}; at m = 64: {{HIT64C}}. Rule of thumb from the table: reliable up to
   about `slots / 2` owner segments (sparse segment addresses collide), perfect for a sequential order at every size.
4. **Time (section B).** ns per foreign free by slot count — cyclic order, m = 16 segments: {{NS16C}} (base {{NS16C_BASE}},
   mimalloc {{NS16C_MI}}); cyclic, m = 32: {{NS32C}} (base {{NS32C_BASE}}, mimalloc {{NS32C_MI}}); random, m = 32: {{NS32R}}
   (base {{NS32R_BASE}}, mimalloc {{NS32R_MI}}); cyclic, m = 64: {{NS64C}} (base {{NS64C_BASE}}, mimalloc {{NS64C_MI}}) — no
   slot count up to 64 serves 64 owner segments in a cyclic order.
5. **Cost of the setting (section C).** On the sequential hit path the 32-slot arm differs from base by {{SEQ32}}
   ({{SEQ4}} at 4 slots, {{SEQ64}} at 64) — not measurable in instructions; time of the sequential order against base:
   {{SEQ_NS}} over every arm and m (noise level of the machine), {{SEQ_NS32}} for the default arm. A first version that wrapped
   the sweep cursor with a run-time modulus was 1.2–1.5 times slower than base in the miss regime and was fixed (section E).
6. **Too few slots are expensive, not neutral.** In the cells where the default hits (hit rate >= 0.99) and an arm does
   not reach the segments (hit rate 0.00), a free costs {{MISS_IR}} extra Ir and {{MISS_NS}} times the time of the default
   (section B, C); a slot count below the producer's owner segments is worse than the default, never better.
7. **Default stays 32** (section 3). Retention is the price of more slots (section D).

## 1. What was measured

- **Identity.** Base: `main` @ `3aab9681` (32 slots, no mask, `SeferAlloc::new()`). Change: {{TREE_ID}}, recorded before the run in `docs/perf/cf2/ident.txt`
  with the binary hashes, rustc and CPU. Arms: the change built with `PC_SLOTS` = 4, 8, 16, 32, 64 (the probe's
  `SeferAlloc::with_config(LargeCacheConfig::new().route_pin_cache_slots(PC_SLOTS))`), time builds with `production`, counting
  builds with `production bench-internals internals alloc-stats`; mimalloc through the same probe (`pincycle ... mi`).
  rustc 1.98.1, Linux 6.18 (WSL2), i7-11800H, shared with other sessions.
- **Entry point.** `SeferAlloc` as the `#[global_allocator]` of the probe process; the producer frees through
  `GlobalAlloc::dealloc` on another thread (the real foreign-free path `HeapCore::publish_foreign`); mimalloc through the
  same probe. The setting reaches the producer through the owner's bind, exactly as in a real program.
- **Config evidence per arm (R26-4).** Every counting run prints `slots_req` (the build-time request) and `slots_res`
  (`RoutePin::dbg_route_pin_cache_slots()` read on the producer thread after its frees); the script asserts
  `slots_req == slots_res == arm` for every counting run. One process per run (subprocess isolation; the registry is fresh).
  The conflict counter is not involved: the setting has none, and every process materialises one config.
- **Mechanism evidence (R30-8).** The hit rate itself is the activation oracle: hits + misses = frees is asserted per run,
  and the 32-slot arm must reproduce base's hit rate within 0.01 in every cell (asserted).
- **Shape.** The owner allocates `(m + 2) x 4096` blocks of 1 KiB, `m` segments of 2048 freed blocks each are chosen; one
  producer thread frees them in order `seq` (segment by segment), `cyclic` (one block per segment in turn) or `random`
  (fixed seed). Time per free = producer wall time / (m x 2048).
- **Statistics.** Time: medians of 9 interleaved processes per arm and cell. Hit rate: counting build, every cell twice,
  asserted equal. Extra Ir per free: callgrind program totals, `(total(arm) - total(base)) / (m x 2048)` (the set-up is
  identical across arms).
