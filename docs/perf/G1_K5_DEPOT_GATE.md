# G1-K5 — склад магазинов для классов 240–1024 Б: гейт (perf(runtime))

Статус: **GO** по предрегистрации (`docs/perf/g1_k5/G1_K5_PREREG.md`,
зафиксирована до прогона, коммит `319517f7` на измерительной ветке).
Код под замером:
- абляция — ветка `g1-k5-meas`@`319517f7` (main `37780bc7` + K1 `69777124` +
  набор абляции из `51eda7b1` + патч `g1_k5/patches/k5_depot_mid_classes.patch`);
- против mimalloc — дерево `g1-k5`: head `9ba7a532` + незакоммиченный diff
  sha256 `7a05c805…e515` (то же дерево закоммичено после прогона как
  `e4f76527`; патч абляции побайтно совпадает с этим diff).

Основа — K1 (`docs/perf/G1_K1_DRAIN_GATE.md`, PR #125). Кандидат найден в
`docs/perf/G1_IDEAS.md`: перенос блоков между классами 256/1024 шёл через
список (flush + drain ≈ 22 % инструкций на mixed 256/1024), потому что склад
(B1-D, пункт 117) покрывал только классы до 192 Б.

## Что изменено

`src/registry/heap_core/state/depot.rs`: склад покрывает все классы до
1024 Б.

- Классы 0..7 (16–192 Б) — прежние `DEPOT_K = [8,8,8,8,8,8,7,1]`.
- Классы 8..17 (240, 256, 304, 384, 480, 512, 608, 768, 960, 1024 Б) —
  K = 2.
- Блоков на складе не больше 241 408 Б на поток (было 64 256 Б);
  `DEPOT_BUDGET_BYTES` 64 КиБ → 240 КиБ, оба числа закреплены `const`-assert.
- Массивы указателей — 18 КиБ на слот реестра (было 8 КиБ; виртуальная
  память, страницы трогаются только при парковке).

Алгоритм тот же: парковка полного магазина и перезагрузка, теперь доступные
этим классам. Склад опустошается при выходе потока, переработке слота и
`trim_current_thread`, как раньше. Почему K = 2: развёртка на пробнике
(`G1_K5_PREREG.md`, ветка `g1-k5-sweep`) — K = 1 даёт половину потолка
(циклы mixed 256/1024 0.863×), K = 2 выходит на потолок (0.724×; K = 4 —
0.739×, K = 8 — 0.744×; инструкции 0.758× при K ≥ 2).

## Тесты

`tests/heap_core_depot.rs`:
- `depot_mid_classes_budget_and_caps` — классы 8..17 и их размеры, полный
  магазин (`FREE_PARK_CAP` = 16), сумма 241 408 Б в бюджете;
- `depot_mid_class_parks_two_and_reloads` — для 256 и 1024 Б паркуются ровно
  два магазина, следующее переполнение идёт в flush, перезагрузки отдают
  только освобождённые тестом блоки без дублей; класс 1200 Б не паркуется.

Контрфактуально: на складе K1 (только классы 0..7) новый тест падает
(ИЗМЕРЕНО локально). Полная тестовая строка CI `production alloc-stats
bench-internals internals` зелёная локально.

## Что меряется

Как в K1: реальный `#[global_allocator]` (`SeferAlloc`, `--features
production`, release, RUSTFLAGS выравнивания), Windows 10, i7-11800H,
rustc 1.97.0; абляция J1′ v2 (20 процессов × 2000 блоков, за вычетом null),
главный судья против mimalloc (`--reps 20 --blocks 2000`), callgrind в WSL
на пробнике (callgrind K5 снят на `g1-k5-sweep`@`760cb17e` — тот же K = 2,
отличие только в константе бюджета).

Оракул активации: `oracle_mismatches=0` во всех процессах прогона против
mimalloc. Путь активен: на mixed 256/1024 self Ir переноса
(`flush_class_internal` + `try_drain_freelist_batch`) падает с 9 937 224 до
0, появляется склад (`depot_park` / `depot_reload` 522 516 Ir).

  1.493×). Столбец «после против до» — ОЦЕНКА, прогоны разные.

## Память

Блоков на складе — не больше 241 408 Б на поток (было 64 256 Б). RSS склад
сам по себе не добавляет: паркованные блоки остаются в своих сегментах. Он
может задержать возврат опустевшего сегмента, пока магазин лежит на складе;
верхняя граница такой задержки — эти 241 408 Б. RSS в этом гейте не мерился
(как и в гейте B1).
