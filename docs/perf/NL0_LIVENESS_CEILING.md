# NL-0 — ceiling of dropping the per-block liveness state byte (`bench`, measurement only)

Measurement-only: no shipping or opt-in code changed by this report. The prototypes
below are throwaway commits on the branch `g1-nl0` and are never merged.

## 1. Question

Owner decision 2026-11-03: the liveness check (the LIVE/MAG/FREE state byte per 16 B
granule, compared on every own-thread small free) guards only against misuse of the
`GlobalAlloc` contract (double free, foreign or interior pointer, wrong layout). Safe
code cannot cause these: every free path is an `unsafe fn` and the crate exports no
C-ABI `free`. The check becomes an opt-in, **default off**, documented as needed only
for unsafe code. This report answers the first half of NL-0: which readers exist and
what the ceiling of removing them is.

## 2. Audit: who reads the state byte

Method: read every `state_byte().read` / `read_granule` site in `src/` (grep, then each
site by hand).

| site | what it does with the byte | needed for correctness of valid (safe) programs? |
|---|---|---|
| `registry/heap_core/free/dealloc_fast.rs` (lane, second-chance) | exact compare with the LIVE tag, else `lane_miss` | no — reject-only |
| `registry/heap_core/free/dealloc_own_base.rs` `small_free_guard` | exact compare, reject reasons | no — reject-only |
| `alloc_core/small/alloc_core_small/dealloc.rs` | exact compare, no-op on mismatch | no — reject-only |
| `alloc_core/small/alloc_core_small_magazine.rs` (flush, guard 2) | skips blocks that are not issued of this class | no — reject-only |
| `alloc_core/small/alloc_core_small_reclaim.rs` | refuses a sidecar record whose block is already FREE or MAG | no for valid programs: a remote-pending block stays LIVE until the owner reclaims it, so FREE/MAG here means a duplicate record, i.e. a double free |
| `alloc_core/small/alloc_core_small/alloc_core_small_impl.rs` 369 | free-list head validation, `hardened` only | no — `hardened` check |
| `alloc_core_small_impl.rs` 444, `registry/heap_core/alloc/hot.rs` 89 | `debug_assert` of the prior value | no — debug only |
| `alloc_core_small_diag.rs` | diagnostics | no |

Reading: on release paths the byte is read only to reject. No decision of the allocator
for a valid program depends on it. The writes (carve/issue, MAG on park, LIVE on
issue, FREE on bin) exist to keep the byte accurate for those readers. Open point for
NL-0 part 2: whether any other consumer (segment-empty detection, decommit, reclaim
credits) relies on the invariants И2–И5 rather than on the byte itself; the live-count
based empty detection (`Phase 35 (M6)`) does not read the byte.

## 3. Ceiling measurement

Entry point: `b4_pmu_probe bulk sefer 1024 <size> <passes>` — bulk alloc of 1024 blocks
then free of 1024 through the `SeferAlloc` global-allocator shims, i.e. the own-thread
small alloc/free lanes of `HeapCore` that ship at `#[global_allocator]` level. Single
thread: the cross-thread, reclaim and flush paths are not exercised.

Source identity (commits on branch `g1-nl0`, base `main` @ `908f2aba`):

- base: `908f2aba` (no change);
- A: `275ec9bb` — both free lanes without the `read_granule != tag.byte()` compare;
- B: `d0742881` — A, plus no `write_granule(MAG)` in the free lanes and no
  `set_state(LIVE)` on the alloc hit/refill lanes.

Binary sha256 and build flags: `docs/perf/nl0/identity.txt`,
`docs/perf/nl0/nl0.sh` (release, `--features production`,
`-C llvm-args=-align-all-functions=6 -C llvm-args=-align-all-nofallthru-blocks=5`,
Linux x86_64 under WSL2). Callgrind: 400 passes, `PROGRAM TOTALS`. Time/cycles:
`perf stat` over 4000 passes, 5 runs per tree and size, median; `ns/op` is the probe's
own printed figure (`cycles:u` from `perf stat`).

Path-activation oracle: the prototype changes are on the executed lanes by construction
— the Ir drop (−2.6 % for A, −9.3 % for B, identical at 16 B and 64 B) is the removed
instruction count per pass, and the 5 runs per cell are in `docs/perf/nl0/run.*`.

## 4. Reading

- The ceiling matches the D16-R line attribution (≈ −4.8 M of 51.9 M Ir, ≈ 9 %): B is
  −9.26 % Ir and −7.9 % (16 B) / −9.9 % (64 B) time on this probe. A alone (the
  compare) is −2.6 % Ir and −1.4 … −3.8 % time; most of the gain is the writes.
- Against mimalloc on the same probe shape (`docs/perf/d16e`, earlier run: sefer 2.937
  vs mi 2.487 ns/op = 1.18× slower at 16 B, 4000 passes; this report's base ran at
  3.121 ns/op on a different day, so the gap is quoted per run, not mixed): B's −7.9 %
  would take that 1.18× to roughly 1.09× at 16 B, i.e. about half of the gap; it does
  not reach parity at 16 B.
- This is a ceiling, not a design: the prototype leaves the writes in every cold path
  (carve, flush, bin), so the byte goes stale on the hot lanes. A real unchecked mode
  needs the cold paths and the reclaim guard consistent with a state byte that is not
  maintained (see §2 and task NL-1), and an equal-or-stronger verification of the
  structural invariants (task NL-3) before the default is changed.
