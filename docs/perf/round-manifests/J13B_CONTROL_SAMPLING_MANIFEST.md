## Declared limitations and conservative direction

- Remote owner-reclaim controls are consumed as UNKNOWN/invalidated: a foreign moving realloc may copy the payload without owner-header invalidation, so the owner-only token can be stale; the mapping is not sampled (no foreign-header protocol or producer mutation was added).
- Control windows are seeded per request group (`group token XOR OBSERVATION_SEED`), not per request, so same-group same-geometry controls reuse window positions (correlation, bounded).
- A sliding 8-window can legally contain 2 controls across a cohort boundary (accepted amendment semantics).
- Reason-separated invalidation accounting: invalidated remote-reclaim is recorded in telemetry field 3, invalidated realloc in field 4, and premise failures are counted separately, so downstream #49 can quantify invalidation/lifetime bias. Realloc consumption is token-derived and exactly-once (now including the successful registry OOM-shrink fallback, which consumes a pending token exactly once before the size setter clears it); cache reuse cannot double-count a realloc invalidation because the token is already consumed at the depositing free.
- Fresh-premise order proof: the fresh OS reservation gets `MADV_NOHUGEPAGE` applied BEFORE the header write, terminal-word init and payload use, so no huge backing can pre-exist when the policy is applied. A failed premise yields an UNKNOWN token that is never sampled. The fresh-premise oracle `tests/j13b_control_premise_fresh.rs` asserts a never-touched mapping reads `resident == 0`.
- The fifteen control test binaries now include installed-GlobalAlloc activation (`tests/j13b_control_installed_global.rs`), remote-UNKNOWN consumption (`tests/j13b_control_remote_unknown.rs`), moving-realloc invalidate/preserve (`tests/j13b_control_moving_realloc.rs`), OOM-shrink fallback accounting (`tests/j13b_control_oom_shrink_invalidation.rs`), capture-bounds rejection (`tests/j13b_control_ticket_log_capture_bounds.rs`), the fresh premise (`tests/j13b_control_premise_fresh.rs`), concurrent competing-ordinal coverage (`tests/j13b_control_concurrent_ordinal.rs`) and reserved-capacity invalidation (`tests/j13b_control_reserved_capacity_invalidation.rs`); six binaries (`tests/j13b_control_premise_recovery.rs`, `tests/j13b_control_sampler_recovery.rs`, `tests/j13b_control_concurrent_ordinal.rs`, `tests/j13b_control_reserved_capacity_invalidation.rs`, `tests/j13b_control_oom_shrink_invalidation.rs`, `tests/j13b_control_ticket_log_capture_bounds.rs`) have dedicated check-matrix rows in `scripts/check-matrix.mjs`.
- Bounded alignment-slack owner geometry is accepted: the pure validator (production binding, oracle `tests/j13b_control_owner_geometry.rs` with exact-variant rejections) accepts a reservation root strictly below the SEGMENT-aligned usable base as ordinary-backend geometry; pointer equality between root and base is NOT required. Native slack presence is address-luck, which is why the oracle is pure.
- VM no-THP evidence is layered: layer 1 is the kernel VMA policy record (`/proc/self/smaps` `VmFlags: nh`), REQUIRED on native Linux/Android (an unreadable smaps is a loud failure, never a silent pass); layer 2 is the mincore granularity oracle, which proves base-page fault granularity under any backing but cannot alone distinguish the no-THP operation from a no-op on an already-base-page host; unsupported backends return typed errors. HugeTLB rejection coverage is environmental (proves rejection only when a real grant is obtained).
- Concurrent competing-ordinal coverage: `tests/j13b_control_concurrent_ordinal.rs` drives 64 competing eligible 16 MiB allocations through the installed GlobalAlloc on 4 barrier-synchronized threads; the oracle reads the runtime's actually consumed tickets and decisions through the bounded bench-internals ticket log (`dbg_thp_control_ticket_log`, reset per scenario) — the captured `(ordinal, decision)` records must be exactly the consumed window `[before, after)` with pairwise-distinct tickets, so a lost, duplicated, or folded ticket (e.g. a selector fed the fetch_add return divided by the cohort length, which repeats ordinals 0..7 across cohorts while leaving the counter delta, the aggregate selection count, and any independent pure replay unchanged) turns the captured multiset red; every captured decision must equal the pure `dbg_thp_control_decision_at` passthrough evaluated at that captured ticket; the per-cohort census over the actual captured decisions holds exactly one control per complete aligned cohort; and the true-decision count closes against the telemetry selections (g2[0] == 8). Aggregate telemetry alone still proves neither property. A sliding 8-window may legally hold 2 controls and is never asserted per-window. Pure selector tests and sequential allocations do NOT cover the competing-RMW property.
- Unknown-token fail-closed accounting is source-verified only: a native malformed-token injection oracle would require a token setter on a raw header, which the task rules forbid as a safe raw-pointer metadata mutation API; this is an explicit limitation, not a silently dropped gap.
- The owner-free sampler adopts the reservation contract-faithfully (usable base/span, SEGMENT creation alignment, untouched root pair) per `from_raw_parts`' documented base-vs-reservation distinction.
- Reserved-capacity boundary: reserved-capacity growth captures the control token BEFORE the helper (whose span setter clears it); success accounts exactly once, and failure preserves the token so the moving leg accounts exactly once (no double count). Dedicated activating row: `test-j13b-control-reserved-capacity-invalidation` (production large-reserved-capacity internals bench-internals).
- Remote consumption boundary: remote telemetry consumption is asserted only after the explicit guaranteed owner drain (`dbg_trim_current_thread`), with an exactly-once second-trim assertion; before the drain only the foreign-publication guarantees are asserted (telemetry field 3 is deliberately unconstrained).
- Failed-premise-through-realloc discrimination: a failed-premise token (9..=14) consumed by a moving realloc is counted as a premise failure exactly once — never as realloc-invalidation, never double-counted (`tests/j13b_control_premise_recovery.rs`).
- Eligibility: Linux/Android, `alloc-decommit`, non-`numa-aware`, fresh Large path with `align < SEGMENT` only. Cache reuse invalidation, moving/in-place realloc invalidation, and the teardown-live skip are wired; no learner exists and no estimator consumes the recorded counts.
