# B1 — склад магазинов в production: гейт DP-5 (perf(runtime))

Статус: **GO** по предрегистрации (`docs/design/2026-10-26-depot-design.md`,
раздел «Порог приёмки»), со второй попытки. Первая попытка — NO-GO, она
приведена полностью. Код под замером — ветка `b4-depot`: попытка 1 —
`36036687`, попытка 2 — `d0bec415` (base `cb6371e5` = main после PR #99).

## Что меряется

Реальный `#[global_allocator]` (`SeferAlloc`, `--features production`,
release, RUSTFLAGS выравнивания `-C llvm-args=-align-all-functions=6
-C llvm-args=-align-all-nofallthru-blocks=5`), Windows 10, i7-11800H.

1. **Склад против текущего sefer** — абляционный протокол ветки `b4-ablate`
   (`scripts/b4_ablate_run.mjs`, там же). В одном процессе две копии sefer:
   A — без патча, B — с патчем склада (`b1_depot_gate/dp5_depot*.patch` =
   `git diff cb6371e5 <sha> -- src/`). Порции A и B чередуются ABBA/BAAB
   по 2000 блоков, внутри процесса берётся медиана `ln(t_B/t_A)`, затем
   медиана по 20 процессам с разными order seeds; CI — bootstrap по
   процессам. Шум машины общий у A и B внутри каждой четвёрки порций.
   Тот же прогон делается для null-копии (патч пуст); эффект = медиана
   варианта − медиана null (убирает постоянный перекос слотов A/B).
2. **Склад против mimalloc** — main-судья J1′ v2
   (`scripts/b4_interleave_run.mjs --reps 20 --blocks 2000`), A = sefer со
   складом (`d0bec415`), B = mimalloc; сравнение с фазой 2 v2 до склада
   (`docs/perf/B4_INTERLEAVE_JUDGE_rep_summary.csv`).

Механизм (oracle активации): в обоих протоколах судья проверяет точное
число вызовов шима каждого плеча и нули чужих вызовов; то, что склад
действительно паркует и забирает, видно по эффекту на bulk64/churn64 и
закреплено тестами `tests/heap_core_depot.rs` и Miri-свидетелем
`tests/miri_depot_cycle.rs` (оба проверяют `dbg_depot_len > 0`).

## Попытка 1 → попытка 2

Попытка 1 провалила порог 3 на bulk16k (медленнее в 1.031×, CI
+2.67…+3.58 %; у прототипа S2 было +0.83 %). Причина (подтверждена
попыткой 2): на bulk16k склад почти всегда полон на free и пуст на
промахе, и каждое переполнение / промах платило вызов холодной функции,
которая возвращала `false` после перехода по указателю в `HeapSlot`
(B−A +1.07 тика/вызов против +0.35 у прототипа). Исправление `d0bec415`:
счётчик запаркованных магазинов — в байте выравнивания `PerClass::parked`
(смещение закреплено, размер не меняется), вызовы склада гейтятся на месте.
Пороги и протокол между попытками не менялись; данные попытки 2 — новые.

Чтение:

- Пороги 1–3 выполнены на попытке 2: bulk64 быстрее в 1.778×, churn64 — в
  1.481× (оба ≥ 1.25×, верх CI < 0); pair16, pair64, larson не медленнее
  (быстрее в 1.004× / 1.003× / 1.099×); ни одно ядро не медленнее.
- «null точен = no» (churn64, churn1024, vec512, larson): полуширина CI
  null-копии больше 1 % — шум машины в этом прогоне. CI эффекта включает
  эту неопределённость (bootstrap обоих наборов процессов); вердикт по
  порогам на этих ядрах с запасом (худший край: churn64 −33.93 % при
  пороге −20 %, larson −6.98 % при пороге +1 %, vec512 +1.08 % и
  churn1024 +0.62 % при пороге +2 %).
- Против mimalloc (ОЦЕНКА по двум прогонам в разное время, каждый — пары
  в одном шуме): разрыв сократился на всех churn/bulk-ядрах (bulk64
  0.445 → 0.778, churn64 0.555 → 0.748, churn16 0.442 → 0.570), но
  mimalloc по-прежнему быстрее на 9 из 11 ядер; sefer быстрее на pair_rt
  (1.400) и vec512 (1.308, в этом прогоне не допущено по A/A).

## Память

Блоки на складе — не больше 64 256 Б на поток (`DEPOT_K = [8,8,8,8,8,8,7,1]`,
`const`-assert ≤ 64 КиБ). Массивы указателей — 8 КиБ на слот реестра в
`HeapSlot` (чанк из 64 слотов: +512 КиБ виртуальной памяти, страницы
трогаются только при парковке). Склад опустошается при выходе потока,
переработке слота и `trim_current_thread`. RSS в этом гейте не мерился.

## Идентичность и сырьё

| Прогон | Код | sha256 патча | Сырьё |
|---|---|---|---|
| попытка 1, против sefer | `b4-depot`@36036687 | `eead166d57cc…` | 120 файлов, `b1_depot_gate/attempt1/MANIFEST.txt` |
| попытка 2, против sefer | `b4-depot`@d0bec415 | `e7cea62bb8f3…` | 120 файлов, `b1_depot_gate/attempt2/MANIFEST.txt` |
| против mimalloc | `b4-depot`@d0bec415 | — (коммит) | 60 файлов, `b1_depot_gate/vs_mimalloc/MANIFEST.txt` |

Сырые JSONL (по ~4.4 МиБ, > 2 МиБ) в git не входят: манифесты содержат
sha256 и размер каждого файла. Абляционный runner, генератор разности с
null и скрипты прогона — ветка `b4-ablate` (origin); генератор таблицы
mimalloc — `scripts/b4_interleave_rep_table.mjs`; сводка —
`docs/perf/B1_DEPOT_PRODUCTION_GATE_summary.csv`.

Команды:

```text
# против sefer (ветка b4-ablate, патч в docs/perf/b4_ablate/patches/)
RUSTFLAGS="<выравнивание>" node scripts/b4_ablate_run.mjs --out-dir <dir> --blocks 2000 --reps 20 \
  --kernels pair16,pair64,pair_rt,bulk64,bulk16k,churn16,churn64,churn256,churn1024,vec512,larson \
  --variants dp5_depot2 --summary <csv> --no-null-gate
node scripts/b4_ablate_vs_null.mjs --dir <dir> --variant dp5_depot2 --reps 20 --kernels <те же> --csv <csv>
# против mimalloc (эта ветка)
RUSTFLAGS="<выравнивание>" node scripts/b4_interleave_run.mjs --reps 20 --blocks 2000 --out-prefix <dir>/j
node scripts/b4_interleave_rep_table.mjs --dir <dir> --reps 20 --kernels <те же> --csv <csv>
# отчёт
node scripts/b1_depot_gate_report.mjs --csv docs/perf/B1_DEPOT_PRODUCTION_GATE_summary.csv
```
