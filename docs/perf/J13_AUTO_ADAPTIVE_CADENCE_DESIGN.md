> **Implementation note (2026-11-12).** The runtime slices (§15 S1–S3 without the Kani harness) are implemented as `perf(opt-in)`.
> Deviations from this text: the learner method is `ThpLearningCell::try_observe_with_prior` returning the estimate of the replaced
> predecessor pair (`Option<LargeThpShare>`); the runtime applies `LargeThpCadence::agrees` itself, so the learning cell stays free of
> cadence policy and its Loom/forced-CAS mounts are unchanged (P27 rules re-pointed at the new method). The pure layer is
> `state/large_thp_cadence.rs`, the cell `state/thp_cadence_cell.rs`. No `ghost_assert!` ids and no Kani harness were added. The
> parallel level log and the diagnostics are bench-internals only; pins: `dbg_thp_cadence_pin`. The existing judge/training executors
> pin level 0 and keep measuring the fixed selector. §8 R1 (settle-based completion, schema v5), the C1–C4 measurement and the
> prereg amendments (§15 S4 beyond README/CHANGELOG) are NOT implemented: paused full-judge backlog. Everything below is the
> original design text.

Status: **design only**. Nothing here was built, tested, run or measured. Every number marked
"model" below comes from a throwaway, uncommitted hand-run of the Q31 estimator arithmetic (it is
neither a measurement nor a result) and must be regenerated by a checked, cargo-free script before
any report cites it (see §13.4). Auto stays opt-in; the THP default stays `Off`; no public knob is
added. Eventual implementation commits are `perf(opt-in)` (Auto code path changed, user must opt in),
the unwired pure foundation is `feat`, tests are `test`, doc amendments `docs(config)`.

Owner requirement (task #115, docs answer 2026-11-11): before any Auto measurement the control
cadence must make a stable estimate sampled rarely — the share of control blocks falls as
observations agree with the current estimate and rises again when they disagree. One control in
eight forever is not acceptable as a candidate default.

Arithmetic motivation (hypothesis, not a result): let `c` be the cost of a dense block under
`Always` relative to `Off` (hypothesis `c = 0.13`) and let controls cost `1.0` of `Off` (no THP).
With control rate `r` on steadily dense work, `Auto/Off = c + (1 - c) * r` and
`Auto/Always = 1 + (1 - c) * r / c`. At `r = 1/8` this is 0.2388 of `Off` (1.84x `Always`); at
`r = 1/256` it is 0.1334 of `Off` (1.026x `Always`). The J13b prereg already declares an
equal-budget policy-overhead ceiling of 1.20 for `a` vs `base`; fixed 1/8 would violate it by
construction under this hypothesis.

Facts that shape the design:

1. The cohort is global across request groups (README "Admission limits": "Cohorts are global across
   eligible sizes, not per group"). Per-group control counts are therefore only statistical for
   interleaved groups and exact for homogeneous streams. This design keeps that and does not change
   the ordinal protocol.
2. `src/**` directory limit is 7 entries. `large_thp/` (7), `large_thp_observation/` (7) and
   `large_thp_runtime/` (7) are full; `large_thp_runtime/state/` has 2 files. New files therefore go
   to `large_thp_runtime/state/`, wired by `#[path]` lines in the existing `mod.rs` (the pattern
   `thp_learning_cell`/`thp_advice_outcome` already use). No directory gains an entry; no baseline
   row is touched.
3. The per-group learner word cannot take another field: both Q31 halves are full width. The cadence
   state is a separate word. No segment header, `ThpTuple`, `PerClass` or tuple codec field changes
   (header stays 144 B; the observation token still carries only the group).

## 2. Decision summary

| Question | Decision |
|---|---|
| Mechanism | **Thinning of the existing selector's candidates by a per-group level `l` in `0..=5`.** A control is issued iff `decision_at(seed, ordinal)` (unchanged candidate, 1/8) AND the candidate's cohort is the single *live* cohort of its aligned super-cohort of `2^l` cohorts. Rate = `1/(8 * 2^l)`: 1/8 ... 1/256. |
| Backward identity | At `l = 0` the final decision equals `decision_at` bit for bit (no mix call). Final controls are always a subset of today's controls. |
| State | One new `AtomicU64` per group (`CADENCE[6]`, 48 B process static): a saturating agreement run `0..=20`; `l = min(run / 4, 5)`. |
| Signal | Per valid observation, **agreement = `abs(o - est_before) <= 1/8`** where `est_before = estimate()` of the exact predecessor pair of the winning learner CAS (coherent, no second load). Agree: run + 1 (saturating at 20). Disagree: run = 0 (snap to the ceiling rate). |
| Ceiling | 1/8 (`l = 0`) — the preregistered `R`; never exceeded. |
| Floor | 1/256 (`l = 5`) — see §6. |
| Atomics | agree: <= 8 CAS attempts (Relaxed), drop is the safe direction; disagree: ONE wait-free `fetch_and` (cannot be dropped); level read: one Relaxed load, only for candidates. |
| New public surface | none. bench-internals doc-hidden diagnostics + one pin hook only. |
| Layout | none (§9). |
| Ordinal | unchanged (P26 I1). Per-group ordinals rejected (§14). |

## 3. Pure layer (`state/large_thp_cadence.rs`, export `LargeThpCadence`)

One file, one export (`pub(crate) struct LargeThpCadence;` namespace of `const`/`const fn`), safe code,
no atomics. It sits in `state/` only because the sibling pure directories are full (fact 2).

```text
LEVEL_MAX      = 5          // 6 levels
RUNS_PER_LEVEL = 4
RUN_MAX        = 20         // LEVEL_MAX * RUNS_PER_LEVEL
TOLERANCE_RAW  = SCALE / 8  // 2^28, Q31 -> 0.125, inclusive
THIN_DOMAIN    = <fixed 64-bit constant, domain-separates thinning from decision_at>

level_of(run)            = min(run, RUN_MAX) / RUNS_PER_LEVEL            // total over u32/u64
agrees(est, obs)         = abs_diff(est.raw(), obs.raw()) <= TOLERANCE_RAW
next_run(run, agreed)    = if agreed { min(run + 1, RUN_MAX) } else { 0 }
live(seed, ordinal, l)   = l == 0 ||
                           (cohort & mask) == (bounded_mix(seed ^ THIN_DOMAIN.wrapping_add(l), cohort >> l) & mask)
                           where cohort = ordinal / 8, mask = (1 << l) - 1, l clamped to LEVEL_MAX
select(seed, ordinal, l) = LargeThpControlSelector::decision_at(seed, ordinal) && live(seed, ordinal, l)
```

`select` is the test oracle (pure, const-friendly, total over the whole `u64` ordinal domain
including the wrap). The runtime evaluates the two conjuncts separately so the level is loaded only
for the 1/8 of requests that are candidates (§5).

Properties (all pure, all testable without a loop to 2^64):

* **H0 identity.** `select(seed, o, 0) == decision_at(seed, o)` for every `(seed, o)`.
* **H1 subset / hard bound.** `select(seed, o, l) => decision_at(seed, o)` for every `l`, so every
  *existing* guarantee survives: at most one control per aligned cohort of 8, under any level
  schedule (the level may change between any two requests).
* **H2 exact rate at constant level.** For constant `l`, each aligned window of `8 * 2^l` ordinals
  (a super-cohort) contains exactly one control: it has `2^l` cohorts, each with exactly one
  candidate, and exactly one cohort is live (the one whose low `l` bits equal the mixed index).
* **H3 bounded gap.** At constant `l` two consecutive controls are at most `2 * 8 * 2^l - 1`
  ordinals apart (511 at the floor; mean 256). This bounds detection latency after a workload change
  for a homogeneous stream. There is no unbounded blind interval, unlike a pure Bernoulli thinning.
* **H4 decorrelation.** The live index and the in-cohort position come from different mixes
  (`seed` vs `seed ^ THIN_DOMAIN + l`); neither is periodic in the ordinal. Same non-guarantee as
  the selector: bounded decorrelation, not representativeness.
* **H5 wrap.** `2^61` cohorts is divisible by `2^l` for `l <= 5`, so super-cohort alignment is
  clean across the `u64` wrap.

Stratification note: thinning at the *cohort* level (not per request) keeps H1 and gives H2/H3; a
per-request Bernoulli draw would break "exactly one per window" and the gap bound.

## 4. State: `ThpCadenceCell` (`state/thp_cadence_cell.rs`, export `ThpCadenceCell`)

```text
static CADENCE: [ThpCadenceCell; 6]     // process-wide, indexed like LEARNERS by group_index(request_size)
struct ThpCadenceCell { state: AtomicU64 }   // AtomicU64 via `super::` so loom/model binds (same as the learning cell)
```

Encoding of `state` (zero-initialised static; no `new()` needed beyond tests):

```text
bits 0..=4   run            0..=20 (decode clamps >20 to 20)
bits 5..=63  reserved, must stay 0 in production
             [bench-internals only] bit 5 PIN_VALID, bits 6..=8 PIN_LEVEL (0..=5)
INITIAL = 0   -> run 0 -> level 0 -> today's 1/8 (a never-observed group behaves exactly as today)
```

Operations (all `Ordering::Relaxed`; the word publishes no external payload, the level is a rate
hint, a stale read is legal and only ever delays a rate change):

| Op | Atomic sites | Bound |
|---|---|---|
| `level(&self) -> u32` | one `load` | wait-free. `[bench-internals]` honours the pin bits; production decode is `level_of(run)` only |
| `note_agree(&self) -> bool` | `load`, then `compare_exchange(current, current + 1, Relaxed, Relaxed)` | `MAX_ATTEMPTS = 8`, same shape as `ThpLearningCell::try_observe`; if `run == RUN_MAX` return without any RMW (steady state = one load per observation); exhaustion returns `false` = agreement dropped |
| `note_disagree(&self) -> u32` | one `fetch_and(!RUN_MASK)` | **wait-free, unconditional** — a disagreement can never be lost to contention. Returns the previous run for diagnostics |
| `run(&self) -> u32` | one `load` | telemetry |
| `[bench-internals] pin(&self, Option<u32>)` | `fetch_or` / `fetch_and` on the pin bits | diagnostic; never called in production |

Invariants (become P29 I1-I5, §11):

* **C1** one word per group; the level is derived from a single load, never from two.
* **C2** `run <= 20` at every observable instant: increments are CAS-guarded below `RUN_MAX`,
  resets only clear bits.
* **C3** agreement updates are at most 8 attempts; losing one only keeps the rate temporarily higher.
* **C4** the rise on disagreement is never lost: it is a wait-free RMW, not a bounded CAS. (A bounded
  CAS reset is the natural mutant and must be rejected by the catalog and a forced-CAS-failure test.)
* **C5** ABA is harmless: every transition is a pure function of the word's value, so a CAS that
  succeeds after an intervening reset-and-reclimb is a legal serialization.
* **C6** Relaxed publishes nothing and orders nothing; correctness of memory never depends on the
  level (it only selects *which* fresh requests lose THP advice for measurement).

Cross-word note: the learner CAS and the cadence update are two separate atomics. They are not
linearized together. Two concurrent observers may apply their cadence updates in the opposite order
to their estimator updates (one agree and one disagree: final run `0` or `1`, never `>1`). That is a
heuristic-rate perturbation bounded to one step, not a correctness property; it is stated, tested in
loom (§12.2), and the two words are never required to be mutually consistent.

## 5. Wiring (runtime), in order of execution

### 5.1 Request time: `ThpRuntime::next_control`

```text
ordinal   = CONTROL_ORDINAL.fetch_add(1, Relaxed)                 // unchanged, one RMW (P26 I1)
candidate = LargeThpControlSelector::decision_at(CONTROL_SEED, ordinal)   // unchanged call/args (R3 rule intact)
if candidate:
    level    = CADENCE[group_index(request_size)].level()          // one Relaxed load, ONLY on the 1/8 path
    selected = LargeThpCadence::live(CONTROL_SEED, ordinal, level)
else: selected = false
if selected { note_group_counter(&CONTROL_SELECTIONS, group, 1) }   // unchanged
[bench-internals] cadence diagnostics + record_control_ticket(ordinal, selected, level_or_NO_LEVEL)
return (selected, ordinal)                                          // signature unchanged
```

`advise_fresh_large.rs` is **unchanged**: it still calls `next_control(request_size)` and reacts to
`selected`. Off/Always never reach this code (zero change to them).

Cost added on the fresh path (not measured): one Relaxed load on 1/8 of eligible Auto requests,
next to an `mmap`-class syscall and an already-contended RMW.

### 5.2 Observation time: `ThpRuntime::note_valid_observation`

```text
match LEARNERS[group].try_observe_agreeing(&gradient, observation) {
    Some(agreed) => { applied++ ; if agreed { CADENCE[group].note_agree() } else { CADENCE[group].note_disagree() } }
    None         => { dropped++ }            // estimator CAS exhausted: no cadence effect
}
```

`ThpLearningCell` gains `try_observe_agreeing(gradient, obs) -> Option<bool>`: the *same single* CAS
loop (<= 8 attempts, one `load`, one `compare_exchange`), and on success it returns
`LargeThpCadence::agrees(decode(current).estimate(gradient), obs)` where `current` is the
predecessor the winning CAS replaced. The agreement is thus derived from exactly the pair the
update linearized against, with no second `snapshot()` (a second load would be incoherent and would
add an atomic site the catalog inventory rejects). `try_observe(...) -> bool` stays as a thin
wrapper (`is_some()`), so the loom/forced-CAS tests that call it keep their meaning; the runtime
calls the new method.

Signal choice and why it is relative to the *estimate*, not the share:

* `est = e + anchor*(m - e)` is what every gradient/curve/gain is applied to; comparing in the
  `est` domain is curve-, gain- and floor-agnostic and works for custom gradients without a new
  parameter. At share 0 (est below floor) agreement still has meaning, which is exactly the
  "sparse steady state" that must become cheap.
* Pre-update estimate (not post-update): the observation must be tested against the belief that
  *was in force when the control was issued*; post-update would always look in agreement.
* Tolerance `1/8` is a fixed constant (no knob). Dead-band consequence, stated plainly: a drift of
  the true density smaller than `1/8` is tracked at the current (possibly reduced) rate and does not
  raise the cadence; the estimate can sit up to `1/8` off steady data. It also makes agreement imply
  the preregistered attained-share gates for the registered `a` gradient (§8, §13): settled dense
  `est >= 0.775` gives share 1.0 (gain 5/4 clamps), settled sparse `est <= 0.225` gives share < 0.5.

What does NOT touch the cadence: premise failures (`group+9`), UNKNOWN remote reclaim, cache second
lives, invalidated old-realloc tokens, sampler errors, estimator-CAS-dropped observations. These are
not valid observations (P27 I5). Consequence, stated: a group whose controls become systematically
invalid keeps its last level (and cannot learn either); a group that never had a valid observation
stays at level 0 = today's rate.

Contention note: at the floor, steady state per observation is two loads (estimator CAS success
path + `note_agree`'s saturation check), no cadence RMW.

## 6. Rates: ceiling, floor, step sizes

Ceiling `1/8`: the preregistered `R`, the existing hard bound, restored on any disagreement. The
design can only lower cost relative to today; it can never exceed it.

Floor — control cost on steadily dense work is `1 + 6.69 r` times `Always` under the hypothesis
`c = 0.13` (model, `(1 - c) / c = 6.69`):

| r | Auto/Off (model) | Auto/Always (model) | mean / worst detection gap (ordinals) |
|---|---:|---:|---|
| 1/8 | 0.2388 | 1.837 | 8 / 15 |
| 1/16 | 0.1844 | 1.418 | 16 / 31 |
| 1/32 | 0.1572 | 1.209 | 32 / 63 |
| 1/64 | 0.1436 | 1.105 | 64 / 127 |
| 1/128 | 0.1368 | 1.052 | 128 / 255 |
| **1/256** | **0.1334** | **1.026** | **256 / 511** |
| 1/512 | 0.1317 | 1.013 | 512 / 1023 |

Choice: **1/256 (`l_max = 5`)**. Reasons: (a) the model overhead falls below 5% only from 1/128
down, and 1/256 leaves a 2.6% margin; 1/64 (+10.5%) would sit uncomfortably close to the 1.20
equal-budget ceiling once real sampling cost (<= 16 `mincore` calls per control, unmeasured) is
added; (b) below 1/256 the gain is under 1.3 percentage points while the worst-case detection gap
doubles — diminishing return on both axes; (c) 2^5 = 32 keeps the live-cohort mask inside 5 bits and
the run counter inside 5 bits. The floor and every other constant are compile-time; the measurement
registers them BEFORE data and sweeps nothing (a sweep would need the R26-4 per-arm requested/
resolved/identity evidence for a knob that does not exist). Alternative `l_max = 3` (1/64) is the
fallback if the owner weights recovery latency above steady overhead; it changes two constants and
the tables only.

Steps: 4 agreements per level (`RUNS_PER_LEVEL`). Climb from a reset to the floor takes 20 consecutive
in-tolerance valid observations, costing `sum_{l=0..4} 4 * 8 * 2^l = 992` eligible allocations (model,
exact under H2). A single disagreement (an outlier block) therefore costs about 16 extra controls
versus the floor and returns the group to 1/8 immediately ("snap up, climb slowly", fast attack / slow
decay). Known limitation: a stationary but high-variance group whose per-observation agreement
probability `p` is low climbs with probability `p^20` and hovers at low levels, i.e. it degrades
toward today's 1/8 but never worse than it. A bimodal group (50% dense / 50% sparse blocks, estimate
about 0.5) never agrees and stays at 1/8 forever; that is the honest "estimate is not predictive"
outcome and is documented, not fixed.

## 7. Recovery after a workload change

Sequence for a homogeneous stream (model, `l = 5` at the change, mean detection 256, worst 511):

1. **Detection**: the next control arrives within `<= 511` eligible requests of that group's
   stream (H3).
2. **Reset**: that valid observation disagrees (`abs(o - est) > 1/8`) -> `fetch_and` clears the run ->
   `l = 0` for the very next candidate.
3. **Convergence at 1/8**: the estimator tracks at the gradient's own rate; the cadence stays at 1/8
   while the estimate lags by more than 1/8, and starts climbing only after 4 consecutive agreements.

Model numbers (CAUTIOUS unless stated; observations are exact Q31 replays of o = 1.0 dense,
o = 0.05 sparse; `valid` counts include the first agreeing ones):

| Transition | Valid obs to first est >= 0.72 (share >= 0.9) | Allocations at 1/8 for that | + detection mean / worst | vs fixed 1/8 total |
|---|---:|---:|---|---|
| sparse -> dense, CAUTIOUS | 39 | 312 | 256 / 511 | ~316 (detect mean 4) |
| sparse -> dense, EAGER | 5 | 40 | 256 / 511 | ~44 |
| sparse -> dense, STEADY | 35 | 280 | 256 / 511 | ~284 |
| dense -> sparse, CAUTIOUS (falls fast) | 16 settled (8 to agree) | see §8 | 256 / 511 | — |

Recovery cost of the floor is therefore about `+256` eligible requests (mean) of the group before
the first dense observation, i.e. roughly 4 GiB of fresh 16 MiB traffic at the old (blind) share.
That is the explicit price of the rate floor and is exactly what the recovery measurement (§14) must
read out, with the fixed-1/8 arm as the comparator.

`Auto` at share 0: controls still run at the (reduced) rate, so P27 I7 ("Auto selects controls
before reading a zero learned share so recovery remains observable") is preserved with the
amendment "at a rate of at least 1/256 per request of that group".

## 8. Reconciliation with the 96 / 1536 training target and cap

Where the numbers come from (prereg cells `phased`/`mixed`, `J13B_JUDGE_README.md` schema v4,
`J13_LIMITED_STUDY_PREREG.md` line 73, `TRAINING_TARGET/CAP` in `j13b_workload.rs` and
`j13b_schema.mjs`, tests `j13b_owner_training_native.rs`, `j13b_adaptive_windows_native.rs`):

* `96 = 3 x 32`: three time constants of the slowest registered preset rate 1/32; `(31/32)^96 =
  0.047` of the class gap remains. It is a count of **valid observations**.
* `768 = 96 x 8`: expected eligible fresh allocations to collect 96 controls at fixed cohort rate
  1/8. `1536 = 2 x 768`: the cap, INSUFFICIENT-SIGNAL if hit before 96 valid.

The identity `eligible = 8 x valid` no longer holds once the cadence adapts. Model, 96 valid
observations under the adaptive cadence (eligible allocations needed): CAUTIOUS sparse -> dense
**4576**; CAUTIOUS cold -> sparse 18464; any gradient cold -> dense 20448; STEADY 872. At 16 MiB
blocks 4576 allocations is ~71 GiB per training phase (versus ~12 GiB in the prereg), and a mixed
64 MiB sparse bucket would be several hundred GiB. Applying 96/1536 unchanged would report
INSUFFICIENT-SIGNAL for a learner that works — a false negative by construction.

Options:

* **R1 (recommended).** Keep `TRAINING_CAP = 1536` (the operational volume bound) and change the
  *completion predicate for adaptive arms* from "valid >= 96" to "**settled**": `run >= 8`
  (`TRAINING_SETTLE_RUN = 8`, level >= 2) reached on class-conforming valid observations, with the
  prereg's attained-share gates unchanged (sparse-trained < 0.5, dense-trained >= 0.9). Rationale: the
  96 count was a proxy for "the estimator has converged"; the cadence's own agreement criterion is a
  direct, tolerance-based convergence certificate. Model, observations to settle and eligible
  allocations (including the climb to level 2 at 1/8 then 1/16): CAUTIOUS sparse -> dense 72 valid /
  608 allocations; EAGER dense -> sparse 72 / 608; STEADY any direction 93 / 776; cold (optimistic
  prior) starts: dense 8 valid / 96 allocations for every gradient, sparse 16 / 160 (CAUTIOUS),
  72 / 608 (EAGER), 93 / 776 (STEADY). With worst detection (511) the bounds are <= 1119 (CAUTIOUS, registered `a`)
  and <= 1287 (STEADY) against the unchanged cap 1536: margin 1.37x / 1.19x of the worst case,
  1.78x / 1.49x of the mean case (vs the old 2.0x of expected). Settled shares in the model:
  CAUTIOUS dense est 0.903 -> share 1.0, sparse est 0.06 -> share 0; EAGER sparse est 0.147 ->
  share 0.18; STEADY dense est 0.89 -> share 1.0, sparse est 0.16 -> share 0.20 — all inside the
  gates (the gates are still judged on the measured attained share, never inferred from this).
  Optimistic-prior note: a cold dense phase settles in 8 valid observations because the prior
  already agrees; the dense phase in `phased` follows the sparse phase, so it starts from a trained
  sparse state and pays the full 72.
* R2: keep 96 valid and raise the cap to ~2 x 4576. Rejected: ~140 GiB per 16 MiB phase, and still
  gradient-dependent (cold paths need 18-20 k).
* R3: pin the cadence at 1/8 during training windows, release for trained windows. Rejected: the
  trained window would start with a cold cadence in transit, so it would not measure the settled
  state the owner asked about.

`96` stays in the code base as (a) the closed-form `e_n` oracle horizon for pure estimator tests, and
(b) the completion rule of any fixed-cadence training (none registered after this change). The
schema needs a **new version** (`j13b.raw.v5`), not a silent edit of v4: `complete` <=> settled
(`level_end >= 2`, `run_end >= 8`); `insufficient_signal` <=> `eligible == 1536` and not settled;
`pending` <=> `eligible < 1536` and not settled; new fields `run_end`, `level_end`,
`candidates_by_level[6]`, `selections_by_level[6]`; ordering `valid <= observed <= issued <=
eligible` unchanged. Training-controller code (`Training` in `j13b_workload.rs`, the owner-return
executor `j13b_owner_training.rs`) changes accordingly (they currently compare to `TRAINING_TARGET`).
All derived figures above are regenerated by script (§13.4) before the prereg cites any.

## 12. Test plan (all run on GitHub CI; nothing is run locally)

### 12.1 Pure (`tests/j13b_cadence_pure.rs`, mounts `large_thp_cadence.rs`, `bounded_mix.rs`, the
selector and `support/j13b_learning_math.rs` by `#[path]`)

1. H0: `select(seed, o, 0) == decision_at(seed, o)` over many seeds (0, `u64::MAX`, random) x ordinals incl.
   `0`, `u64::MAX - 7 ..= u64::MAX`.
2. H1: for random level schedules (level may change per request) `select => decision_at`; at most one per aligned 8.
3. H2: for each `l in 0..=5` and many seeds, every aligned `8*2^l` window has exactly one control (counterfactual: a
   mutant using `% 8` instead of the live mask, or a constant live index, fails).
4. H3: max gap `<= 2*8*2^l - 1`; decorrelation: the live-cohort index over many super-cohorts is within
   an explicit binomial bound of uniform (catches a constant-index mutant, same justification style as
   the selector tests).
5. Wrap totality at ordinal `u64::MAX` for every level.
6. `level_of` table for `run = 0..=31`, `agrees` boundary (exactly `TOLERANCE_RAW` agrees, `+1` does not),
   symmetry, endpoints `ZERO`/`ONE`; `next_run` saturation and reset; exactly 20 consecutive agreements
   reach level 5, a disagreement at any position (0..=19) returns level 0.
7. Estimator-coupled replay: feed the exact Q31 observation streams of §7/§8 through
   `LargeThpEstimator` + `agrees` + `next_run` and assert the settle/convergence counts the doc quotes
   (pins every figure in this document to code; generated by the §13.4 script, not typed).

### 12.2 Loom / forced-CAS (`tests/loom_thp_cadence_cell.rs`, `tests/j13b_cadence_contention_bound.rs`)

* loom M1: two racing `note_agree` from run 0 end at exactly run 2 (a blind-store mutant loses one).
* loom M2: `note_agree` racing `note_disagree` from run 3 ends at 0 or 1, never above (disagreement never lost).
* loom M3: a `level()` reader racing a writer sees only valid levels `<= 5`.
* forced-CAS stub (as `j13b_learning_contention_bound.rs`): with `compare_exchange` always failing,
  `note_agree` makes exactly 8 attempts and leaves the word unchanged; `note_disagree` STILL clears the
  run (the counterfactual that rejects a CAS-based reset).
* `try_observe_agreeing`: same stub, exactly 8 attempts, `None`, estimator unchanged.
* Existing `loom_thp_learning_cell.rs` and the learning contention test stay green unchanged (they call

### 12.3 Native (Linux, `alloc-global alloc-xthread alloc-decommit internals bench-internals`, one scenario
per binary, `tests/j13b_cadence_native.rs` family)

* N1 steady sparse: a single-owner loop (16 MiB, touch one byte, owner free, cache off) records, per
  free, the telemetry resident/sampled deltas of each control; the pure model replayed over those
  observations must predict the level log at every captured candidate, and after settling the realized
  selections per `8*2^5` window must be exactly 1 (H2) — a strong replay oracle, not a count.

  requests, the next candidate's logged level is 0, the share crosses 0.9 after the modelled number of

* N4 concurrent: four threads with the cadence pinned to level 2 (log cap 128 = 4 super-cohorts of 32):

## 14. Rejected alternatives

* **Per-group ordinals / per-group cohorts.** Would make per-group rates exact under interleaving and
  cut ordinal contention, but rewrites P26 (receiver `^CONTROL_ORDINAL$`, window oracle in
  `j13b_control_concurrent_ordinal.rs`, ticket log meaning) for a guarantee no registered gate needs.
  Revisit only if the mixed-cell statistics show cross-group distortion.
* **Per-request Bernoulli thinning.** Loses H2/H3 (no exact rate, unbounded blind gaps).
* **Cadence inside the learner word.** Both Q31 halves are full width; narrowing them changes the
  estimator contract.
* **Variance / EMA-of-surprise signal.** More state, a second tolerance and a stationary-noise
  ambiguity (high variance with a stable mean is not disagreement); the single tolerance is simpler
  and its failure mode (stay at 1/8) is the safe one.
* **Decay-by-halving on disagreement** (instead of snap to 1/8): slower recovery after a genuine
  change; one outlier then needs several in-band observations to restore the rate.
* **Dropping the cadence update when the estimator CAS is exhausted** is kept (no signal available); the
  alternative of classifying against the last failed `actual` is rejected as incoherent.
