Рабочий документ цели G1 (паритет с mimalloc по судье J1′ v2). Раздел 1 —
каталог прошлых нерабочих идей, чтобы не воплощать их повторно. Раздел 3 —
новые кандидаты. Каждое число здесь — цитата из указанного отчёта, не новый
замер.

## 2. Уроки

1. **Меньше Ir ≠ меньше времени** (GR-1, U32): дважды подряд −7…−9 % Ir
   дали замедление. Кандидат с Ir-аргументом без механизма по времени —
   слабый. Нужен механизм, который видно во времени: промахи кэша,
   зависимые загрузки, store-forwarding, раскладка кода.
2. **Churn — не шаги own-free**, а перенос блоков между классами
   (пункт 116): блок проходит magazine → reset → refill → issue. Склад
   закрыл часть, разрыв churn16 1.66× остаётся.
3. **bulk — инструкции drain + flush** (пункт 114), но GR-1 показал, что
   урезание flush по Ir не даёт времени. На bulk16k (2.10×) разрыв
   наибольший — механизм не выяснен по времени.
4. **Микро-уровень исчерпан**: 7 арифметических хаков, 4 NO-GO подряд в
   flush, перебор TCACHE_CAP/FLUSH_N. Следующий выигрыш — структурный, не
   микро.
5. **Одиночные короткие прогоны недостоверны**: разброс между процессами
   до ±17 % (пункт 115). Только J1′ v2: 20 процессов × 2000 блоков, null-
   прогон, bootstrap по процессам.

## 4. Кандидаты (ранжированы)

| # | Кандидат | Ядра | Потолок (ОЦЕНКА) | Проверки | Решение владельца |
|---|---|---|---|---|---|
| K1 | drain без повторной записи кода класса в `ClassLeaves` | bulk16k, bulk64, churn с переносом, larson | ≈ 15–20 Ir на выданный из списка блок; ≈ 7 % Ir bulk16k | все остаются | не нужно |
| K2 | класс на free из байта состояния вместо `class_for(layout)` | все (каждый free) | ≈ 7 инструкций на free из ≈ 74 | free с чужим Layout сейчас тихий no-op (утечка), станет освобождением в истинный класс | нужно (меняется поведение при нарушении контракта Layout) |
| K3 | повтор GR-1 (flush без повторных проверок) с PMU-разбором | bulk | flush 48.3 → 27.9 Ir/пару (пункт 121) | внутренние, под I-MAG | триггер пункта 121 — теперь PMU есть |

**K1 — почему безопасно.** В список класса c попадают только блоки, ранее
выданные этим классом: `flush_run` (магазин, байт MAG/LIVE класса c),
`reclaim_sidecar_record` (класс из записи sidecar = код листа),
`dealloc_small` (байт `encode(c, LIVE)`). При выдаче код c+1 записан в лист;
листы `ClassLeaves` только создаются (`promote`) и живут до последнего пина
маршрута; код никогда не стирается; при сбросе сегмента списки обнуляются
(`decommit.rs`). Значит, на drain блок уже несёт код c+1 — повторная
Release-запись того же значения ничего не меняет для читателей других
потоков (они синхронизированы с первой записью через передачу указателя).
Инвариант проверяется ghost-проверкой на drain. На нарезке (carve) запись
кода остаётся.

**Порядок:** K1 → замер против main и против mimalloc (J1′ v2, 20 процессов ×
2000 блоков, null) → K2 после решения владельца → K3.
