## Согласие между двумя ревью

- Rounds 13-17 — арка корректности/soundness-хардening, не perf-арка.
  `production`'s feature-список не менялся с Round 13.
- R17-3 (`b8612bc`) — реальный, подтверждённый iai-числами выигрыш
  (−81,966 Ir), но это bootstrap-константа (per-heap), не marginal
  per-op экономия.
- R17-4 (`1b761f4`) — серьёзный, реальный фикс утечки, но живёт только под
  opt-in `medium-classes`, не влияет на `production`.
- `class-aware-dirty` (единственная фича, промотированная в `production`) —
  full-round эффект НЕ подтверждён ни в одном из 4 независимых process-level
  замеров (1 значим в проигрышную сторону, 3 незначимы).
- R17-10's design doc корректно самооценивает свой потенциал как
  constant-factor, не алгоритмический — оба ревью согласны, реализовывать
  sub-design B только если stage-1 счётчик покажет реальную частоту
  multi-empty sweeps.

## Что НЕ заводится задачами в этом раунде

- Page-run слой (256 KiB-2 MiB) — оба ревью согласны, что DEFERRED-статус
  (`R12_13_PAGE_RUN_LAYER_DEFERRED.md`) остаётся корректным без измеренного
  victim-ворклоада; R18-2's результат может это изменить (если R10-2 всё же
  останется красным даже после фикса утечки — тогда page-run вновь
  становится кандидатом), но это решение — после R18-2, не сейчас.
- Expandable/chained `SegmentTable` — CONDITIONAL, `MAX_SEGMENTS=4096`
  headroom ещё не исчерпан (~1 порядок величины остаётся) — не срочно.
- `cargo-hack --depth 2` тюнинг — верифицировано, что текущая глубина всё
  ещё покрывает свой мотивирующий баг через граф зависимостей фич; не
  требует изменений сейчас, только заметка на будущее.

**Порядок исполнения:** R18-3 (сузить kind_at) → R18-1 (watchdog fix,
независим) → R18-2 (re-run R10-2 gate, зависит от R18-3) → R18-7
(инвентаризация mimalloc-plan) → R18-4/R18-5 (мелкие doc-фиксы, можно
объединить) → R18-6 → R18-9 → R18-8. Методология прежняя: делегирование
согласно текущей активной инструкции пользователя (на момент заведения —
`/crush`), личная zero-trust верификация каждого диффа, red/green
counterfactual для soundness/correctness-фиксов, коммит между задачами.
