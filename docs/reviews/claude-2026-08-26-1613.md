## 3. Новые находки

### P3

**F1 — третье остаточное вхождение опровергнутой const-eval-семантики: rustdoc `size2class_len` утверждает «`const`/debug traps on this», ту же семантику, что run-5 F1 закрыл в двух других местах — но другими словами, поэтому оно пережило и grep run-5, и фикс `d17aae9`.**
Где: `crates/size-classes/src/lib.rs:155-161` (rustdoc-абзац P2-1 на публичной `size2class_len`): «the trailing `+ 1` was a bare add -- `size2class_len(usize::MAX, 1)` divides to `usize::MAX`, and the `+ 1` then overflows. **`const`/debug traps on this; a `release` runtime call (this function is `pub`, not `const`-only) silently wrapped to `0` instead**».
Введено коммитом `cc94a46` (task #1417, фикс run-1 P2-1) — то есть В ХОДЕ кампании, но ДО того как task #1423/#1431 эмпирически установил профильную семантику; проверено `git log -S` — единственный коммит, вносивший эту фразу.
Почему это та же ошибка: дихотомия абзаца — «const-вызовы трапаются; из runtime-вызовов release враппит» — молча помещает release-профильный `const`-вызов в корзину «traps». По эмпирически установленной семантике кампании (overflow-проверки тела `const fn` следуют профилю) pre-fix `const L: usize = size2class_len(usize::MAX, 1)` в release-сборке ТИХО враппился бы в 0, а не трапался — ровно тот случай, ради которого `d17aae9` только что исправил формулировку «the bug only existed at runtime» в `builder.rs:399-403`, описывающую ЭТОТ ЖЕ P2-1-нарратив. После `d17aae9` тест-файл и rustdoc той же функции рассказывают одну историю двумя несовместимыми способами: `builder.rs:400-401` — «the bug these tests pin is release-profile-specific either way, `const` or runtime»; `lib.rs:157` — «`const`/debug traps on this». Обе версии одновременно истинными быть не могут; какая ложна — кампания уже установила экспериментом.
Эпистемический статус — явно: этот аудит read-only и не выполнял никаких проверок компилятором; направление истины целиком из task #1423/#1431, применённого к идентичной форме кода (голая арифметика внутри тела `const fn` — не литеральное const-выражение, для которого действует исключение «errors in every profile»). Текстовое противоречие `lib.rs:157` ↔ `builder.rs:400-403`/`507-511` доказуемо чтением независимо от направления.
Вес: в отличие от двух мест run-5 F1 (внутренний `//`-комментарий тела функции и заголовок тест-секции), это `///`-rustdoc публичной функции — уходит и в crates.io-tarball, И в отрендеренный docs.rs. Ошибка по-прежнему «в безопасную сторону» (занижает охват собственного фикса, не завышает гарантий), не блокирует публикацию.
Фикс — одно предложение по образцу уже принятых: например «debug (`const` or runtime) traps on this; a `release` call -- runtime or `const` (const-eval overflow checks follow the profile for a `const fn`'s body, task #1423/#1431) -- silently wrapped to `0` instead». После него grep по `traps` в крейте не должен оставлять ни одного вхождения без профильной квалификации.
