## P3-1. Новый extractor всё ещё может проверять неисполняемый или неполный контракт

Места: `tests/protocol.rs:519`, `:522`, `:555`, `:578`, `:582`, `:592`, `:855`;
reference — `scripts/paired-ab-runner.mjs:250`, `:253`.

`extract_runner_contract` ищет первое подходящее `/^RESULT` во всём тексте.
У него нет понятия комментария, строки, нужной функции или активной ветки.
После проверки `.exec(` он возвращает найденное выражение сразу. Preprocessing
сведён к одному биту: `arg.ends_with(".trim()")`.

Два независимых контрпримера к нынешнему коду, без выполнения мутаций:

1. Перед изменённой строкой parser оставить комментарий со старым выражением:

   ```javascript
   // Previous contract: /^RESULT\s+([a-z0-9_]+)=(\S+)$/.exec(line.trim())
   ```

   В настоящей строке затем добавить `i` или убрать trim. Extractor сначала
   прочитает комментарий, получит прежние body, пустые flags и `trims = true`,
   вернёт `Ok` из drift guard и до изменённого рабочего кода не дойдёт.

2. В единственной настоящей строке заменить аргумент на
   `.exec(line.toLowerCase().trim())`. Body и flags прежние, suffix `.trim()`
   присутствует, guard проходит. Но runner теперь меняет строку до matching:
   нормальный `RESULT k=1` становится `result k=1` и не совпадает с regexp.
   Node helper из теста по-прежнему делает только trim, не toLowerCase;
   результаты проверки corpus не отражают изменённую семантику.

На текущем HEAD рабочее выражение runner не менялось, поэтому не утверждаю,
что сейчас ему передаётся неправильный contract. Проблема в защите от
рассогласования и в обещаниях «ACTIVE»/«CURRENT semantics»: её обходят именно
те текстовые конструкции, которые новый extractor не разбирает.

Две добавленные отрицательные проверки полезны: они ловят добавленный flag
и удалённый trim в минимальном fixture. Но они не доказывают идентичность
активного callable. Это остаток P3-1 прошлого раунда, а не новая ошибка emitter.

Рекомендация: общий чистый parser/helper, действительно используемый runner
и interop-проверкой. Не импортировать текущий runner целиком: его top-level
main запускает измерительный workflow. Не наращивать самодельный JavaScript
lexer очередной частичной обработкой comments/strings: это переносит проблему,
но сохраняет второй источник истины. Если остаётся строго ограниченный source
guard, его допустимая грамматика и выбор active statement должны быть явными,
с проверками обоих контрпримеров выше.

## P3-2. Ошибка записи corpus обходит ожидание уже созданного child

Места: `tests/protocol.rs:800`, `:801`, `:812`, `:816`, `:817`, `:818`.

После успешного spawn helper владеет Child. Запись в stdin заканчивается
`.expect(...)` ещё до `wait_with_output()`. Если child закрыл читающий конец
pipe до записи — например, завершился на ранней ошибке инициализации, —
`write_all` может вернуть BrokenPipe. Тогда тест паникует, не забрав exit status
и stderr дочернего процесса.

Pipe handles при unwind закроются, но это не эквивалент wait. У `Child` нет
автоматического ожидания/остановки процесса; на Unix завершившийся, но не
собранный родителем процесс может остаться zombie. Так определён контракт
[std::process::Child](https://doc.rust-lang.org/std/process/struct.Child.html#warning).
Здесь риск ограничен тестовой обвязкой, не процессами пользовательского emitter.

Первый `node --version` этого не исключает: проверяется другой запуск, а
ошибка записи возникает уже после приобретения нового child handle.
Заодно теряется наиболее полезная диагностика раннего отказа Node — его stderr.

Сохранить результат записи, закрыть stdin и завершить сбор результата child
также на ошибочном пути; только затем сообщать ошибку теста. Если путь требует
принудительного завершения, делать его через принадлежащий helper объект Child
и всё равно забирать exit status. Нужен отрицательный контроль, где child
закрывает stdin до записи, а тест проверяет не только ошибку, но и завершённый
жизненный цикл процесса.

Обычный успешный путь устроен правильно: `wait_with_output` сам закрывает
оставшийся stdin, что позволяет Node получить `end`. Поэтому отдельного
happy-path deadlock «забыли закрыть stdin» здесь нет. Это видно и в
[реализации Rust 1.88](https://github.com/rust-lang/rust/blob/1.88.0/library/std/src/process.rs#L2230).

## P4-1. CHANGELOG приписывает host-проверке bare-metal покрытие MSRV

Места: `CHANGELOG.md:139`, `:142`; `.github/workflows/ci.yml:2687`, `:2688`;
отдельная stable-проверка — `.github/workflows/ci.yml:1266`.

В MSRV job добавлены две правильные команды с `--all-targets`, default и
feature-off. Они компилируют собственные host targets пакета, включая tests.
Но у них нет `--target thumbv7em-none-eabi`. Снятие default features не выбирает
bare-metal target, а `--all-targets` означает виды Cargo targets, не все
архитектуры. Глобального target override, меняющего этот вывод, не найдено.

Поэтому фраза CHANGELOG про проверку tests на MSRV в «bare-metal
--no-default-features configuration» неверна. Отдельная bare-metal библиотека
собирается в другом job на stable, не на 1.88. Так что прежний пункт P4-3
закрыт частично, а не полностью.

Уточнить документ до host feature-off и, если закрывается весь обещанный
пункт, добавить библиотечный cross-check на 1.88 с явным `--target`.
Не добавлять к нему `--all-targets`: host-тестовая обвязка использует std
и не предназначена для исполнения на bare metal. Найденного несовместимого
с 1.88 API здесь не заявляю; это точность покрытия и документации.

## P4-2. Несколько комментариев тестов всё ещё обещают больше, чем проверяют

Места: `tests/protocol.rs:244`, `:346`, `:391`, `:407`, `:412`.

- «Exactly this test (and only this test)» больше неверно: общий oracle
  вызывают и обычный, и serial-child тесты. Поломка emit-body затрагивает
  оба. Достаточно пояснить независимость ожидаемых байтов от production-format,
  без утверждения об эксклюзивности отказа.
- «Both child thread modes (multithreaded default and forced serial)» не
  гарантированы: обычный helper наследует окружение и доступный parallelism.
  При внешнем `RUST_TEST_THREADS=1` оба запуска будут serial. Либо описать
  покрытие как inherited/default и forced-serial, либо отдельно закрепить
  второй formatter mode. Само исправление serial-ошибки от этого не страдает.

Это низкоприоритетные уточнения, не повод ослаблять assertions или менять
runtime-код. Длинные повторения истории ревью полезнее заменить кратким
объяснением актуального инварианта и ссылкой на исторический отчёт.

## Общая проверка кода и затрат

### Production API

Повторно проверены все пять emit-функций, constant и четыре measurement
реэкспорта. Сигнатуры не передают владение heap-буферами, числовых сужений нет;
unsafe/FFI/ручных Send/Sync в собственном коде нет. Все std-зависимые items
по-прежнему согласованно gated, dependency optional. `SnapshotError` теперь
именован в compile-time type pin теста.

Unchecked политика key/value и Panics явно документированы; не превращаю
её снова в требование добавить валидацию. Фасад предоставляет fallible путь,
а README объясняет отличие ошибки измерения от нулевой метрики. Таймер в
quick start фиксируется до snapshot/output — прошлое замечание закрыто.

Передача строк требует O(K + V) по количеству байтов key/value. Пять прямых
вызовов std formatting не содержат собственных String/Vec/clone/collect.
Снижения O на production-пути не требуется. Умышленное добавление
`to_string()` ради делегирования numeric helpers в строковый emit было бы
ненужной аллокацией, не улучшением. Новых замеров скорости/allocator calls нет.

### Тестовая обвязка

Terse-режим задаётся непосредственно child; extra env для serial-случая
тоже передаётся только child. Real-stdout oracle сохраняет независимый
literal RESULT, contiguous LF block и проверку лишних RESULT-строк. Старые
контрпримеры с пустым emitter и сужением u128 этим путём наблюдаемы.

Переход corpus на stdin действительно удаляет temp-file round trip и
зависимость от кодировки TMPDIR. Node объединяет Buffer chunks перед UTF-8
декодированием, поэтому разрез многобайтового символа между chunks не теряет
данные. Длина и алфавит verdicts проверяются до индексирования; фиксированный
corpus остаётся ограниченным 37 строками. JSON escaper на этих входах
сохраняет нужные escapes; ошибки кодирования или переполнение не найдены.

SKIP теперь ограничен NotFound и выводится напрямую в stderr. Отдельный
capture-тест действительно наблюдает stderr child, без --nocapture и без
наследуемого RUST_TEST_NOCAPTURE. CI проверяет наличие Node и runner до tests.
Это существенное улучшение; в этом раунде я не исполнял эти проверки.

В новых byte scans границы срезов не дают найденного UTF-8 panic:
search_from продвигается за найденный ASCII anchor, возвращаемые диапазоны
проверяются через get. Ошибка extractor семантическая — P3-1, а не UB.

### Где можно упростить и ускорить

Тестовый файл вырос с 575 до 1009 строк при неизменившемся production-коде.
Проблема не в самом числе строк, а в дополнительной реализации части языка
JavaScript ради проверки одного parser: она уже не покрывает заявленный
контракт. Наиболее полезное упрощение — убрать дублирование parser/preprocessing
из P3-1, а не развивать собственный lexer.

В cold-path ещё есть два запуска Node, сборка JSON и небольшие промежуточные
String/Vec. Сначала исправить lifecycle и источник истины; микропрофилирование
этих небольших allocations или новая formatter dependency не обоснованы.
Не приписываю стоимость тестовой обвязки самому `emit*` и не обещаю численного
ускорения без измерений.

Writer/sink API мог бы обслуживать пакетную запись с одним stdout lock,
но решение не расширять public API без измеренной необходимости остаётся
приемлемым. Лицензии, dated CHANGELOG и manifest сохранены; независимой
проверки packaging/linking в этом раунде не было.
