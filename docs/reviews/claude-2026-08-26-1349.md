## 2. Свежий полный обзор — что проверено и признано корректным

Не просто «посмотрел» — проверил рассуждением по коду:

- **`build_table`, merge.** Ленивая генерация геометрического ряда + two-pointer merge: advance выполняется только когда `gi < geo_count` ПОСЛЕ эмиссии, т.е. шаг за последним классом никогда не вычисляется — ложных overflow-panic на неиспользуемых значениях нет. При равенстве `cur == extras[ei]` merge эмитит extra первым, дубликат ловится финальной проверкой. Цикл делает ровно `geo_count + extras.len() = N` итераций, `out` заполняется полностью.
- **`build_size2class`, monotone-pointer.** `class_idx` монотонен вместе с `need` — O(L + N) корректен. Sentinel-bucket `L-1` недостижим из `class_for` (для `need <= small_max` максимальный индекс `(small_max-1)>>shift = L-2`) — кламп безвреден, как и заявлено.
- **`class_for`, fast path.** `align <= min_block` (оба pow2) ⟹ `align | min_block | block` — делимость тривиальна; seed = наименьший класс `>= need` (bucket-округление корректно, т.к. каждый класс кратен `min_block`, а между кратными классов нет).
- **`class_for`, jump slow path.** Для pow2 `align > min_block`: `align` кратен `min_block`, значит `next_mult` (кратное `align`) кратно `min_block`, значит lookup по `(next_mult-1)>>shift` даёт наименьший класс `>= next_mult` ТОЧНО (без округления вверх мимо кандидата). Пропущенные классы в `(block, next_mult)` кратными `align` быть не могут. Терминация: строгая монотонность таблицы ⟹ индекс растёт каждый виток. Эквивалентность walk/scan дополнительно запинена proptest'ом на трёх схемах.
- **Тестовые оракулы.** `reference_table`/`reference_class_for` независимы от SUT; циркулярность формулы округления закрыта hand-derived golden-тестом (`geometric_run_matches_hand_derived_golden_values` — арифметику в комментарии перепроверил, все 8 значений верны). Полный sweep `size × align` до `SEFER_MAX + 1` против reference — сильный exhaustive-оракул для боевой схемы.
- **Публикационные метаданные.** name/version/edition/rust-version/license/description/readme/repository/homepage/documentation на месте; keywords — 5 штук, все ≤ 20 символов; все три категории — валидные слаги crates.io; LICENSE-MIT/LICENSE-APACHE лежат в директории крейта; README-пример использует ```text-фенс (no-doctest конвенция соблюдена), его `MAX_CLASS = 258_752` арифметически верен для приведённых параметров. MSRV-чувствительные API: `div_ceil` (1.73), `is_multiple_of` (1.87), `checked_*` — всё внутри заявленного 1.88.

## 3. Новые находки

### P3

**F1 — 2 из 4 закрытых P2-1 точек не запинены regression-тестами.**
Где: `lib.rs:468-471` (кламп bucket-need) и `lib.rs:690-693` (`checked_add` → `None` в slow path); тесты покрывают только `size2class_len` и L-check.
Обе точки достижимы легальной, целиком `Params`-собираемой схемой (64-bit): `min_block = 1 << 62`, `geo_count = 1`, `extras = [2 << 62, 3 << 62]` → таблица `[1<<62, 2<<62, 3<<62]`, `small_max = 3<<62`, `L = 4`. Тогда (а) в `build_size2class` bucket `k = 3` вычисляет `(4) * (1<<62) = 2^64` → overflow → кламп-ветка; (б) `class_for(3 << 62, 1 << 63)`: seed — класс `3<<62`, он не кратен `1<<63`, `(3<<62) | ((1<<63)-1) = usize::MAX` → `checked_add` → `None`-ветка. До фикса обе точки в release давали wrap; сейчас поведение корректно, но контрфактуальность (упал бы тест без фикса?) не закреплена — ровно тот стандарт, который run 1 требовал («runtime-регрессии именно для release-семантики») и который для двух других точек выполнен. Рекомендация: два теста по рецепту выше, под `#[cfg(target_pointer_width = "64")]`.

**F2 — бенчмарк-строки «slow path» ни разу не исполняют jump.**
Где: `benches/size_classes_bench.rs:58-67`.
Обе строки — `class_for(256, 256)` и `class_for(1024, 1024)` — резолвятся на ПЕРВОЙ итерации slow path: 256 и 1024 сами являются классами (extras) и тривиально делятся на себя, т.е. измеряется вход в slow path + одна проверка делимости, но не jump-механика (`next_mult` → re-seed) — главное алгоритмическое заявление крейта («skipping whole runs of non-divisible classes»). Комментарии честны («potentially jump»), имена не лгут, поэтому это не P2-класс run 1, но перф-профиль различительной ветки не измеряется вовсе. Рекомендация: добавить строку с реальным прыжком, например `class_for(128, 128)` — seed попадает в класс 144 (не кратен 128), один jump до 256; ровно этот сценарий уже запинен юнит-тестом `sefer_jump_skips_non_divisible_run_for_align_128`. После добавления — перекалибровать `bench-iters.txt`.

**F3 — `geo_count + extras.len()` в assert `build_table` — bare add.**
Где: `lib.rs:217-220`.
При абсурдном `geo_count` (например `usize::MAX` при непустых `extras`) сумма в release wrap'ается, и проверка `N == geo_count + extras.len()` может ПРОЙТИ на wrapped-значении. Silent-wrong результата не возникает никогда: цикл merge делает истинное (не wrapped) число итераций и гарантированно падает на `out[oi]` с bare «index out of bounds» — но это ровно тот класс диагностической непоследовательности (голый panic вместо именованного assert, называющего плохой параметр), который этот же крейт уже дважды чинил (task #731: `den == 0`; run 1 P2-1). Рекомендация: `geo_count.checked_add(extras.len())` + именованное сообщение; `# Panics` дополнять не обязательно (покрывается текстом про N).

**F4 — doc-drift: третье machine-checked precondition `extras` не заявлено на самом поле.**
Где: `lib.rs:80-88` (`Params::extras`), `README.md:8-15`.
Рустдок поля говорит «Both preconditions are machine-checked» (кратность + строгое возрастание), но после P2-2 проверок три: добавлено `>= min_block` (материально это запрет ровно одного значения — `0`, т.к. любое положительное кратное `min_block` уже `>= min_block`). Запрет задокументирован только в `# Panics` у `build_table`; первичная справка по контракту поля («Both…») теперь недосчитывает. README аналогично называет «both preconditions». Однострочная правка в двух местах.

### P4

**F6 — `1usize << 63` ломает компиляцию тест-сьюта на 32-bit хостах.** `tests/builder.rs:317, 337` — const-eval shift overflow на 32-bit target = ошибка компиляции всего сьюта. CI это не затрагивает (thumbv7em-строка — lib-only `cargo build`), но портабельная форма `1usize << (usize::BITS - 1)` бесплатна.

**F7 — формулировка «Panics in `const` evaluation if…»** во всех трёх builder-фнах занижает контракт: те же panic'и равно срабатывают в runtime-вызовах (pub fn), и весь смысл P2-1-фикса был именно в runtime-release поведении. Приписанные task-note абзацы это проговаривают, но заголовочная строка контракта — нет.

**F8 — рустдок `build_size2class` не оговаривает sentinel-bucket.** Публичный контракт «`size2class[k]` is the smallest class whose `block_size >= (k+1)*min_block`» для верхнего bucket `L-1` невыполним (класса `>= small_max + min_block` нет; entry клампится к последнему классу). Объяснено только во внутреннем комментарии (`lib.rs:454-457`), не в публичной доке.

**F9 — defense-in-depth для hand-built таблиц проверяет монотонность, но не кратность `min_block`.** Таблица `[16, 24, 32]` с `min_block = 16` проходит `build_size2class`; класс 24 через lookup недостижим (bucket (16,32] резолвится в 32). По заявленному bucket-контракту результат формально корректен, а собрать `SizeClasses` минуя `build_table` публичный API не позволяет — поэтому только заметка: либо дополнительный assert кратности, либо одна строка в доке.

**F10 — `let _ = shift;`** в `build_size2class` (`lib.rs:433, 445`) — вычисленное и отброшенное значение; const-only, нулевая цена, чисто косметика.

### Perf-возможности (semantics-preserving, только с измерением)

**P-1 — slow path: `block.is_multiple_of(align)` → `block & (align - 1) == 0`.**
`is_multiple_of` разворачивается в ветку на `rhs == 0` плюс `block % align` — для runtime-`align` это аппаратное деление на каждой итерации slow path. `align` контрактно pow2 (fast path недосягаем для `align > min_block`), поэтому масочная форма эквивалентна на всём in-contract домене (для non-pow2 `align` поведение и так объявлено незащищённым, `debug_assert` сохраняется). Соседний `next_mult` уже использует масочную идиому — правка ещё и унифицирует стиль. Hot fast path трогать нечего: `max` + сравнение + shift + индекс + сравнение уже минимальны. По дисциплине репозитория: сначала добавить jump-строку из F2, затем мерить до/после (`cargo bench -p size-classes`).
Попутное наблюдение (не дефект): mul-до-div в геометрическом шаге (`cur * num / den`) может дать loud panic на схеме, чей истинный следующий класс помещается в `usize` (например `cur = 1<<63`, growth `(3,2)`) — это in-contract (задокументированный громкий отказ, не silent-wrap), расширение через u128 не оправдано для build-time-only пути.
