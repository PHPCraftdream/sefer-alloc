## Executive summary

The crate is in good shape where it matters. The algorithm is ~410 lines of code (`src/imp.rs` minus comments), the atomics are correct and loom-proven, the one `unsafe` token is exactly where the ADR says it is, rustdoc builds clean under `-D warnings`, and I found **no bugs** — no reachable panic beyond the three documented ones, no false-positive path for the self-loop detector under contract-abiding contention, no unsound cast, no ordering hole.

Performance: nothing actionable beyond the two items already open in `docs/perf/OPEN_ITEMS.md` (61: redundant `store_next` per retry; 62: arm64 wall-clock). Every hot function is generic (so `#[inline]` is moot), the layout has no false-sharing defect, and the hot path does the minimum the algorithm needs. The only code-level perf note is a dead `.min()` in the backoff that exists purely to be explained away in the doc comment.

The real debt is prose and mechanical duplication, and it is substantial: `src/imp.rs` is 77% comment lines, `src/lib.rs` 91%; the `StackStorage` trait doc alone is 510 lines and carries **two different five-item lists both cited as "rule N"** — the single most confusing thing in the crate, and it sits on the one contract an `unsafe impl` author is required to read. Residual doc drift survived the P3-5 consolidation in five places (the most important: the push/pop CAS comments still say the weak-CAS win is "real but unmeasured — no multi-target harness", one commit after the harness measured it NULL). Code-side, the same ~25-line backoff arm is written twice, the same ~55-line child-cargo boilerplate five times, the same ~130-line bench phase twice, and a 130-line panic-hook rig guards one assertion that a one-test binary would make trivial.

Verdict: **publishable code; the documentation needs a second, register-focused pass, and four small refactors would remove most of the duplication.** Nothing here blocks; the doc drift in §5.1–5.3 should land before publication because each states something false about the current code.

## 1. Performance opportunities

**1.1 [checked, no finding] Missed `#[inline]`.** Every hot function is generic over `INDEX_BITS`/`N`/`S` (`push_index_impl`, `pop_index_impl`, all `StackHead`, `ArrayLinks`, `TaggedIndex` methods, `ArrayIndexStack::push/pop`), so each is monomorphized in the downstream crate and cross-crate-inlinable by construction. The only non-generic functions are the two `#[cold] #[inline(never)]` panic helpers (`src/imp.rs:1394-1435`), which are correctly kept out of line. Adding `#[inline]` anywhere would change nothing.

**1.2 [checked, no finding] Layout / cache-line placement.** `StackHead` is a bare `AtomicU64`; `ArrayLinks<N>` is a dense `[AtomicU32; N]`; `ArrayIndexStack` is `{ head, links }` with no padding, so `head` shares its 64-byte line with `links[0..14]`. That is *true* sharing, not false sharing: a link cell is only ever touched by a push/pop that also touches the head, so no line transfer is added that the head CAS would not already cause. The production consumer (`Registry`) is slot-resident and unaffected. Both layout notes (`src/imp.rs:276-287`, `:1597-1609`) correctly push isolation to the embedder. One precision nit: the `StackHead` note's "interpose padding" advice cannot be applied to `ArrayIndexStack`'s own head/links adjacency (fields are private); only whole-struct alignment is available there. Doc-only, low.

**1.3 [checked, no finding] Hot-path work audit.** push = 1 Relaxed load + 1 Release link store + 1 CAS + one range-check branch; pop = 1 Acquire load + `is_empty` branch + 1 Acquire link load + guard (two compares, one of them `next != TAIL` short-circuit) + 1 CAS. That is the minimum for a tagged Treiber stack with the documented release-active guard. The double masking of `head` by `is_empty` then `unpack` (`src/imp.rs:1208`/`:1202`, `:1299`/`:1302`) is CSE'd by LLVM. `#[track_caller]` on the generic `*_impl` functions costs a hidden `&Location` argument only when not inlined; in practice they are inlined and the location constant-folds.

**1.4 [confident, micro] Dead `.min()` in the backoff shift** — `src/imp.rs:1256` and `:1355`: `1u32 << spins.min(BACKOFF_SPIN_CAP)`. `spins` is already saturated at the cap by the guard four lines later (`:1276-1278`, `:1366-1368`), so the `.min` can never change the value; the `BACKOFF_SPIN_CAP` doc admits this in five lines (`:37-41`, "belt-and-braces, not the enforcement mechanism"). Cost is a register `min` per retry — unmeasurable — but it is code that exists only to be explained. Fix together with §2.1: one saturating increment, shift by `spins`, and let the existing `const _: () = assert!(BACKOFF_SPIN_CAP < 32)` (`:70`) be the sole overflow guard.

**1.5 [second look, doc-level] The pop-`TAIL` branch is arithmetically redundant, and its justification is wrong.** `src/imp.rs:1325-1330` selects between `pack_truncating(empty_index(), tag)` and `pack_truncating(next, tag)`; but `pack_truncating(TAIL as u64, tag)` already produces the empty sentinel at every width, because `u32::MAX & INDEX_MASK == INDEX_MASK` whenever `INDEX_MASK <= u32::MAX` — an identity, not the "numeric coincidence" the `TAIL` doc (`:24-30`) and the push comment (`:1204-1207`) call it. LLVM folds the branch to a select, so there is no runtime cost either way; I would keep the explicit branch for readability but fix the "coincidence" framing (§5.6). If someone wants the branch gone, a `const _` assert pinning the identity is the honest replacement, not the existing prose.

**1.6 [process note] A third ordering candidate is named in the CHANGELOG but tracked nowhere.** `CHANGELOG.md:283-292` records "pop_index's CAS SUCCESS ordering (Acquire today) as a Relaxed candidate ... considered and NOT changed". It appears in neither `docs/perf/OPEN_ITEMS.md` item 61 nor 62, nor in the gate report's variant list (`scripts/tis_p3_ab_runner.mjs:39` has only `base`/`links_relaxed`/`cas_weak`). Under CLAUDE.md's round-start rule it should be an indexed item or folded explicitly into 62's scope. (The candidate itself looks sound to me — the success RMW still extends the release sequence and pop publishes nothing — but it is unmeasured and correctly unlanded.)

Items 61 and 62 remain the only real perf headroom; I found nothing the prior measurement missed.

## 2. Code smell

**2.1 [confident] The CAS-retry backoff arm is written twice.** `src/imp.rs:1244-1279` (push) and `:1341-1370` (pop) are the same ~25 lines — counter increment, spin loop, cap-reach counter, saturating increment — differing only in counter names and pop's empty-skip; the pop copy carries four "see push's identical comment" pointers (`:1296`, `:1338`, `:1342`, `:1348`, `:1365`). A private `struct Backoff(u32)` with `fn spin(&mut self)` and `fn at_cap(&self) -> bool` (the gated counters stay at the two call sites, or `spin` returns whether it ran at cap) removes the duplication and the dead `.min()` (§1.4) in one move, with no behavior change. Verification: `tests/threaded_conservation.rs` under `--features test-internals` already asserts both counter levels.

**2.2 [second look] `TaggedIndex::unpack` returns `(u64, u64)` and `pack` takes `index: u64`,** which forces `as u32` narrowing at `src/imp.rs:1211`, `:1303` and `as u64` widening at `:1181`, `:1219`, `:1322`, `:1329`, `:1425` (clippy pedantic flags all seven). `_CHECK_BITS` guarantees every index fits in 16 bits, and the docs argue "every valid index fits in push_index's u32 parameter" in prose three times (`:89-92`, `:120-124`, `:984-986`). Returning `(u32, u64)` / taking `index: u32` would let the type system carry that fact and delete every cast on the hot path. Breaking, but 0.1.0 is unpublished. Only the `u64` API's symmetry (both halves the same type) argues for keeping it.

**2.3 [confident] Five compile-fail drivers duplicate ~55 lines of child-build boilerplate each:** manifest path, packaged-skip guard, `CARGO_TARGET_TMPDIR`, env stripping, `CARGO_TERM_COLOR=never`, output capture, context string — `tests/compile_fail_two_backings.rs:97-154`, `tests/compile_fail_array_index_stack_head.rs:52-103`, `tests/compile_fail_index_bits_bounds.rs:63-120`, `tests/compile_fail_loom_cfg_without_feature.rs:66-128`, `tests/compile_fail_unsafe_impl_required.rs:32-83`. The "Published-package behavior" prose block is also repeated verbatim in three module docs (`two_backings:34-48`, `index_bits_bounds:13-27`, `loom_cfg_without_feature:23-37`). A `tests/common/compile_fail.rs` helper — `fn build_fixture(dir: &str, rustflags: Option<&str>) -> Option<Output>` returning `None` in the packaged-skip case — leaves each driver as its assertions only. `compile_fail_index_bits_bounds.rs:62-138` already shows the shape (it is a local helper used twice).

**2.4 [confident] The bench's two contention phases are the same ~130 lines.** `benches/tagged_index_stack_bench.rs:255-391` and `:439-536` share the entire published-window protocol (two barriers + `OnceLock`, warm-up loop, entry-lateness guard, `DEADLINE_CHECK_INTERVAL` timed loop, join + elapsed); only the per-thread seed and the pop-`None` policy differ. A `run_contention_phase(name, num_threads, setup, body)` helper halves the file, removes the three "see contention/push_pop's identical comment" pointers (`:459`, `:479`, `:515`), and fixes clippy's 223-line-`main` warning. `scripts/tis_p3_ab/harness_bin.rs:100-179` is a third copy; it lives in a standalone scratch crate so it cannot share code, but it can shrink once the bench has a reference shape to copy from.

**2.5 [confident on simpler; second look on whether wanted] 130 lines of panic-hook machinery guard one assertion.** `tests/stack_unit.rs:234-364`: `HOOK_SERIALIZE`, `RestorePanicHook`, a chaining wrapper, and a thread-id filter exist so that ONE test (`width_16_push_rejects_index_mask_itself`) can read the panic `Location` while libtest runs sibling tests in parallel. `tests/threaded_conservation.rs:112-114` already uses — and names — the simpler alternative: a one-`#[test]` binary needs no serialization. Move that single test to its own file (`tests/push_guard_track_caller.rs`) and the entire rig collapses to `take_hook`/`set_hook`/restore (~15 lines). Cost: one more test binary; see §6.1 for the offsetting merge.

**2.6 [confident, cosmetic] Wrong mechanism claimed in the bridge-impl comment.** `src/imp.rs:1159-1160`: "Fully-qualified calls below avoid infinite recursion into this very impl." Inside `impl<S: StackStorage<B>> SealedStorage<B> for S`, a bare `self.head()` would not recurse — both traits are in scope in that module and both apply to `S`, so it is an E0034 "multiple applicable items in scope" error. The fully-qualified form disambiguates; it does not break a loop.

**2.7 [confident, cosmetic] Misplaced comments.** `//` explanations wedged between `#[track_caller]` and `pub fn` (`src/imp.rs:1499-1503`, `:1515-1519`); `///` doc on `const _: () = assert!(...)` (`:66-70`) that rustdoc never renders — both should be `//` above the attribute.

**2.8 [second look] `Cargo.toml` carries 70+ lines of comment in a 131-line manifest,** including review identifiers (`:5`, `:64-65`, `:113`). `cargo package` ships the commented file as `Cargo.toml.orig`. The MSRV rationale (`:5-27`) duplicates README `:263-271` and CHANGELOG `:393-405`; one pointer would do.

**2.9 [checked, no finding]** `unwrap()`/`expect()` usage: every instance in `src/` is absent (there are none); in tests/benches/examples each `expect` documents an invariant that is asserted earlier in the same file (e.g. `benches/...:434-437` before `:464`). Dead code: none found; `#[cfg(any(feature = "test-internals", loom))]` gating is consistent across all nine sites. Naming: consistent (`*_for_test`, `*_impl`, `*_out_of_range`); `idx_v`/`cur_idx` in the two loops are the only terse names and are local.

## 3. Bugs

**[checked, no finding]** — stated explicitly, with what was examined:

- **Unsafe inventory:** exactly one `unsafe` keyword (`src/imp.rs:943`) under exactly one item-level allow (`:934`); `#![deny(unsafe_code)]` at `src/lib.rs:292`; zero `unsafe` blocks/fns anywhere in the crate including tests, benches, examples, scripts. Matches the ADR and the "Where unsafe lives" section.
- **Tag wrap arithmetic:** `tag.wrapping_add(1)` at `2^TAG_BITS - 1` yields `2^TAG_BITS`; `pack_truncating`'s `tag << INDEX_BITS` then overflows the *value* (not the shift amount), which Rust discards silently in both debug and release — the documented wrap-to-0. `tests/stack_unit.rs:169-191` and `tests/regression_counter_wrap.rs:80-95` pin the boundary; `proptest_pack_unpack.rs:115-134` pins the width-1 `1u64 << 63` edge.
- **Self-loop detector false positives under contract-abiding contention:** a link `X -> X` can only be written by `push(X)` while `head == X`, i.e. while `X` is simultaneously live in the stack and held by the pusher — a caller-contract violation by definition. A stale `load_next(X)` by a popper that read `X` as head before another thread popped it sees whatever the last contract-abiding push stored (`TAIL` or a different live index), so neither guard arm fires and the CAS fails as designed. CHANGELOG `:348-351`'s 1,670,492-call zero-self-loop audit agrees.
- **Guard precedence:** `(next as u64 & mask)` at `src/imp.rs:1425` parses as `(next as u64) & mask` — correct.
- **Width-1 degenerate case:** `INDEX_MASK == 1`, sole valid index 0, `push(1)` panics on the range guard; exercised by `tests/stack_unit.rs:517-526`.
- **Reachable panics from safe code:** exactly the three documented ones — push range guard, pop rule-4 guard, `ArrayLinks` bounds (`index >= N`) — each with a test. `ArrayIndexStack::<16, 4>::push(5)` panicking on the links bound before the stack bound is documented (`:1037-1043`) and tested (`stack_unit.rs:391-394`).
- **`index as usize`** in `ArrayLinks` is lossless on every `target_has_atomic = "64"` target.
- **Loom aliasing:** under `--cfg loom` the retry/backoff counters deliberately stay `core` atomics (`:1699-1700`) so they survive loom re-runs; `Ordering` is loom's re-export of `core`'s, so test code passing `core::sync::atomic::Ordering` type-checks.
- **Release-sequence invariant** on `StackHead::head` (`:290-313`): every writer is an RMW (both CASes, `cas_head_for_test`); `new` is initialization; `raw_head`/`is_empty` only load. Holds.

## 4. Neuroslop

**4.1 [confident — the most important finding in this report] Two parallel five-item lists, both cited as "rule N", with different content under the same numbers.** The `StackStorage` doc has `# Safety` clauses 1–5 (`src/imp.rs:447-467`: one binding per head / one backing consistently / disjoint reachable populations / valid answers from dedicated cells / same head every call) and then, under "# The binding: what is structural, what is not", a second numbered list 1–5 (`:553-727`: one backing + one live value / stable index↔cell mapping / coherence + reachability clause / `load_next` returns TAIL-or-valid / backing lifetime). Cross-references throughout the crate — "rule 3's binding-level clause", "rule 4's release-active guard", "rule 1's completeness note" (`:269`, `:537`, `:563`, `:627`, `:668`, `:686`, `:693`, `:767`, `:777`, `:806`, `:827`, `:999`; README `:59`, `:63`; `tests/custom_storage_impl.rs:162`, `:187`, `:323`, `:419`, `:477`, `:481`) — mostly mean the SECOND list. The tests already have to translate: `tests/custom_storage_impl.rs:283-284` says "clause 2 — the coherence obligation the explanatory rules list as rule 3". For an `unsafe trait`, the `# Safety` list is the normative text an implementor must uphold; a second differently-numbered "rules" list beneath it (which `:469-471` calls an "explanatory appendix") undermines exactly the clarity the `unsafe` conversion was meant to buy. Fix: keep ONE numbered list (`# Safety`), rewrite the appendix as un-numbered prose keyed to the Safety clause numbers, and update every "rule N" citation to "clause N".

**4.2 [confident] Volume and register.** `src/imp.rs`: 1822 lines, 413 code, 1348 comment (77%); `src/lib.rs`: 332 lines, 305 comment (91%); the `StackStorage` trait doc is 510 lines (`:424-933`); `BACKOFF_SPIN_CAP` gets 30 lines of doc for `= 6`. ## 6. Non-optimalities

**6.1 [second look] Twelve integration-test binaries for one small crate.** Five compile-fail drivers are five binaries whose tests are already process-isolated child builds; they could be one file with six `#[test]`s. `tests/regression_counter_wrap.rs` (2 tests) overlaps `tests/stack_unit.rs`'s `TaggedIndex` section — its own module doc (`:3-8`) says two duplicates were already removed; the remaining two belong in `stack_unit.rs`. Net with §2.5's split: fewer binaries, less link time, and the hook rig disappears.
