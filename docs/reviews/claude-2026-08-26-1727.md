- `tests/builder.rs:369–371` (шапка `min_step_fallback_overflow_panics…`): «`growth.0 == 0` is a **docs-blessed** valid scheme **(see `build_table`'s own doc comment)** whose EVERY advance step goes through this exact fallback».

Факт: rustdoc `build_table` (`lib.rs:180–204`) не содержит ни слова про `growth.0`/нулевой числитель — ни в Spacing-абзаце, ни в `# Panics` (там только «if `params.growth.1` (the growth denominator) is `0`»; молчание списка паник — импликация «не паникует», не блессирование «intentional valid scheme»). Единственное место, где схема действительно объявлена валидной — **обычный `//`-комментарий** task #731 внутри тела функции (`lib.rs:213–221`: «…is an intentional (if unusual) valid scheme, not a contract violation»), невидимый на docs.rs. Проверено git-историей: уже в `ab269a5` — коммите, НАПИСАВШЕМ обе формулировки — rustdoc блессирования не содержал (`git show ab269a5:…lib.rs`), то есть это не устаревание после переноса, а изначальная подмена поверхности («rustdoc»/«doc comment» вместо inline-комментария). Grep десяти предыдущих отчётов («bless», «growth.0», «linear»): ни разу не адъюдицировано.
Почему дефект: тот же класс, что run-9/run-10 F1 (неверная атрибуция места, где живёт факт), в одном отношении сильнее — читатель, следующий указателю в опубликованные docs.rs-доки, вообще не найдёт заявленного утверждения, а претензия «this crate's own docs bless as valid» не верифицируема из published-doc-поверхности крейта. Семантика самого утверждения верна (деградация к линейной таблице подтверждена по коду, см. §2), паника денominatorа задокументирована корректно.
Вес — P4: ни кода, ни контракта, ни panic-поведения не касается; чистая перекрёстная ссылка в internal-комментарии и тестовой шапке.
Фикс (любой из двух, второй предпочтительнее для публикуемого крейта): (а) переадресовать оба указателя на реальное место («see the `growth.1` assert's comment in this function's body»); (б) поднять блессирование в сам rustdoc `build_table` — одна фраза в Spacing-абзаце вида «a zero growth numerator is valid: every step degrades to the `min_block` minimum step, yielding a linear table» — тогда оба существующих указателя становятся верными как написаны, а docs.rs-читатель получает утверждение, на которое они ссылаются.
