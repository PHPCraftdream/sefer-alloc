# R10 P3: owner-visible active-kind index advice

Date: 2026-09-30 CEST. Source inspected at `a40f8554e388bcabe1770c076ed041a770b01d53` on `advice/src-r10-active-index-20260930`. Scope is only the historical-high-water hot scans in `docs/reviews/2026-09-30-192803-src-review-xs-sol-round-10.md`. This is design advice, not an implementation, test result, release gate, or measured speedup. No source edits, builds, tests, benchmarks, project scripts, version changes, or mutating git commands were performed.

## Decision

Use an exact, owner-only, per-`SegmentTable` active-kind index: two 64-word `u64` leaf bitsets (Small including Primordial, and Large), each with one `u64` nonempty-word summary. Store the 1,040-byte plain-data index in the primordial metadata window, not inline in every `AllocCore`/`HeapSlot` and not in a producer-visible route descriptor. Add only a pointer to it in `SegmentTable`, or derive its address from the existing primordial `slots` pointer if the measured `HeapSlot` stride increase is unacceptable. Prefer the explicit pointer first for simpler provenance and test-harness contracts. After pre-publication bootstrap, all reads/writes are under the existing exclusive owner, maintenance lease, or fallback lock; no atomic bitset, foreign-free RMW, global lock, dirty flag, queue, or notification is needed.

Use active-Large only for `drain_large_sidecar_ingress` (including Large alloc, Small magazine refill, zeroed, batch, and realloc call sites). Use active-Small/Primordial only for the guarded linear fallback in `find_segment_with_free_impl`, including routed negative-directory, forced rescue, non-materialized-directory, and no-directory modes. Do not change the directory-positive validation or its NUMA preference. Do not change `drain_sidecar_ingress`, `drain_sidecar_ingress_bounded`, `trim_for_recycle`, TLS exit, re-claim trim, or the background cursor in this P3 change: their high-water walks are cold, bounded/complete recovery paths and are the independent safety net. The index is an enumeration accelerator, not a new terminal-publication or lifetime authority.

## Source facts that constrain the design

- `src/alloc_core/segment/segment_table/segment_table_impl.rs`: `MAX_SEGMENTS=4096`; slot 0 is a non-recyclable Primordial segment; `count` grows on append and is never decremented; `unregister`/`recycle` null slots and push their indices onto the primordial free-list; `register_payload` prepares the fallible route before popping/appending; `RouteSlots` is System-allocated; own-cache and hash eviction are co-located with removal. `unregister` has a routed corrupted-id fallback and standalone defensive no-op; `recycle` checks hash membership before reading a possibly unmapped header and has a corrupted-id fallback. Keep those defensive outcomes and update the index only on an actual slot transition.
- `src/alloc_core/alloc_core/sidecar_drain.rs`: the Large-only hot scan currently probes every `[0,count)` slot, including NULL and Small. The strict pass fixes `count` at entry and cuts every live Small word; the bounded pass persists `(slot,word)` and charges each inspection/cut. Removing the hot loop must not remove or reinterpret either cold pass.
- `src/alloc_core/small/alloc_core_small/find_segment.rs`: routed negative directory lookups deliberately do not trust the negative and scan all registered Small/Primordial roots. The scan can recycle its current candidate while walking, so an iterator holding a table borrow or a pre-collected root array is inappropriate. NUMA mode retains a foreign fallback and validates it before return.
- `src/alloc_core/small/alloc_core_small_pool/alloc_core_small_pool_impl.rs`: pooled empty Small segments remain registered, committed, and usable; release, decay, drain, and current-cursor trim call `table.recycle`. A pool member must keep its active-Small bit. `src/alloc_core/alloc_core/mem/mem_impl.rs` and `src/alloc_core/large/alloc_core_large.rs` unregister Large on both cache-deposit and release legs; cached reservations are not active routes and must have no active-Large bit. Reissue registers a fresh route incarnation.
- `src/registry/heap_registry/claim.rs`, `src/registry/heap_core/state/ownership.rs`, and `src/global/fallback.rs`: claim/maintenance/fallback serialize owner mutation. A recycled heap slot retains its materialized `HeapCore`; a new claimer trims under the winning lease rather than constructing a fresh table. The bitset therefore persists across heap-slot recycle/claim and must not be reset there.
- `docs/REMOTE_FREE_SIDECAR_REVISION_2026-09-29.md`, `docs/ARCHITECTURE.md`, and `src/registry/segment_route/`: foreign Small publication ends at sidecar `fetch_or`; Large ends at `LIVE -> PENDING`; a producer pin can outlive the reservation but an outstanding issue credit prevents premature release. Route unlink closes new pin admission. These obligations stay unchanged. The source review's P3 is an operation-count claim, not a latency measurement; README's current terminal-sidecar acceptance is still pending.

## Exact representation and traversal contract

Let `S[i]` mean slot `i` is non-NULL and registered with kind Small or Primordial, and `L[i]` mean it is non-NULL and registered with kind Large. At every owner-observable method boundary:

1. For `0 <= i < count <= 4096`, exactly one of `S[i]`/`L[i]` is set iff the slot is live; neither is set for NULL slots or `i >= count`. In particular `S[0]=1`, `L[0]=0`, and slot 0 is never cleared. `Unknown` is not a registrable kind; reject it before any slot/free-list change. Primordial is seeded by bootstrap, never registered again.
2. For each kind and word `w`, summary bit `w` is set iff leaf word `w` is nonzero. A 0-to-nonzero leaf transition sets its summary bit; a nonzero-to-0 transition clears it. Kind changes are clear-old then set-new through a real unregister/recycle and register, never by relabeling an in-use reservation.
3. The index contains numeric slot positions only. It never contains a root pointer, route handle, class bit, pending bit, borrowed `RouteScan`, or credit. A selected position is resolved with a fresh `table.base_at(i)` and checked non-NULL before any header/sidecar dereference. A kind mismatch is an invariant failure, not permission to silently skip a possible pending free.

A private `next_active(kind, from)` returns the least set index at or above `from`. Guard `from >= 4096` before arithmetic, mask the starting leaf word, and if empty mask the top summary above that word and use `trailing_zeros` to jump to the next nonempty leaf. Guard the `word+1 == 64` case before shifting: shifting a `u64` by 64 is invalid. Read the leaf/summary by value in each call; do not return an iterator borrowing the index across `&mut self` reclaim. A hot loop sets `from = i + 1` before calling anything that may unregister/recycle `i`, then asks for the next position after the call. It must not retain a stale leaf-word snapshot or advance a dense-array position after swap-removal. The scan may stop at its existing first Small hit; Large visits all active Large positions. Bound results to the entry `count` and re-read `base_at` for each selected slot. No registration is reachable inside these current scan bodies; if that ceases to hold, newly inserted earlier positions wait until the next scan, and strict/high-water maintenance remains complete.

`A_L` and `A_S` denote the entry counts of active Large and active Small/Primordial routes, not `count` or the number of pending frees. The candidate/route-slot inspections become at most `A_L` for a Large-only hot pass and at most `A_S` for a Small fallback (possibly fewer on a hit), with O(1) leaf/summary work per selected candidate and a fixed-size summary. With this fixed 4096-slot geometry, even an empty kind costs O(1), independent of historical `H=count`. This is an operation-complexity statement only. A Small candidate can still cost up to its issued-word high-water to cut; directory word scans, OS work, cache work, and the retained strict/background O(H) walks are outside that bound. Do not call the whole allocation O(A) or claim nanoseconds/RSS saved without measurement.

NUMA fallback should retain a slot number rather than an unborrowed raw root. Before finalizing it, re-read `base_at(slot)` and recheck kind, class free-list head, node preference, and pool membership on that *current stored root*; if gone, continue/return `None` as the existing path does. This new enumeration retains no raw root or bitset snapshot across a call, lease, or reservation release. Route incarnation and Large generation already distinguish actual reissues; the new index does not need a second generation because it holds no cross-call handle. If future code persists active-index cursors across calls, it must add an incarnation check or retain the present wrap-and-revalidate semantics, not treat a reused slot number as the old reservation.

## Lifetime, ordering, fairness, and rollback proof obligations

- Registration is prepare-then-commit. `RouteSlots::prepare` and its System allocations may fail before a slot is popped, count increments, hash is inserted, or any active bit is set. On success, set the matching active bit in the same owner-only `register_payload` transaction after the slot/hash/route handle have been installed and before return/user issue. Fresh Small/Large callers currently initialize the header *after* `register_payload` returns; the passed kind, not an uninitialized header read, selects the bit. No owner scan, callback, or user issue may interleave with that caller-side header initialization. The caller's `None` branch releases its still-owned OS reservation with no index change. A directory sidecar materialization failure after a successful Small registration is *not* registration rollback: the Small route remains active and the directory is simply unavailable.
- Removal is consume/close-then-retire. For Large, a legal own-thread claim or descriptor `PENDING -> CONSUMING` claim precedes `unregister`; clear the bit in that same method after the actual slot has been resolved and route admission closed, before the reservation is cached or released. For Small, credit zero and non-Primordial eligibility precede `recycle`; pooled segments never call it. Clear only the resolved live slot's bit, then preserve the existing release-then-NULL-then-free-list-push sequence under the same exclusive owner operation. Defensive no-op/leak paths leave the bit untouched. No recoverable failure or callback may occur between these co-located table/index transitions; an internal impossible-state abort is not a successful rollback.
- A producer paused after pin but before terminal publication still owns an issue credit. Therefore its route and active bit cannot legally disappear. If the owner checks/cuts it first, its later `fetch_or` or `LIVE -> PENDING` leaves it in the same active kind for a later pass. A post-word-cut Small bit is not lost by the index; a Large publication after an earlier unsuccessful claim is likewise retried next pass. Clearing an *empty/clean* active bit would be wrong: active means registered, not dirty. Strict trim's pre-entry publications remain covered by its unchanged high-water/per-word cuts; later publications retain credits for another pass. An index update never occurs in a producer after its terminal operation, so terminal-last-access and descriptor-pin lifetime remain intact.
- Per-call ascending indices give deterministic visitation under current owner-only, no-register-during-scan bodies. Removal of the current index does not skip the next higher set bit. Reuse at the same index on a later call is seen from the newly set kind bit; it is never mistaken for an old sidecar because route incarnation and Large generation remain authoritative. A Small fallback may return at the first eligible segment and therefore does not promise to visit every later Small segment in that call, exactly as today. Strict trim and the existing round-robin `(slot,word)` background cursor provide completeness/eventual service under their existing lease/fair-scheduling assumptions. Keep the cursor numeric, budget-charged and independent of index snapshots: a reused earlier slot or a post-cut word is reached after wrap, while each visit remains bounded. No new wall-clock bound or ownerless guarantee without successful maintenance startup is inferred.
- Drop closes routes while primordial storage is mapped, releases cached Large reservations separately, walks registered `table.bases()` including slot 0, and releases primordial last (`src/alloc_core/alloc_core/lifecycle.rs`). The index is inert plain data and must never be read or dropped through its primordial pointer after that final release. `HeapRegistry::recycle` does not drop this table; claim preserves its bits and invokes the unchanged strict trim. Standalone `AllocCore::drop` remains quiescent by its existing non-shared contract.

There is no notification-overflow path to design. An owner-only exact membership index has capacity fixed by `MAX_SEGMENTS`; if a new registration cannot fit, the existing graceful registration failure runs *before* issue. A separate dirty queue/summary would add a producer RMW and overflow fallback, and a pre-terminal hint can be cleared by the owner before the actual terminal RMW (lost wake). A post-terminal hint would add work after the defined terminal last access and couple producers to owner metadata. Neither is needed merely to avoid ghost slots.

## Storage and integration plan

The index is `2 * 64 * 8 + 2 * 8 = 1040` bytes, with `u64` alignment. `src/alloc_core/segment/segment_header/segment_header_layout.rs` currently places `free_top` at a page boundary: the preceding registry (4096 pointers), hash (8192 pointers), and free-list (4096 `u32`) each occupy whole 4096-byte pages after `small_meta_end()`. Place the index after the 4-byte `free_top`, rounded to 8-byte alignment. Its end is 1048 bytes after that boundary, inside the same 4096-byte metadata page already covered by current `primordial_meta_end()`. Add compile-time checks for offsets, alignment, non-overlap, metadata end within `SEGMENT`, and real-page/lazy-initial-commit coverage; verify this arithmetic on supported pointer widths instead of assuming the page remains free after future layout edits. Explicitly initialize every leaf and summary word, including under Miri; seed Small bit 0. Do not rely on OS zero pages for initialized Rust metadata.

An inline 1040-byte `SegmentTable` field would be replicated inside each `HeapSlot` and each lazily materialized 64-slot registry chunk, potentially adding roughly 64 KiB per chunk and up to roughly 4 MiB over 4096 slots before alignment. The primordial-carved form costs one pointer per slot (or zero if derived from the existing slots pointer) and one 1040-byte region per actually constructed primordial heap. Check actual `size_of::<AllocCore>()`, `size_of::<HeapSlot>()`, and `RegistryChunk::CHUNK_SIZE` in the implementation's target feature sets: `repr(Rust)` may reorder/pad and `HeapSlot` has 64-byte alignment, so a source-level `+8` is not a measured stride delta. Carving, bitmap operations, and diagnostics must use the existing `Node`/OS/System seams, never `Vec`, `Box`, or the installed `GlobalAlloc` on allocator paths.

## Deterministic acceptance witnesses for the implementing change

1. In `production internals bench-internals` with a pointer-free, per-operation inspection counter placed **before every attempted `base_at`/route-slot probe**, materialize 127 simultaneously live Large allocations plus Primordial (`table.count()==128`), keep the Large at slot 127, free the other 126, and disable cache admission with `budget_bytes(0)` or explicitly account for unregistered cached entries. One next `HeapCore::alloc` Large call with no pending remote free must inspect exactly one active Large route, not 128 slots. In a separate reset of that setup (or after freeing the just-allocated Large), a genuine first Small magazine miss must make the Large-drain inspect one active Large route; assert the miss/refill path was actually taken. A reverted `[0,count)` loop must make this counter read 128, so counting only non-NULL successes after `base_at` is an invalid oracle. This is one bounded 512 MiB *virtual segment-span* fixture (128 x 4 MiB including Primordial), with only needed metadata/user bytes touched; never create 4096 segments or a fake multi-GiB load. If even this virtual reservation is unsuitable for a runner, use a pure logical H=128 table/index fixture that never dereferences synthetic roots for the structural counter and a 2-3-segment real routed integration case, reporting the two coverage layers separately.
2. For routed negative-directory fallback, first force actual directory materialization by registering a Small segment after the historical Large churn (the sidecar materialization hook is in Small reserve, not Large reserve). Request a never-used class with no directory bit. Assert the routed negative really enters fallback and its probe counter equals the *current* Small/Primordial count (normally 2 in this compact setup), not H; preserve `None` and later real-hit/self-heal behavior. Repeat with `numa-aware` local/unknown/foreign candidates and with a forced rescue. A test that simply calls the bitmap helper or never takes the negative branch is not evidence.
3. Exercise transitions at indices 0, 63, 64, and 127 in a reduced-geometry model, plus index 4095 in a table-only boundary fixture: append, NULL, free-list reuse, Small-to-Large and Large-to-Small reuse, last bit in a leaf removed/reinserted, empty summary, and high-water unchanged. In a small real routed case, disable Small pool when release is required, assert pooled Small stays active, assert cached Large is inactive, and assert new route incarnation on reuse. After every operation compare both kind bitsets/summaries against a *separate cold census* over table slots; a duplicate/missing bit must fail. Do not use the index itself as its oracle.
4. Pause a foreign producer after route pin but before terminal publication using a barrier, let an owner hot pass find no pending work, then publish and prove the next pass claims/reclaims exactly once. Cover Small after its word cut and Large after a failed `PENDING` claim; include a last-outstanding-Small-credit case without a sentinel so premature recycle would be exposed. Keep old pin/new route incarnation separate during same-slot reuse. A mutant that clears a clean active bit must fail these tests. No sleeps, wall-clock assertion, or producer access to the reservation after terminal publication.
5. Inject `RouteDirectory` registration failure before both append and free-list reuse. Assert `None`/null, no count/free-list/index mutation, caller reservation release, then a successful retry reusing the expected slot. Also cover primordial owner-attach failure and `AllocCore` drop without reading the freed index. Use existing `internals` failure injection with no intervening same-thread allocator call that could consume it. Keep these cases separate from capacity-exhaustion tests; do not allocate 4096 real segments just to test an OOM branch.
6. Keep the existing strict trim, TLS exit, recycled-slot claim, fallback lock, and bounded-background cursor cases as regression controls. Verify strict pre-entry publications are consumed in that pass; post-cut publications in a later pass; bounded visits charge at most their budget and wrap to reused earlier slots. The high-water cold scan must remain observable so an implementation cannot quietly replace completeness with a potentially stale active/dirty summary.

The existing `tests/loom_sidecar_bitmap.rs`, `tests/loom_terminal_large.rs`, and `tests/loom_terminal_owner_drain.rs` model terminal word/phase/credit operations, not active-kind index maintenance, registration rollback, or mutation-safe enumeration. `tests/r6_terminal_owner_drain_model.rs` demonstrates a post-cut word, and `tests/r9_bounded_background_maintenance.rs` tests the old numeric cursor, reuse, and a negative pre-terminal hint; neither proves the new index is exact or that the actual hot loops avoid NULL probes. Add a reduced Loom composition with owner registration/removal/claim under a modeled exclusive lease and concurrent terminal publisher, asserting that an outstanding credit keeps membership until the owner can consume it; include the clean-bit-clearing negative mutant. Plain owner bitset accesses are intentionally non-atomic and must not be moved into producer code merely to satisfy Loom. Miri should run small actual-index bootstrap/register/recycle/drop and candidate-removal tests under the relevant borrow models, particularly primordial pointer alignment/initialization, short-lived `Node` accesses, no table/route borrow across decommit, and no read after primordial release. Re-run the targeted M5 counter test in `tests/alloc_core_reentrancy.rs` over index churn: `Node`/self-hosted metadata must add zero installed-`GlobalAlloc` calls. Include a focused metadata-layout check for eager/lazy primordial bootstrap and supported page sizes. Loom cannot prove OS mapping/provenance, Miri cannot prove weak-memory interleavings or latency, and neither substitutes for a real `production` path counter witness or later measured perf/RSS acceptance.

Acceptance for this design is exact membership plus the candidate-count bound and unchanged reclaim behavior in targeted standalone `alloc-core`, minimal routed `alloc-global alloc-xthread`, `production`, `hardened`, `numa-aware`, and no-`alloc-decommit` configurations, with relevant Windows/Unix and Miri coverage. This names future verification cells, not runs performed here. Any runtime speedup remains an unmeasured hypothesis until a separate gate measures the actual `HeapCore`/`GlobalAlloc` workload, allocator footprint, and cold-sweep cost on the same pinned source/features/hardware. No P4 finding is addressed here.
