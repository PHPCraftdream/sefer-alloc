**F2 — «the clamped entry is an unreachable sentinel, not an observable answer»: хвост-клауза шире собственной области истинности; собственный тест крейта пинит противоположное для hand-built-режима.**

Что верно (и дважды адъюдицировано, runs 3/8): для всякого `SizeClasses` — истинно и структурно герметично: единственный конструктор `build` → `build_table` ⟹ `small_max` кратен `min_block` ⟹ максимальный in-range bucket = `(small_max−1)>>shift` = L−2; `class_for` bucket L−1 не читает никогда.
Не адъюдицированный остаток: та же дока строкой выше (`lib.rs:429–431`) явно благословляет standalone-использование с hand-built таблицей («`table` need not come from `build_table`») и предписывает индекс-рецепт `size2class[(size - 1) >> log2(min_block)]` (`:415–416`). Для hand-built таблицы, чей ПОСЛЕДНИЙ класс не кратен `min_block` (ровно форма review-2 F9), L = ⌊small_max/min_block⌋+1 и in-range размеры `((L−1)·min_block, small_max]` индексируют именно bucket L−1 — «sentinel» там ЕСТЬ наблюдаемый ответ. Собственный тест крейта существует ровно поэтому: `build_size2class_bucket_need_overflow_flips_the_release_answer_for_a_hand_built_table` (`tests/builder.rs:571–625`, таблица `[1<<62, 2<<62, (3<<62)+2, (3<<62)+5]`) ассертит `s2c[L−1] == N−1` с сообщением «top bucket must resolve to the last class, **not the pointer's pre-overflow position**» — т.е. трактует top-bucket-значение как несущий наблюдаемый ответ, чью release-подмену P2-1 и чинил. Дока называет это же значение «not an observable answer». Проверено и то, что хранимое значение в обоих режимах КОРРЕКТНО (кламп к последнему классу = верный ответ для всякого in-range need этого bucket'а; для размера ниже интерьерного некратного класса ответ может быть не наименьшим — но это уже задокументированный `[16, 24, 32]`-каveat `:429–437`).
