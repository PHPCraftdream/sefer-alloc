### P2-1. Невалидный realloc в self-check — открыт

Места: `crates/globalalloc-model/examples/perf_probe_p4_measurements.rs:190`,
`:208`, `:321`.

`layout32` имеет alignment 8, но следующий realloc получает
`new_size = isize::MAX`. Округление вверх даёт `isize::MAX + 1`.
GlobalAlloc::realloc требует, чтобы округлённый размер не превышал
isize::MAX; иначе вызов вне unsafe-контракта.
[Официальный контракт](https://doc.rust-lang.org/std/alloc/trait.GlobalAlloc.html#method.realloc).

CountingAlloc пересылает запрос в System без нормализации. Проверка null
после вызова не восстанавливает предусловие. `main` по-прежнему начинает
работу с этого self-check. Это не проблема самого `drive`: его realloc arm
в `src/drive.rs:547` ограничивает размер до
`(isize::MAX / align) * align`, то есть для alignment 8 — до MAX − 7.

Исправление: валидный align-зависимый размер; предпочтительнее управляемый
отказ backend на малом допустимом запросе для проверки accounting.
Рассчитывать на настоящий OOM как на переносимый deterministic fixture
не следует. Опасный вызов в этом ревью не выполнялся.

### P3-1. S3 расходится с настоящим TestRunner — открыт

Места: `crates/globalalloc-model/examples/perf_probe_p4_measurements.rs:585`,
`:667`, `:670`, `:693`.

После успешного complicate реальный runner сначала оценивает восстановленный
current и лишь затем решает, нужен ли simplify. S3 сразу возвращается к
безусловному simplify в начале следующей итерации. False от complicate
также не обрабатывается как немедленное завершение поиска.

Сохраняются оба дополнительных расхождения:

- `result` удерживает последний принятый Vec во время создания следующего
  candidate, изменяя peak-memory относительно runner без такой копии.
- 16384 названо default лимитом, тогда как proptest 1.11.0 без env overrides
  получает 1024 из default cases=256 и формулы `cases * 4`.

Счётчик complicates подтверждает вызовы метода, но не правильность
протокола. Нужен реальный `TestRunner::run_one` с явной конфигурацией либо
точное воспроизведение переходов и времени жизни значений. После исправления
требуется обновить относящиеся к S3 данные и выводы. Ошибки делегирования
`SizeValueTree::complicate` в рабочем генераторе не найдено.

### P4-1. Направление memory-выигрыша в CHANGELOG — открыто

Места: `crates/globalalloc-model/CHANGELOG.md:159`, `:173`;
`src/strategy.rs:124`, `:133`.

Для Single в S2 указаны enum 848124 B и boxed 464204 B, но написано
`enum smaller`: enum больше на 383920 B. Та же ошибка у Single/S3:
193091580 B против 192707730 B — enum больше на 383850 B.

Утверждение об одинаковых enum totals между configs в каждом сценарии
также не соответствует S3: 189749448 B и 193091580 B различны. Исправить
знаки и различать total/peak, default/Single. Это проверка внутренней
согласованности опубликованных чисел, не подтверждение их измерительной базы.

### P4-2. Изменение метрики выдано за run-to-run drift — открыто

Места: `crates/globalalloc-model/examples/perf_probe_p4_measurements.rs:108`,
`:126`, `:533`; `tests/size_strategy_avoids_boxed_value_trees.rs:75`;
`CHANGELOG.md:134`.

Probe теперь считает realloc отдельно от ALLOC_CALLS, а mean_allocs читает
только ALLOC_CALLS. Test wrapper без override realloc учитывает этот путь
через default alloc/dealloc. Исключение событий realloc меняет numerator,
поэтому абсолютную разницу 0.015 → 0.000 нельзя объяснять только шумом.

Определения метрики следует унифицировать или явно показывать alloc,
realloc и сумму. Сам paired gap около 0.75 и действующий порог 0.35 этим
замечанием не опровергаются.

### P4-3. Runtime lockfile не равен идентичности бинарника — открыто

Место: `crates/globalalloc-model/examples/perf_probe_p4_measurements.rs:235`.

Версии читаются относительно runtime cwd и могут относиться к другому
проекту/другому состоянию lockfile. Кроме того, `found` не очищается между
candidate files: proptest из одного файла может соединиться с arbitrary
из другого, а вся пара будет подписана последним путём.

Не объединять файлы. Для build identity связывать resolved metadata с
артефактом при сборке; иначе честно подписывать runtime lockfile snapshot.

### P4-4. Время current в S1 не измерено — открыто

Места: `crates/globalalloc-model/examples/perf_probe_p4_measurements.rs:626`,
`:632`, `:641`, `:785`.

Таймер new_tree заканчивается до current, walk начинается после него, drop
измеряет дерево отдельно. Материализация и освобождение возвращённого Vec
не попадают ни в одну timing column, хотя входят в memory-окно S1.
Нужен current time и/или полный elapsed S1; сумма нынешних колонок не
показывает время полного успешного case.

## Общий обзор и возможности улучшения

Дополнительный проход не выявил оснований открывать новые задачи по этим
частям ядра:

- Валидация alignment предшествует делению/clamp. Размер 0 нормализуется до
  1, верхний предел согласован с Layout. Modulo индекса применяется только
  при непустой live-модели.
- Новые указатели проверяются на null, alignment и overlap до доступа.
  Успешный realloc использует новый указатель и обновляет размер/layout;
  null сохраняет старую запись. Сужение не скрывает повреждённый suffix:
  сначала проверяется весь старый блок.
- Перед dealloc и каждым teardown free сохранены проверки fill. Утечки
  после oracle panic документированы; безусловный Drop подозрительных
  указателей не является безопасной заменой этой политики.
- RawAllocator отделяет диагностируемые значения от обязательных extent,
  provenance, initializedness и liveness. M2 требует unsafe token и не
  разрешён для обычного blanket GlobalAlloc.
- Full-width веса arbitrary помещаются в u64; zero-weight arm proptest
  удалён структурно. Exponent mapping остаётся в допустимом диапазоне.
  SizeValueTree правильно делегирует current/simplify/complicate.
- Lockstep-тест сравнивает bool и current после backoff и имеет activation
  floors. Этот контроль генератора полезен, но не доказывает правильность
  отдельного измерительного S3. Static introspection остаётся без создания
  стратегий и доступна только при proptest+internals.
- Точный docsrs feature set, package/consumer проверки, i686, MSRV,
  bare-metal, release-profile и Miri wiring сохранены. Наличие команд в CI
  не является их свежим успешным прогоном; сборка example не исполняет main.

Стоимость драйвера остаётся **O(M + MK + B)**, худшая **O(M² + B)**;
память модели **O(K)**, prepass **O(M)**. M — число операций, K — peak live
count, B — суммарная байтовая работа. Снижение overlap complexity имеет
смысл под реальную длинную нагрузку; нынешний read-only проход не даёт
измеренного основания добавлять ordered index.

Для копирований/аллокаций наиболее полезен следующий практический шаг:
исправить S3 и timing current, затем сравнивать конкретные lifecycle-сценарии.
Нельзя выбирать представление только по alloc count: inline enum уменьшает
число size-Box, но оплачивает большой stride Vec на всех операциях, в том
числе при отключённом weighted arm. Старые performance trade-off не
добавляются к числу новых замечаний этого раунда.
