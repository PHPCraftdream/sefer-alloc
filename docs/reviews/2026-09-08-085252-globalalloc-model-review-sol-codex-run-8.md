### Почему исправление self-check принимается

`examples/perf_probe_p4_measurements.rs:154`, `:239`, `:279`.

CountingAlloc стал generic по backend, но глобальный экземпляр продолжает
использовать System. Локальный self-check применяет RefuseMarked, который
возвращает null только на выделенном размере 4096 и не вызывает System
для этого запроса. Отказ проходит через обычный null-result accounting
CountingAlloc. В realloc-отказе backend не освобождает старый блок.

Положительные шаги 64 → 128 → 32 имеют согласованные layouts и ненулевые
размеры. На обоих отказах проверяются неизменные live/total/peak, затем
старый блок используется и освобождается. Это исправляет прежнее нарушение
unsafe-предусловия, не полагаясь на настоящий OOM машины.

### Почему исправление S3 принимается

`examples/perf_probe_p4_measurements.rs:812`, `:947`, `:968`.

Наблюдатели predicate хранят только числовые Cell, не Vec предыдущего
кандидата. Дерево потребляется run_one, итоговый TestError::Fail обрабатывается
сразу; текущая схема больше не навязывает неправильный переход после
complicate. Ok и Abort не принимаются за измеренный успешный shrink.
При этом runtime-настройки, наследуемые от Default, ещё можно сделать
строже для воспроизводимости — это отдельный P4, описанный ниже.

## P4-1. Для измерительного S3 стоит явно отключить внешний time budget

Места: `crates/globalalloc-model/examples/perf_probe_p4_measurements.rs:812`,
`:989`, `:1107`, `:1144`.

runner_s3 фиксирует seed, отсутствие persistence и лимит итераций, но
наследует max_shrink_time, RNG algorithm и verbosity из
`ProptestConfig::default()`. В частности, `PROPTEST_MAX_SHRINK_TIME` может
включить остановку по времени независимо от заданных 65536 итераций.
[Документация Config](https://docs.rs/proptest/1.11.0/proptest/test_runner/struct.Config.html#structfield.max_shrink_time).

При такой остановке proptest может вернуть тот же TestError::Fail с
лучшим найденным значением. `cap_truncated = steps > limit` наблюдает
итерационную границу, не time budget; ноль в этой колонке не доказывает,
что поиск завершился естественно. Две стороны A/B при ограничении по
времени могут пройти разный объём работы. Сам runner ведёт себя корректно:
это настройка/интерпретация измерения, не регресс его протокола.

Неблокирующее улучшение: для воспроизводимых S3 явно задать
`max_shrink_time = 0`, выбрать/напечатать RNG algorithm и исключить
измерительную verbose-нагрузку. Либо учитывать и явно сообщать причину
ранней остановки. Обычный default max_shrink_time уже равен нулю; в этом
ревью не установлено, что опубликованные автором прогоны были усечены.
Поэтому это не основание отвергать их результаты или возвращать прежний
P3 к уже исправленному runner-протоколу.

## P4-2. Self-check можно усилить проверкой положительных приростов TOTAL_BYTES

Места: `crates/globalalloc-model/examples/perf_probe_p4_measurements.rs:279`,
`:295`, `:319`, `:370`.

Сейчас положительные alloc/grow/shrink проверяются по LIVE_BYTES. Для
TOTAL_BYTES self-check проверяет лишь отсутствие изменения на отказах.
Если, например, из успешного realloc удалить `TOTAL_BYTES.fetch_add`,
положительные live-assertions и последующие сравнения unchanged total
останутся верными. Ошибки в текущем прибавлении не найдено; это пробел
защиты от его будущего регресса.

Можно сохранить total baseline до первого запроса и проверить приращения
**64, затем 192, затем 224 байта** по принятой full-request семантике
(64 + 128 + 32), отсутствие изменений на обоих отказах и при dealloc.
Так бухгалтерия cumulative bytes получит такой же прямой контроль, как
live bytes. Это небольшой самостоятельный тестовый hardening, не новый
дефект подсчёта в текущем коде.

## Общий обзор и производительность

- **Безопасность драйвера.** Null/alignment/overlap проверяются до доступа
  к новому диапазону. Clamping согласован с Layout, индексы берутся modulo
  только при непустой модели. Realloc не использует старый указатель после
  успеха; null сохраняет его запись. Перед shrink проверяется весь old
  block, а перед каждым teardown free — ещё живой survivor.
- **Контракты.** RawAllocator требует extent/provenance/initializedness/
  liveness и отсутствие racing access. M2 off-by-default и требует unsafe
  token, не разрешённый для blanket GlobalAlloc. Документированная политика
  не освобождать подозрительные указатели после panic обоснована.
- **Генераторы.** Config проверяется до генерации, веса arbitrary суммируются
  в u64, size draw отделён от выбора arm. Zero-weight proptest arm отсутствует
  структурно. Методы enum ValueTree делегируют нужным вариантам; статическая
  introspection не создаёт стратегии. Нового изменения алгоритма в этих
  коммитах нет.
- **Регрессионные оракулы.** Allocation guard сохраняет отрицательный boxed
  контроль и общий lock. Lockstep проверяет bool/current после backoff,
  включает оба Single режима и activation floors. Его ограниченный prefix
  не выдаётся за исчерпывающую проверку всех деревьев.
- **Сложность и память.** Драйвер остаётся O(M + MK + B), в худшем случае
  O(M² + B), с O(K) памятью модели и O(M) prepass. Усложнять overlap index
  без подходящей нагрузки не требуется. Цена больших inline ValueTree
  остаётся реальным компромиссом; отсутствие отдельной expected-payload
  копии у драйвера сохраняется.
- **Корректность performance-пояснений.** Знаки дельт в source/CHANGELOG
  теперь совпадают с числами: boxed меньше в S1 для обоих configs и во всех
  Single-сценариях; enum меньше в S2/S3 при default Config. S3 totals между
  configs не объявлены одинаковыми. Устаревшие wall-clock коэффициенты
  отозваны. Арифметика сверена; сами замеры не повторены.
- **CI и публикация.** Feature/package/consumer/i686/MSRV/bare-metal/
  release-profile/Miri wiring не изменилось. Exact docsrs combination
  соответствует metadata; отдельный release guard остаётся. Counting test
  под Miri исключён, и его native assertions не следует считать Miri-доказанными.
  В этом проходе статус удалённых запусков не подтверждался.

Практический приоритет дальнейших ускорений — работать по исправленным
раздельным сценариям и смотреть одновременно calls, reallocs, bytes и
стоимость current. Само по себе уменьшение числа Box не означает меньшую
память. Нового обязательного performance-refactor перед публикацией по
этому статическому проходу не требуется.
