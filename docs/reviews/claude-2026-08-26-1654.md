`git log -L` по обоим регионам: единственный коммит — `8529c0f` (08-06); `b970f52` (P2-2) обновил rustdoc/CHANGELOG, но не inline-комментарии; `b433b0b` — только field-doc. Три экземпляра, один корень, один фикс-коммит закрывает все:
- **(a)** `lib.rs:248–249` (комментарий per-entry-проверок в `build_table`): «Checked here — not just at the merged-table level in `build_size2class` — because …». На момент написания merged-table-уровень действительно жил только в `build_size2class`; после `b970f52` первичная merged-table-проверка стоит в САМОМ `build_table`, ~130 строк ниже в той же функции (`:387–399`). Обоснование клаузы (глобальная монотонность не ловит misaligned extra) остаётся верным — устарела только атрибуция «где живёт merged-table-уровень».
- **(b)** `lib.rs:454–459` (комментарий monotonicity-check'а в `build_size2class`), вторая клауза: «…and it is also exactly what catches `Params::extras` entries that overlap (or are otherwise misplaced relative to) the geometric run — … would otherwise leave the colliding slot silently unreachable». После `b970f52` extras-overlap структурно НЕ МОЖЕТ достичь этой проверки: любая таблица, пришедшая из `build_table` (единственный путь, где `Params::extras` вообще существует), уже прошла его собственный merged-check — паника случилась бы раньше, в `build_table`, с его собственным сообщением. Контрфактив «would otherwise» тоже более не верен (без ЭТОЙ проверки overlap всё равно пойман upstream). Клауза прямо противоречит комментарию `b970f52` в том же файле («closes the contract at its own function, not one layer downstream; … stays in place as defense-in-depth», `:383–386`), CHANGELOG (`:21–24`) и пост-`b433b0b` field-doc. Первая клауза («natural chokepoint … the monotone-pointer algorithm below depends on it») в роли standalone-валидации СВОЕГО входа остаётся верной — править нужно только вторую.
- **(c)** `lib.rs:463–466`, panic-сообщение: «table must be strictly increasing (check Params::extras for overlap with the geometric run)». Единственная оставшаяся достижимая аудитория этого assert'а — hand-built таблица, у которой `Params::extras` не существует вовсе; hint указывает на структурно невозможную причину (до `b970f52` он указывал на самую вероятную — тогда был точен). Первичная клауза сообщения точна и громка. NB для фикса: сообщение запинено `#[should_panic(expected = …)]` в `tests/builder.rs:255`, и его подстрока намеренно не пересекается с сообщением `build_table` (адъюдикация run 2) — при переформулировке сохранить непересечение и обновить пин.
Вес — P4: ни один экземпляр не создаёт silent-hazard (обе паники громкие и именованные в обоих контекстах; семантика кода верна и запинена тестами со всех сторон); направление ошибки — то же, что в run-9 F1: читателю internal-комментариев даётся mapping «overlap ловится в build_size2class», отменённый `b970f52`.

**F2 — CHANGELOG-буллет `class_for` описывает последствие нарушения pow2-align контракта как «a suboptimal class choice» — отстаёт на слово от собственной формулировки `lib.rs` («suboptimal/wrong») и на два режима от её же трёхрежимного перечня.**
Где: `CHANGELOG.md:64–66`: «`align` must be a power of two (the `Layout` contract), enforced by a `debug_assert!` (task #729) — a violation yields a suboptimal class choice, not memory unsafety».
История: `lib.rs` говорит «the failure mode is a suboptimal/wrong CLASS CHOICE … not memory unsafety or table corruption» (`:686–687`) с самого коммита task #729 (`5741243`); CHANGELOG при создании (`a968577`, task #1220) уронил «/wrong»; run-3 F2 (`5ffb85c`, task #1429) добавил в `lib.rs` третий режим (false-accept: `class_for(20, 24)` на SEFER возвращает block=32, `32 % 24 == 8`) и правил СОСЕДНЮЮ формулировку CHANGELOG (F4, const-eval), но «suboptimal» не тронул. Grep девяти отчётов: слово ни разу не адъюдицировалось.
Почему дефект: «a violation yields X» — определённое утверждение об исходе; из трёх задокументированных режимов `lib.rs` (`:670–682`) под «suboptimal» подпадает только overshoot; wrong `None` (уводит в large path при существующем подходящем классе) — не «choice» вовсе, а false-accept — возврат класса, НАРУШАЮЩЕГО задокументированный fit-предикат (`block_size % align == 0`), то есть «wrong», не «suboptimal». Ключевой контраст буллета («not memory unsafety») верен. Направление ошибки — занижение последствий контрактного нарушения в единственной поверхности, где читатель релиза видит сводку.
Вес — P4: касается только out-of-contract вызовов (Layout-производный `align` — pow2 by construction), debug_assert ловит в debug, режимы полностью и корректно расписаны в авторитетном rustdoc. Фикс — однострочная синхронизация: «a suboptimal or outright wrong class choice (or a wrong `None`), not memory unsafety».
