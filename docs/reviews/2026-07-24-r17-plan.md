# Round 17 — план по итогам внешнего ревью волн R14–R16

Дата: 2026-07-24. Ревью покрывает диапазон Round 14–16 (задачи #286–#317).
Вердикт ревью: «корректность — сильный прогресс; качество исследований —
сильный прогресс; default production performance — небольшой/не доказанный
общий прогресс; opt-in Large workloads — действительно крупные выигрыши».
Рекомендованный ревью порядок следующего раунда: сначала unsafe-sidecar +
bootstrap zero-loops + pad/cache root-cause, затем batched deferred reclaim
и единая adaptive Large policy.

Единственный call site (`SegmentDirectory::init_node_ids`) адаптировать | **P1** |

Крупные архитектурные направления ревью (единая adaptive Large policy,
page-run слой 256 KiB–2 MiB, ленивая chunked segment table) — НЕ заводятся
задачами этого раунда: каждое из них — многофазная работа уровня отдельной
волны, и по методологии ревью они идут ПОСЛЕ закрытия P1-очереди выше.
Зафиксированы здесь как бэклог направления для будущего планирования.

Процессные рекомендации ревью (перепиновка IAI baseline, сокращение
комментариев в hot-path файлах, политика raw-логов как CI artifacts,
профили вместо feature-комбинаторики) — учтены; из них только IAI-baseline
перепиновка достаточно механическая, чтобы войти в текущий раунд при
свободном ресурсе, остальное — материал для отдельного процессного забега.

**Порядок исполнения:** R17-1 → R17-2 → R17-3 → R17-5 → R17-6 (мелкие доки
можно объединить) → R17-4 (самое исследовательское из P1) → R17-7 → R17-8 →
R17-9 → R17-10. Методология прежняя: делегирование @sh, личная zero-trust
верификация каждого диффа, red/green counterfactual для soundness-фиксов,
коммит между задачами.
