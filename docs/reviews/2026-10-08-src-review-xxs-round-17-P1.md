## R17-UNS-01 — Безопасный decommit-наблюдатель разыменовывает provenance вызывающего

- **Исходный ID и severity:** `R17-UNS-01`, **P1**, unsafe/provenance-обзор §2. **Проверенный приоритет: P1, без изменения.** Категория: soundness безопасного публичного API за тестовыми/internal-фичами; не эксплойт в обычном `production`.
- **Диспозиция: CONFIRMED CURRENT.** Описанное историческим обзором тело функции остаётся в текущем дереве.
- **Текущее доказательство:** `src/alloc_core/small/alloc_core_small_pool/decommit.rs:19–36`, `AllocCore::dbg_is_decommitted_for`, — безопасный публичный метод под `internals` и `alloc-decommit`. Он выводит `base` из `ptr`, проверяет `contains_base_ro(base)`, затем через тот же caller-derived указатель вызывает `SegmentHeader::kind_at` и `SegmentMeta::new(...).is_decommitted()`.
- **Независимо проверенная цепочка:** `src/alloc_core/platform/os.rs:133–150` сохраняет, а не создаёт provenance посредством `map_addr`. `src/alloc_core/segment/segment_table/segment_table_impl.rs:764–807` превращает результат проверки членства в Boolean и прямо объясняет, почему совпадение адреса не даёт provenance; возвращаемый канонический указатель наблюдатель отбрасывает. `src/alloc_core/segment/segment_header/segment_header_views.rs:8–15` читает kind через `Node::offset`; `src/alloc_core/platform/node.rs:412–416` выполняет pointer `add`. Указатель без provenance, адресно совпавший с живым сегментом, может пройти проверку адреса и дойти до доступа к метаданным без provenance. Это вывод из pointer-операций, не утверждение о наблюдённом нативном падении.
- **Достижимость:** `AllocCore` реэкспортирован в корне (`src/lib.rs:511–512`); доступность его метода определяется гейтом самого метода, а не приватностью пути модуля. `production` исключает `internals` (`Cargo.toml:452–460`). Поэтому `production` и `production internals` нельзя смешивать при оценке экспозиции.
- **Владелец в индексах:** точная карточка этого оставшегося наблюдателя не найдена. Correctness **5/7/8/9** владеют более широким классом hook-safety residual, а не этим конкретным provenance-дефектом. Принятый P1-box **164** — другая проблема; он не переоткрывается и не учитывается второй раз.
- **Почему P1:** UB достижимо через безопасный публичный метод даже за `internals`; тестовая фича не разрешает безопасному методу разыменовывать произвольный provenance входа. P0 завысил бы экспозицию отгружаемого набора фич.
- **Нужный oracle, не запускался:** strict-provenance Miri-сценарий исходного обзора с указателем без provenance и тем же адресом, фичи `alloc-core alloc-decommit internals`. `scripts/miri.mjs:56` выбирает старую диагностическую регрессию без `alloc-decommit`; поиск по `.github/`, `scripts/`, `package.json` не нашёл проводки `r6_route_lifecycle_diag_provenance`. Это наблюдения о покрытии, не сообщение, что новый witness уже упал.

Соседний unsafe `dbg_force_decommit_retain_for` (`decommit.rs:93–108`) имеет тот же способ вывода указателя. Его контракт относится к `R17-UNS-03` в P4, а не образует второй safe-API P1.
