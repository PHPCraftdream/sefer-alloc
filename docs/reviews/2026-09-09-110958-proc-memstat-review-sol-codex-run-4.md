## Вердикт

**GO с неблокирующими замечаниями по статическому ревью библиотеки.**

**P0=0, P1=0, P2=0, P3=1, P4=2.**

Нового нарушения памяти, неправильного расчёта штатных counters или блокера
публикации уровня P0–P2 не обнаружено. Существенные замечания прошлого раунда
исправлены. Оставшееся P3 — переносимость новых файловых tests при не-UTF-8
временном каталоге; оно не затрагивает обычный runtime, читающий фиксированные
procfs-пути. Рекомендую исправить его ближайшей небольшой правкой, но не
приравниваю к прежнему P2, ломавшему сборку тестового пакета на PowerPC.

Этот GO означает результат чтения кода, **не подтверждение успешных native
tests, CI или публикации**. Исполняемые прогоны запрещены и не выполнялись;
состояние удалённого CI отдельно не проверялось. Возможности уменьшить аллокации перечислены отдельно, без
обещания неизмеренного ускорения.

## P3-1. Новые файловые tests требуют UTF-8 от системного временного пути

Места: `tests/status_read.rs:38`, `:64`, `:65`, `:83`, `:107`, `:131`;
`src/status_read.rs:36`.

`temp_path` возвращает PathBuf, а `write_temp` записывает файл через нормальный
Path API. Но перед вызовом acquisition seam тесты переводят пути в str через
`to_str().expect("utf-8 temp path")`. Сам seam принимает два `&str`, хотя его
операция — файловое чтение, не обработка Unicode-текста.

На Unix `temp_dir()` учитывает TMPDIR. Такой существующий и доступный для записи
каталог вправе иметь не-UTF-8 байты в имени. Это не предположение о кодировке
статистики: системные пути действительно имеют другой домен значений.
См. [std::env::temp_dir](https://doc.rust-lang.org/std/env/fn.temp_dir.html) и
[Path::to_str](https://doc.rust-lang.org/std/path/struct.Path.html#method.to_str).

Статический сценарий: TMPDIR указывает на доступный каталог, один компонент
имени которого содержит байт FF. Создание fixture через PathBuf допустимо,
но последующий `to_str()` даёт None, и `expect` паникует. Проверка падает до
вызова интересующей ветви fallback; в некоторых случаях fixture уже записан,
а находящийся после assertions remove_file не достигается. Каталог с таким
именем и процессы с изменённым окружением в этом ревью не создавались.

Исправление: принимать в закрытом `read_status_from` `&Path` либо подходящие
`AsRef<Path>` и передавать PathBuf/Path без преобразования в текст. Production
по-прежнему сможет использовать свои константные пути; public API не меняется.
`to_string_lossy` здесь не решение: замена байтов может назвать другой файл.
Регрессионный fixture должен проверять именно не-UTF-8 путь на Unix, а не
обычное кириллическое имя, которое вполне может быть корректным UTF-8.

Это P3 в тестовой инфраструктуре. Работу публичного snapshot на обычных procfs
путях TMPDIR не определяет, поэтому считать проблему runtime-блокером нельзя.

## P4-1. SKIP внутри дочернего non-UTF-8 теста не виден обычному runner

Места: `tests/non_utf8_name.rs:60`, `:63`, `:65`, `:124`.

На NotFound child печатает `SKIP: ...` через println и возвращает успех. Но:

1. Child запускается как libtest binary с `--exact`, без отключения capture.
   Вывод успешного `#[test]` по умолчанию скрывается harness.
2. Parent получает stdout/stderr через `Command::output`, но использует их
   только в сообщении неуспешного assert. При exit status 0 они отбрасываются.

Таким образом, при обычном запуске пользователь видит прошедший test, а не
обещанное объяснение пропуска. Даже показ stdout самого parent не возвращает
текст, уже скрытый внутри child. Capture успешных tests описан в
[Rust Book: Showing Function Output](https://doc.rust-lang.org/book/ch11-02-running-tests.html#showing-function-output).

Сделать результат child явно различимым для parent: отдельный SKIP-маркер/статус
и его доставка в доступный диагностический вывод или CI summary. Просто
добавить println в дочерний `#[test]` недостаточно. Не превращать legitimate
legacy skip обратно в failure и не отключать modern-kernel regression guard.

Это замечание о наблюдаемости покрытия. Ветка runtime-fallback корректна;
`thread_leader_exit` с собственным main не имеет этого же внутреннего libtest
capture и не требует аналогичного вывода из настоящего `#[test]`.

## P4-2. Служебные комментарии местами перестали соответствовать коду

Места: `src/status_parse.rs:35`; `tests/status_read.rs:9`, `:92`;
`CHANGELOG.md:105`.

- Объяснение allow(dead_code) на KibFieldLookup называет status_convert.rs и
  tests/status_parse.rs «both #[path] includers, invisible to the library».
  В production status_convert — обычный `mod`, непосредственно использующий
  этот enum; это видно в `src/lib.rs:296` и `src/status_convert.rs:27`.
  Обоснование для других test/example-компиляций может быть верным, но
  конкретная фраза про production consumer — нет.
- Вводная к status_read tests всё ещё перечисляет directory как инъекцию ошибки,
  хотя действующий тест использует путь с NUL; пояснение ниже уже правильно
  говорит, что directory был только рассмотренным вариантом.
- CHANGELOG описывает разделитель перед kB как «one ASCII whitespace», тогда
  как точная грамматика в parser допускает один ИЛИ БОЛЬШЕ пробельных байтов.
  Лучше сослаться на единую грамматику либо написать one-or-more.

Это не повод менять работающую логику. Сократить повторяющиеся истории до
короткого актуального объяснения; длинная история решения уже есть в отчётах
и git. Количество пояснений само по себе не даёт дополнительных гарантий,
если при правке приходится синхронизировать несколько копий факта.

## Общий обзор реализации

### Acquisition, parser и conversion

`read_status_from` читает primary; только NotFound запускает fallback, другая
ошибка возвращается без подмены. При успешном primary fallback не нужен.
Смена path-injected testability не вводит глобального состояния или кэша fd.
Код работает с полученными bytes, а не пытается валидировать UTF-8 всего status.

В parser первый соответствующий prefix определяет результат; эта семантика
сохранена. Числовой диапазон извлекается внутри границ среза; единица kB и
хвост проверяются. Decimal accumulation checked. Tri-state теперь сохраняет
разницу между отсутствием и ошибкой до conversion, где все три значения
масштабируются через checked multiply. Искусственные чрезмерные числа не могут
снова дать успешный optional None, как до предыдущего исправления.

Ошибка чтения отображается в Os, непригодное содержимое — в Malformed;
Unsupported остаётся отдельной ветвью stub. `snapshot()` — простой
`try_snapshot().unwrap_or_default()`, без другой логики чтения или конверсии.

### Unsafe и платформы

Windows output buffer соответствует base PROCESS_MEMORY_COUNTERS: два u32,
восемь SIZE_T, cb и проверка результата до чтения полей. Pseudo-handle не
требует закрытия. Mach buffer сохраняет нужные поля/offsets, 48 bytes и count
12; cached task port копируется по значению, не приобретается и не освобождается.
Startup и child-side reinitialization учтены в SAFETY.

Новых raw-pointer входов в public API, ручных Send/Sync, небезопасных lifetime
преобразований или FFI-буферов с недоказанным размером не появилось. Native
сценарий завершения leader по-прежнему использует собственный процесс и
проверяемый результат worker. Неизвестный SYS_EXIT теперь приводит к skip,
не к выбору произвольного syscall. Это исправление переносимости, не
утверждение, что неизвестная архитектура была проверена на настоящем ядре.

### Тесты и публикационная инфраструктура

Exact-value tests используют production conversion и отдельные исходные числа;
они отличаются от сравнения двух живых RSS/VmSize. Добавленные optional fixtures
проверяют ошибку единицы и parse overflow отдельно для VmSize и VmHWM.
Path-injected acquisition tests полезно проверяют успех primary, fallback,
не-NotFound ошибку и ошибку fallback; их Unicode-предпосылку нужно убрать.
Non-UTF-8 process-name test действительно вызывает публичный backend, а не
только проверяет свой fixture.

Собственная CI-матрица Linux/Windows/macOS, downstream link-and-call и
package dry-run остаются на месте. Их наличие не заменяет результат выполнения;
native CI, member MSRV/Miri и другие архитектуры здесь не запускались и не
объявляются зелёными. Старые ограничения известных skip-путей остаются
границами покрытия, не новым доказательством поведения этих путей.

## Возможности ускорения, снижения O и копирований

- **Runtime:** три поиска по status — O(L), не O(L²); временный Vec — O(L).
  Tri-state и conversion не добавляют heap allocation: существующий Vec
  передаётся по владению, а разбор использует срез. MemStat — фиксированный
  Copy value без глубоких копирований. Windows/macOS заполняют стековые структуры.
- **Главный кандидат при частом опросе Linux:** повторно используемый scratch
  либо streaming reader. Это может убрать свежие alloc/realloc, а потоковый
  разбор — сократить временную память до O(1), сохранив O(L) чтения. Нельзя
  обрезать данные первым фиксированным куском: длинная Groups может предшествовать
  memory fields; нужны корректные границы chunks/строк и частичные чтения.
- **Не обещать старые проценты текущему коду.** Отказ от fused reader принимаю
  как прежнее решение, а записанные числа — как свидетельство состояния
  `3119719`. Они не измеряют сегодняшнюю строгую grammar/tri-state реализацию
  или zero-allocation вариант. Новых benchmarks этот обзор не делал.
- **Маленькая необязательная экономия в tests:** проверка non-UTF-8 status
  через `String::from_utf8(status_bytes.clone())` может использовать
  `str::from_utf8(&status_bytes)`, без копирования buffer. Здесь bytes получены
  во время исполнения, поэтому прежний аргумент о const-fixture lint не мешает.
  Это cold test code, не ускорение библиотеки и не отдельный release blocker.

Для редких snapshot текущая простая реализация разумна. Не вижу основания
добавлять тяжёлые зависимости, агрессивный кэш открытых procfs fd или усложнять
публичное владение ради непроверенной микроэкономии.
