## 3. Новые находки

### P3

**F1 — residual review-4 F1: два старых комментария крейта всё ещё утверждают семантику const-eval, ПРОТИВОПОЛОЖНУЮ эмпирически подтверждённой task #1431; противоречие, которое review-4 вскрыл, осталось в дереве — задета была не та сторона.**
Где: `crates/size-classes/src/lib.rs:323-327` (комментарий #701: «in `const` context this was ALREADY a hard compile error either way (const-eval traps on overflow regardless of profile), so this fix's real effect is entirely on the previously-unguarded runtime call sites») и `crates/size-classes/tests/builder.rs:397-401` (заголовок P2-1-тестов: «These are runtime (not `const`) calls specifically because `const` evaluation already traps on overflow regardless of profile -- the bug these tests pin only existed at runtime, in `release`, before the fix»).
Эпистемический статус — явно: этот аудит read-only и НЕ выполняет никаких проверок компилятором; направление истины здесь взято ЦЕЛИКОМ из собственного эмпирического результата кампании (task #1431: временный откат checked_mul-фикса собрался и прошёл тест под `--release` без ошибки, доказав, что const-eval overflow-checking для тел `const fn` следует профилю `overflow-checks`), а не из знаний о rustc. Текстовое же противоречие доказуемо чтением: `builder.rs:507-509` (эмпирически подтверждённая сторона) говорит «const-eval overflow checks follow the profile for const-fn bodies», два места выше — «regardless of profile». Grep по крейту и шиму даёт ровно эти три вхождения; обе версии одновременно истинными быть не могут, и какая из них ложна — кампания уже установила экспериментом.
Следствия для текста обоих старых комментариев (при принятии эмпирического результата): (a) «traps on overflow regardless of profile» — опровергнуто; (b) `builder.rs:400-401` «the bug these tests pin only existed at runtime, in `release`» — неполно: до фикса тот же silent wrap существовал и в const-контексте release-профиля (const `L`, вычисленный в release-сборке, тихо свернулся бы в 0); (c) `lib.rs:326-327` «this fix's real effect is entirely on the previously-unguarded runtime call sites» — занижает собственный фикс: #701 защищает и const-потребителей release-профиля (до фикса wrap там маскировался min-step-fallback'ом точно так же, как в runtime). Обе ошибки — «в безопасную сторону» (занижение ценности фиксов, не завышение гарантий), но это ровно тот комментарий-класс, который уже произвёл одно ложное ревью-заключение: review-4 F1 явно цитировал эти два места как «написанные раньше и корректные» и на их основании построил своё (опровергнутое) P3.
Фикс: два точечных doc-изменения — привести `lib.rs:324-326` и `builder.rs:399-401` в согласие с эмпирически подтверждённой формулировкой `builder.rs:507-509` (или, как минимально-инвазивная альтернатива, оставить текст, добавив в оба места однострочную сноску на task #1431 как на разрешение противоречия). Исполнителю доступна та же 2-минутная эмпирическая перепроверка, которую уже делал orchestrator. Не блокирует публикацию, но `lib.rs` и `tests/` уходят в crates.io-tarball — закрыть лучше до/вместе с релизом.

### P4

**F2 — неточность внутри свежего F3(c)-фикса: `SegmentLayout::class_for` назван примером клампящего каллера, хотя он не клампит.**
Где: `src/alloc_core/size_classes.rs:216-218` (текст, добавленный `5b1d4d5`): «`size` here is already clamped to `>= MIN_BLOCK` by every caller (see e.g. `AllocCore::alloc`/realloc, the registry heap-core entry points, and the `SegmentLayout::class_for` re-export)».
Первые два примера верны (клампы `.max(MIN_BLOCK)` проверены на всех перечисленных путях, §2). Третий — нет: `SegmentLayout::class_for` (`segment_layout.rs:86-88`) форвардит `size` в шим БЕЗ клампа; кламп там — документированный контракт ЕГО каллера («the caller's contract; the public allocator entry points clamp it», `:76-77`), т.е. через реэкспорт-путь `size < MIN_BLOCK` физически достижим (тестом), и утверждение «already clamped by every caller» для этой ветви ложно. Вреда нет: `class_for` крейта тотальна для `size >= 1` (и даже для `size == 0` при `align >= 1`), так что это чистая doc-неточность — но она внесена именно фиксом гигиены формулировок, класс «regression-in-fix». Фикс — одно предложение: либо убрать реэкспорт из списка примеров, либо переформулировать («clamped by every allocator entry point; the `SegmentLayout::class_for` re-export instead passes the clamp obligation to its own caller as a documented contract»).
