## Context: why consolidation, and why now

The crate went through ~13 review rounds in four days. Each round's remediation edited rustdoc, README, CHANGELOG, and test docs in parallel, so the same narrative (shared-storage hazards, panic causes, MSRV, backoff tradeoffs) accreted on every surface, each copy stamped with its originating round. Duplication regrew twice even after consolidation attempts:

- Round 13's single-sourcing of the shared-storage hazard statement into the `StackStorage` trait doc: commit `92d0182` ("one canonical shared-storage hazard statement in StackStorage's trait doc").
- Round 15 / Wave-1's README-to-canonical-rule-3 sync: commit `ee47233` ("sync README to canonical rule 3, two-shape guard, bounded loom scope").

Both syncs went stale again. **OBSERVED drift in the current tree** (all verified 2026-09-01):

- `crates/tagged-index-stack/README.md:60` still says "link cells must not be shared between stacks meant to be independent" — the pre-round-15 wording of rule 3. The canonical restatement (`src/imp.rs`, `StackStorage` rule 3, ~lines 673-686) is a REACHABILITY invariant in which cell sharing per se is harmless for disjoint index populations.
- `crates/tagged-index-stack/README.md:64` says anyone who can read a live `ArrayIndexStack` "can take its `.head()`" — false since the Group-A sealing commit `a205d75`, which removed `ArrayIndexStack` from the public `StackStorage` trait.
- `crates/tagged-index-stack/README.md:68` cites the runtime test `array_index_stack_head_still_double_issue` — the test deleted/converted by the same Group-A change (`a205d75`); per the Wave-2 ADR it is now a compile-fail oracle, not a compiling demonstration.
- `crates/tagged-index-stack/README.md:325-328` and `crates/tagged-index-stack/CHANGELOG.md:374-377` state MSRV 1.81; `crates/tagged-index-stack/Cargo.toml:28` declares `rust-version = "1.79"` (Sol-codex run-4 P2-3, fixed by commit `0a37f33` in the manifest but not propagated to README/CHANGELOG).

Root cause: narrative placed on more than one surface with no single-owner rule. Consolidation is therefore not a one-time cleanup but a policy: exactly one canonical location per narrative, everything else a pointer, and this ADR as the safety net holding any fact the trims remove.

## Decision record — the doc-consolidation principles

**1. Rustdoc carries the exact current contract only.** Long-lived source text (`src/**/*.rs`, README, test module docs) contains: safety/preconditions, the ordering proof, panic conditions, short examples. Nothing else. **No internal review-round identifiers ("round-13 @oh review P2-1", "Sol-codex run-4") in any long-lived source text.** Dated CHANGELOG entries under `## 0.1.0 - Unreleased` are the sanctioned home for round references, as history.

**2. Canonical-location map (single source of truth per narrative; every other mention is a short pointer).** Reviewer checklist — grep each location, expect the full statement there and nowhere else:

- a. Shared-storage hazard inventory (4 binding-level shapes) + detection coverage → `crates/tagged-index-stack/src/imp.rs`, `StackStorage` trait doc, section "The shared-storage hazard class".
- b. `# Safety` clauses (the five implementor obligations) → same trait doc's `# Safety` section.
- c. Link ordering contract/proof → same trait doc's "Ordering contract" section; implementation-side ordering comments in `push_index_impl`/`pop_index_impl` cover the crate's own atomics and cross-reference it.
- d. No-double-push caller contract → `StackOps::push_index`'s "# Caller contract".
- e. Self-loop two-cause disjunction → `StackOps::pop_index`'s "# Panics".
- f. loom per-model breakdown → `tests/loom_aba.rs` module doc.
- g. Per-test status list (which test pins which shape/clause; guard fires vs. silent) → `tests/custom_storage_impl.rs` module doc.
- h. Decision history → this ADR, plus `docs/adr/2026-09-01-tagged-index-stack-storage-binding-closure.md` for the storage-binding decision.

**3. De-rounding policy for tests.** Review-round identifiers and finding IDs are removed from test module/function docs; the FACT each comment carried (what the test pins, why the guard exists) is restated without the identifier. Test function names are NOT renamed (they are load-bearing: cited in README, CHANGELOG, and the per-test status list). No assertion changes.

**4. CHANGELOG carve-out.** Dated `0.1.0-unreleased` entries may keep round references as history. Entries describing CURRENT behavior must be corrected when false. Three known corrections, all OBSERVED in the current tree: (i) `CHANGELOG.md:108-116`'s "still compile and still double-issue" — superseded by the unsafe-trait conversion (`0486e90`); (ii) the rule-3 "link cells must not be shared" wording — superseded by the reachability restatement (`2135d21`); (iii) the MSRV-1.81 sections (`CHANGELOG.md:374`, `README.md:325-328`) — superseded by the declared 1.79 (`Cargo.toml:28`, `0a37f33`).

## Relocated / obsolete fact ledger (the safety net)

Every fact below is being REMOVED from long-lived source text by the companion trims; this section is where each survives.

- **`# Stability` reversal narrative** (forbid→deny history; the E0053/`forbid` compile errors under the old policy; the owner's reversal): survives in the Wave-2 ADR §"The real cost of the `unsafe trait` option" and §"Final decision", plus `src/lib.rs`'s "Where unsafe lives" section (which keeps the current-state why). The **rejected `unsafe fn head()` alternative's full three-point design rationale** — restated here in full because rustdoc keeps only a one-line version (substance copied from the current trait doc, `crates/tagged-index-stack/src/imp.rs` ~944-957): (1) every known hazard is IMPLEMENTOR-side, never caller-side, so `unsafe fn` forces acknowledgment at the wrong site — implementors would signature-match `unsafe fn head()` with no contract acknowledgment at the `impl` site, the actual thing that needs forcing; (2) it falsely implies that *calling* `head()` is the dangerous act, when the danger is building on the returned reference; (3) it would reopen `unsafe` blocks inside the `StackOps` plumbing for no gain. Whole-trait `unsafe` with safe methods leaves exactly ONE `unsafe` token in the crate and ZERO `unsafe` blocks, and every `push_index`/`pop_index` caller (including sefer-alloc's registry) is untouched. (The compile errors `unsafe fn head()` once produced under `forbid` no longer apply but are recorded in the Wave-2 ADR.)
- **Rule-1 completeness audit method** — the literal grep recipes, with their "as of this writing" counts (source: `src/imp.rs` ~646-671; counts re-verified 2026-09-01 against the current file). Dated audit snapshot **2026-09-01**: `grep -n "^impl" crates/tagged-index-stack/src/imp.rs` → **10 impl blocks**, none adding a PUBLIC `&StackHead` accessor beyond `head` itself; `grep -n "derive(" crates/tagged-index-stack/src/imp.rs | grep -v "///"` → **3 hits** (lines 288, 1496, 1643), **all `Debug`**; `grep -nE -- "-> &.*StackHead" crates/tagged-index-stack/src/imp.rs | grep -v "///"` → **4 hits** (lines 980, 1185, 1195, 1614): `head`'s declaration plus three in the `pub(crate)` `SealedStorage` plumbing (sealed trait accessor, blanket bridge impl, `ArrayIndexStack`'s direct impl) — all three crate-internal only. Two routes to `&StackHead` from safe code exist (own a `StackHead` value; call `head()`), route 2 is closed under delegation (hence a value-level, not type-level, obligation), and no third route exists as of this writing. Known falsification limits of the recipes themselves: the `.*` pattern misses a rustfmt-wrapped return type; the fallback is reading the impl list.
- **README's 128-bit-CAS rejection rationale** (`crates/tagged-index-stack/README.md:201-213`, "Why the default is not a wider packed word") — restated here; README keeps a short pointer: a 128-bit CAS (e.g. `portable-atomic`, nightly intrinsic) was considered and explicitly rejected for the default packed word because (1) `loom` has no `AtomicU128`, so it would drop loom's coverage of the real type; (2) it adds an unsafe third-party dependency to a crate whose own code holds exactly one audited `unsafe` token; (3) `cmpxchg16b` is not in the x86-64 baseline, so `pop`'s read-only head observation would likely become an RMW on some targets. A genuine future need for >65535 indices in one pool should be a separate, explicitly opt-in feature-gated type — not a change to this default.

## Consequences

- **Exactly-one-full-exposition verification.** A reviewer greps the signature phrases — "shared-storage hazard class" (expect the full 4-shape inventory only in the `StackStorage` trait doc), the five-clause `# Safety` list, the two-cause self-loop disjunction, the no-double-push caller contract — and must find each full statement in exactly ONE place, with short pointers elsewhere. More than one full statement, or zero, is a violation of this ADR.
- **Drift regrowth is the known failure mode** — it happened after `92d0182` and again after `ee47233`. Any future edit that adds narrative to a second surface (duplicating a hazard explanation into README or a test doc, restating the Safety clauses, re-stamping round IDs into rustdoc) violates this ADR even if the added text is individually accurate. The fix is always: extend the canonical location, leave a pointer.
- This ADR is append-only for relocated facts: if a companion trim removes a fact not yet in the ledger above, the ledger must be extended in the same change, not the fact deleted.
